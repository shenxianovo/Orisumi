分析前一天的数据，先查各来源的观测依据，再关联事实：

```sh
orisumi capture coverage --from 2026-11-13T00:00:00+08:00 --to 2026-11-14T00:00:00+08:00
```

命令只读各来源的 `capture_coverage` 视图，返回与半开区间 `[from,to)` 相交的记录；缺库返回 `no_database`。记录保留原区间，不裁剪到查询边界。

| 字段 | 含义 |
| --- | --- |
| `scope` | 事实或通道范围 |
| `mode` | `replay` 日志/历史补读，`notification` 通知，`snapshot` 当前值采样 |
| `started_at_utc_ms` / `stopped_at_utc_ms` | 此项依据的时间范围；同值为一个时点，空结束表示未确认 |
| `evidence` / `detail` | 读取结果、可用性、运行状态或缺口及上下文 |
| 来源附加列 | 运行 ID、浏览器配置等，用于库内关联 |

运行记录显示进程或浏览器连接的起止，`confirmed_until_utc_ms` 表示最近成功提交一轮的时间。结束尚未确认时，`evidence` 为 `unconfirmed`。读取失败以 `read_failed` 时点记录；日志文件的移动、缺失和重新读取等变化另列。补读在何时完成与日志覆盖的来源时间是两回事。Codex 的 rollout 事务独立提交；`state_5.sqlite` 读取失败记在 `current_state` 范围。

浏览器连接读到 stdin EOF 时确认结束。连接仍在且约两分钟未收到标签快照时，记录一次 `snapshot_timeout`，到新快照或 EOF 结束缺口。快照与库中已知状态不一致时记录 `reconciliation_changed`，用快照建立新初值。书签的最后使用时间来自采样，变化时照常记录。格式无效的投递连同原始 JSON 和错误写入 `browser_rejected_deliveries` 后确认移出待发队列，覆盖视图以 `delivery_rejected` 标记缺口。暂时的读写失败保留投递并退避重试。历史的 `range_read` 区间取自已提交的游标，范围含义见[采集数据](./sources.mdx#浏览器)。

这些记录不能合并成一个“全程完整”的布尔值。通知后读取现值只能证明该次观测，无新事实本身不证明状态未变；未确认结束不能用重启或查询结束时间补齐。

## 恢复边界

| 来源 | 可恢复内容 | 无法补齐的内容 |
| --- | --- | --- |
| Claude 日志 | 从已提交完整行继续；保留的主会话与子 Agent 日志可回填，重放按记录身份去重 | 来源已删除的记录；追加同时改写未检查的已读中段 |
| Codex rollout | 从已提交完整行继续；保留的活跃和归档 rollout 可回填，移动或转为压缩归档后重放去重 | 下次完整核对前被来源覆盖或删除的记录 |
| Codex 会话现值 | 重读名称、归档和置顶 | 两次读取之间的中间变化 |
| 浏览器 | 重放未确认的投递，从已提交位置补读保留的访问记录；标签、书签、下载重建初值 | 入队前丢失的事件、浏览器已清理的历史和离线中间状态 |
| macOS | 恢复通道后重新订阅、建立初值 | 中断期间的切换、输入及未观察到的释放；两次读取之间的激活策略、音频和摄像头往返 |

日志增量读取用文件身份、长度和修改时间识别变化。Claude 校验首尾检查点。Codex 收到纯文本 rollout 的追加通知时也只校验首尾检查点，再从游标增量读取。每 60 秒核对时会校验已提交字节的完整前缀，长度不变但修改时间变了也会完整校验。中段改写后再追加时，改写部分最迟在下一次成功的完整核对中发现并重放，前提是来源仍保留改写内容。Codex 事件重放按 rollout、行哈希及该行在当前版本中的出现次数去重，用量按会话、响应 ID 去重。活跃日志只提交以换行结束的记录。归档按版本完整解码，最后一条记录可以在文件末尾结束。

输出库重建前停止对应采集器，重建后重启；浏览器代码更新另需重载扩展。来源保留的历史重新回填，事件来源重新建立初值。具体事实与调度见[采集数据](./sources.mdx)。
