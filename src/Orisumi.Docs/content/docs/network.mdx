## 运行

需要 macOS 自带 `nettop`，使用普通用户权限；数据写入 `STORE/raw/network.sqlite`，每个存储目录允许一个网络采集进程。

```sh
orisumi network capture
orisumi network capture 60 --interval 1
```

默认每 5 秒执行一次 `nettop -L 1 -n -x` 快照，覆盖工具返回的 TCP、UDP、IPv4、IPv6 和接口；不是逐连接事件流。省略秒数则持续运行，Ctrl+C 或 SIGTERM 正常结束。

`orisumi capture start` 安装并启动 `dev.orisumi.capture.network` LaunchAgent，保活当前构建产物。日志在存储目录 `logs/network.{out,err}.log`。停止后台任务：

```sh
launchctl bootout gui/$(id -u)/dev.orisumi.capture.network
```

采集和查询均校验结构版本；不匹配时按[采集开发](./capture.mdx#数据库结构)重建输出库。

## 查询

时间参数包含 UTC 偏移或 `Z`；增加 `--details` 获取原始计数、记录 ID、出现/消失、状态变化和统计区间。

```sh
orisumi network query \
  --from 2026-11-13T00:00:00+08:00 \
  --to 2026-11-14T00:00:00+08:00 --details
```

JSON 按进程实例、协议、远端地址/端口、接口汇总，并返回采集区间与中断信息：

- `received_bytes`、`sent_bytes` 只累加完整落在查询范围内的有效增量，无有效增量为 `null`。
- `boundary_intervals` 统计跨边界区间，明细保留整个区间，不按比例分摊；`unknown_intervals` 统计首次基线、未知或不可连续比较的计数。
- `runs` 的样本数和首末时间描述整个运行，实际覆盖看 `samples`。`sample_id` 是本次成功采样，两个方向的 `*_observation_sample_id` 指向最近计数变化，静止时可以不同。
- `process_identity_verified=0` 的进程未通过启动时间核实，增量保持未知。`observed_socket_segments` 是观测段数，不是新建连接数。

通过时间、进程生命期、`sample_id`、`socket_id` 查询明细，再与其他来源关联；不同库的本地 ID 不通用。

## 事实与身份

| 表 | 一行的含义 |
| --- | --- |
| `capture_runs` | 采样进程区间，含来源、系统启动标识、间隔、起止和停止原因 |
| `samples` | 一次完整采样或失败，含读取起止 UTC 毫秒、单调经过时间、序号、连续性和错误 |
| `process_instances` | 运行内经 PID＋启动时间验证的身份，或一段未验证的连续观测 |
| `process_presence_events` | 初始可见、连续快照中消失或中断后重现；不是系统启动/退出事件 |
| `process_name_observations` / `process_path_observations` | 名称／路径的初值和变化；名称可能截短，未知路径为空 |
| `process_traffic_observations` | 某进程、某方向累计字节数的初值与变化 |
| `socket_instances` / `socket_presence_events` | 连续匹配的连接观测段，含协议、端点、接口、歧义标记／初次可见和连续下一快照中消失 |
| `socket_state_observations` / `socket_traffic_observations` | 来源连接状态／每方向累计计数的初值与变化，未知为空 |

出现/消失、名称、路径、连接状态、接收和发送独立写入；已知与未知之间的变化也保存。`socket_history` 组合出现/消失与当时进程信息；`process_traffic_intervals`、`socket_traffic_intervals` 先还原每次成功采样的值，再计算相邻采样增量。

例如计数在 10:00:00、10:00:05 都为 100，10:00:10 为 150，只存 100 和 150。每次采样仍有一行，证明第二次观察成功，因此 50 字节属于 10:00:05–10:00:10，前一区间为 0。静止对象不重复写状态。

进程启动时间由 `sysctl(KERN_PROC_PID)` 读取，精度 UTC 微秒；路径单独读取，前后核对出生时间，拒绝采样开始后才出生的 PID。启动时间未知时，仅在连续、PID/名称/路径一致、进程计数未回退时复用未验证观测段；消失、中断、属性变化或计数回退即建新段。该段不计算增量，之后读到启动时间也不追溯认证。跨来源核对设备、系统启动区间、PID、启动时间和活动时间。

nettop 无稳定 socket ID；连续采样中进程身份、协议、端点、接口一致且计数未回退时连接为同一观测段。同属性的多个 socket 标为 `ambiguous`，不跨采样算增量；整组原始行相同（允许重排）则复用，任一行改变则整组重建，避免猜测对应关系。

## 还原边界

- 首次累计值是基线，不计入采集前流量。间隔内完成的短连接、末次采样至消失间的流量可能漏掉；同端点连接被替换且计数未回退时也可能无法区分。
- 出现、消失是观测时间。TCP `Listen` 是监听端口，UDP `*` 表示地址未提供，不能直接解释为对外请求。
- 采样失败、间隔超过配置两倍、时钟倒退或进程重启打断连续性，恢复后重建基线；结束时间空表示正常停止未确认。成功快照与进程元数据在同一事务提交。
- 进程计数可能随 socket 集合改变；回退保留原值并令增量未知。进程汇总与 socket 明细不能相加。
- 回环、VPN、代理可能重复体现同一通信，不同接口/进程之和不等于互联网总流量。
- `-n` 保留数值地址；无 HTTP 方法、路径、HTTPS 明文或访问时域名。时间相近只是关联线索，因果需要直接证据。

验证命令见[命令行与开发](./development.mdx#验证)。网络检查覆盖解析与 IPv6、独立变化、静止、未知值恢复、PID 复用与未验证身份、系统进程出生时间、计数重置、重复 socket、中断和边界查询；集成检查使用本机 TCP/UDP 与临时库，验证入口、停止和并发采集保护。
