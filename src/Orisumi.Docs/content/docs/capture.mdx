## 来源与连续性

按具体事实选择采集方式，同一来源可以组合使用：

| 来源能力 | 采集方式 | 中断恢复 |
| --- | --- | --- |
| 可回放日志 | 首次回填，随后按来源位置增量读取 | 从已提交位置补读；来源已丢失的部分标为缺口 |
| 变更通知 | 初始快照与监听衔接，保存每次变更 | 重放待发事件；无法补读的区间标为缺口，重新建立初值 |
| 只能读取当前值 | 按需采样、比较并保存差异 | 保留采样边界，恢复后建立基线 |

建立初值时先接收或缓存通知，再取得与通知顺序一致的快照；来源无法原子衔接时，通过序号、重试或核对处理。通知只提示“有变化”时，读取结果仍是一次观测，不能承诺保留所有中间状态。

定期核对用于纠正当前状态、发现来源遗漏，读取不要求重复入库。批量写入、重试和时间到期也可使用定时器；它们与采样频率分别设置。校准快照无法补出中断期间的 A→B→A。

## 提交与恢复

- 同次观测的关联事实在一个事务中提交；本地读取游标与事实一起提交。
- 跨进程投递使用稳定事件 ID，提交后确认，确认后移除持久队列；丢失确认可安全重试。
- 日志游标关联文件身份和读取位置，处理截断、替换、移动与末尾残行。文件通知只触发读取，来源内容决定事实。
- 记录采集起止、可用性和已知缺口；异常退出的结束时间保持未确认，恢复时重新核对。无新事实不能单独证明状态未变。
- 输出库重建后，读取进度与投递端基线也要失效；有历史的来源重新回填，其余建立新初值。

## 事实与查询

例如下载状态变化只写状态，路径变化只写路径；查询视图组合两者。一次事件可产生多类事实，以观测标识关联。

事实表保存身份、事件和状态变化；`*_history` 组合历史，`current_*` 返回最后已知状态。当前值不证明来源仍可用；采样差异不证明变化恰好发生在读取时刻。需要查询缓存时，应能从事实重建。

`observed_at_utc_ms` 表示收到通知或读取来源的时间，来源时间按含义命名；本库观测序号只保证本库顺序。跨来源关联核对设备、对象生命期和时间，不能直接连接不同库的本地 ID。

`_collector_state`、`_token_usage_rollouts`、读取游标及待发送队列属于可更新的采集进度，不作为历史事实。

## 数据库结构

每个来源写入 `STORE/raw/来源.sqlite`。持久化定义放在采集器项目的 `Schema/`：

| 路径 | 内容 |
| --- | --- |
| `Tables/` | 每表一个 SQL 文件，含字段、键和约束 |
| `Indexes/` | 普通索引按所属表归文件 |
| `Views/` | 每视图一个 SQL 文件 |
| `Version.txt` | 该来源的正整数结构版本 |

构建自动收集文件，按表、索引、视图顺序执行，各组按文件名排序；无需登记清单。文件只定义结构，临时导入视图留在采集代码中。

C# 使用共享的 `Collectors/Storage/SqliteSchema.cs` 加载程序集内 SQL；Swift 使用 `Native/DatabaseSchema.swift` 加载可执行文件旁的 `Orisumi.Collectors.MacOS/Schema/`，构建和发布负责复制。

初始化事务只接受无用户对象的空库或匹配版本：空库建结构并设置 `PRAGMA user_version`，版本不符报错，失败回滚。外键与锁等待在打开连接时设置，WAL 在事务外设置。结构变化递增版本；版本不匹配时停止对应采集器、重建其输出库，不迁移。macOS 始终创建完整结构，选项只控制通道采集与写入。

## 开发与验证

1. 明确每类事实的身份、来源能力、时间含义和可还原范围。
2. 完成初值衔接、提交确认和中断恢复，再接入启动与查询。
3. 按实际风险验证：A→B→A、静止不重复写、重复投递、提交前后崩溃、恢复缺口；日志来源另测残行、替换与截断，采样来源另测重置和身份变化。
