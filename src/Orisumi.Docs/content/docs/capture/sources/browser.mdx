## 浏览器

来源身份含 `browser`、`profile_id`。`profile_id` 是本次扩展安装生成的随机 ID，重连沿用，卸载后重新安装会生成新 ID。是否属于同一个 Chrome 配置由派生层判断。观测 ID 表示入库顺序，`run_sequence` 取扩展投递序号。本库键只用于库内关联。

| 事实或视图 | 含义 |
| --- | --- |
| `visits` | Chrome 保留的访问记录，含来源访问时间、跳转类型、引荐访问和本地标记；属性只能补空，引荐访问为 `''` 表示没有 |
| `history_page_title_observations` / `history_pages` | 按配置与 URL 保存非空标题初值和变化／最新标题；是读取时看到的标题，不代表历史访问当时的标题 |
| `tabs` / `browser_windows` | Chrome 会话内的标签、窗口身份，接收端重连和 worker 唤醒时沿用 |
| `tab_observations` | 一次快照或通知；同次观测的事实共享 `observation_id` |
| `tab_presence_events` / `window_presence_events` | 标签／窗口的存在初值、出现和关闭 |
| `tab_window_observations` | 标签所属窗口的初值和变化；拖出窗口、尚未放下时 `has_window=0`。不记标签条位置 |
| `tab_url_observations` / `tab_title_observations` | URL／标题独立变化；空为 `''`，读不到为空 |
| `active_tab_focus_events` | 前台标签的初值和切换；`has_tab=0` 表示没有可采集的前台标签 |
| `tab_history` / `current_tabs` | 每次变化后每个标签的完整状态，含是否前台和有效区间／每个配置最近一次 Chrome 会话里最后已知打开的标签 |
| `downloads` / `download_observations` | 下载身份、URL 和来源开始时间（不变，只能补空）／观测、采集会话、时间与来源 ID 的关联 |
| `download_response_observations` | 最终 URL、总大小、MIME 的初值与变化；不含进度字节数，未知大小为空 |
| `download_state_observations` / `download_path_observations` | 状态及来源完成时间／本地路径，独立变化 |
| `download_history` / `current_downloads` | 每次观测后的状态／最后已知状态 |

扩展在入队前排除隐身窗口、标签和下载。聚焦到隐身窗口时结束普通标签焦点。标签和窗口每分钟发完整快照，下载列表和书签树每五分钟发一次。连接建立后也读取全部快照。扩展按收到的顺序持久化通知，接收端在 SQLite 中比较已知值，提交后确认，扩展再删除已确认的投递。

标签 URL 和标题由 Chrome 通知独立提供。替换标签时读一次新标签属性。下载通知省略的字段沿用上次值，列表移除时保留最后已知事实。快照读取期间收到相关通知会重读；两次快照之间只靠通知保留中间变化。

历史按 Chrome 保留的 URL 最近访问时间查询范围，对每个 URL 读取所有保留的 visits 和当时可读的页面标题。历史事实和读取位置在同一事务提交。

| 书签表或视图 | 含义 |
| --- | --- |
| `bookmarks` | 配置内节点身份、节点种类、来源创建时间；未知身份属性可后续补全 |
| `bookmark_observations` | 观测时间、事件种类及会话顺序，同次事实共享 `observation_id` |
| `bookmark_presence_events` / `bookmark_title_events` / `bookmark_url_events` | 存在性／名称／目标 URL；文件夹没有 URL 事实 |
| `bookmark_location_events` | 父文件夹的初值与变化；根节点没有父文件夹 |
| `bookmark_last_used_observations` | 来源最后使用时间；未知不覆盖已知，不能列出每次使用 |
| `bookmark_state` / `current_bookmarks` / `bookmark_history` | 含删除节点的最新状态／当前存在节点／每次观测后的状态 |

删除节点只追加消失，保留旧属性；删除文件夹时，已知子孙节点一并追加消失。

## Codex

只读 `CODEX_HOME`（默认 `~/.codex`）下 `sessions/` 和 `archived_sessions/` 的 rollout，含 `.zst`。同时从 `state_5.sqlite` 读取会话名称、归档和置顶的现值。监听变更并每 60 秒核对，失败后重试。

| 事实或视图 | 含义 |
| --- | --- |
| `threads` / `current_threads` | 日志中的会话身份、创建时间、工作目录、Git、来源、发起方和已知父会话／合并最新名称、归档和置顶。名称为空字符串表示未命名，为 NULL 表示未知 |
| `thread_name_observations` / `thread_archive_observations` / `thread_pin_observations` | 三个现值独立记录初值和变化，同一轮的变化共享 `database_observation_id` |
| `turns` / `current_turns` | 会话内回合身份／来源开始、结束和最后的生命周期状态。未读到生命周期时状态未知 |
| `rollouts` / `source_file_events` | rollout 文件名身份及首次读取、移动、版本变化和缺失等观测。事件及用量通过 `source_file_event_id` 查首次入库的路径和文件身份 |
| `rollout_events` / `event_contents` | 回合生命周期、回合上下文和条目事件，含来源行号。正文保留消息内容、模型与审批和沙箱策略、命令摘要、文件路径和改动类型、MCP 调用、搜索查询与状态、休眠毫秒数和图像生成的提示词与状态。图像生成结果省略。命令输出长度以 UTF-16 计，仅非零退出码保留整段输出。推理和未知条目只记事件 |
| `message_timeline` | 用户和助手消息的正文及来源顺序 |
| `response_token_usage_events` / `response_token_usage` | 每响应一行，含输入、缓存读写、输出、推理与总用量。视图从同一回合的上下文取模型 |

同一会话可以有多个 rollout，各自保存读取位置。子 Agent 的父会话取自日志，分叉取自日志或与会话 ID 相符的文件名。搜索调用和条目完成可以是同一条目的两条来源事件，按会话、回合和条目 ID 关联。增量和重放边界见[覆盖与恢复](./recovery.mdx#恢复边界)。

## Claude

只读 `CLAUDE_CONFIG_DIR`（默认 `~/.claude`）下的主会话与子 Agent JSONL。监听变更并每五分钟核对文件，增量和重放边界见[覆盖与恢复](./recovery.mdx#恢复边界)。

| 事实或视图 | 含义 |
| --- | --- |
| `sessions` / `current_sessions` | 会话及已知父会话／最新自定义、AI 标题与可见消息的最早、最晚时间 |
| `source_records` | 导入记录的文件身份、路径、行号、哈希和运行 ID |
| `transcript_events` | 带 UUID 的事件及其父节点，保留分支、sidechain 与 Agent ID。链首的父 UUID 为 `''`，字段缺失为 NULL。人输入的提示行记录来源与权限模式，斜杠命令的提示来源为空 |
| `event_contents` | 可见文本、图像、文档，工具名称与完整输入，及工具结果的错误标记、权限决定和来源、内容长度。长度以 UTF-16 计，结构化结果取原始 JSON 长度。仅错误结果保留完整错误文本，thinking、attachment 和其他未选正文的事件无内容行 |
| `message_timeline` | 可见用户与助手消息，按 `session_id, chain_order` 排列，`visible_parent_uuid` 指向链上最近的可见祖先。分支和 sidechain 均保留 |
| `session_title_observations` | `custom`、`ai` 标题分别保留初值和变化，沿来源行顺序写入 |
| `response_token_usage_observations` / `response_token_usage` | 同一响应分行记录的用量初值与变化／每个响应的最后用量，汇总使用后者 |

跳过文件历史、API 请求、队列操作、Agent 名称和单独的权限模式记录。

## macOS

Swift 以 JSONL 发送观测，C# 把完整的一轮写入同一事务。事件以 `run_id`、`run_sequence`、`observed_at_utc_ms` 关联运行、观测顺序与 Swift 当时读到值或通知的时间。按键顺序在按下时确定，事实在观察到释放或结束监听时入库。

应用通道从 `NSWorkspace` 观察应用。进程实例第一次被观察到是 `regular` 或进入前台时开始记录，之后持续跟踪其策略和存在性。

| 事实或视图 | 含义 |
| --- | --- |
| `process_instances` / `running_app_observations` | 观察到的进程生命期、PID、bundle ID、名称、来源启动时间／首次纳入、恢复初值和消失 |
| `foreground_app_events` / `foreground_app_history` / `running_app_history` | 前台初值和切换，`has_app=0` 表示无前台应用／组合进程身份的历史视图 |
| `window_focus_instances` / `focused_window_events` | 连续焦点段及所属进程／焦点初值和切换；`has_window=0` 表示无聚焦窗口，读取失败记 `read_failed` 且 `has_window` 为空；焦点 ID 不是稳定窗口 ID |
| `window_title_observations` / `window_history` | 焦点段内标题初值和变化／焦点与当时标题；无标题为 `''`，读取失败为空；初始标题与焦点共享序号 |
| `capture_permission_events` / `capture_channel_events` / `capture_method_events` | 授权变化／通道可用性及原因／监听或采样方式的初值与变化 |
| `time_zone_events` / `afk_events` | 时区／active、idle 的初值和变化；`idle_ms` 是当次检查的无输入时长 |
| `clock_events` | 墙钟与 `mach_continuous_time`（含休眠，纳秒）一起读的初值，以及 `NSSystemClockDidChange` 通知后的变化；两者之差变了说明时钟被调过，NTP 的渐进微调看不到 |
| `system_sleep_events` / `user_session_events` | 休眠、唤醒／用户会话激活、停用通知，不补造启动前事件 |
| `screen_lock_events` / `display_sleep_events` | 锁定／显示器休眠各自的初值和变化，NULL 表示当次读不到初值 |
| `keyboard_presses` / `mouse_button_events` | 一次按键（键码、起止、按下时修饰键）／鼠标按下或释放（按钮、坐标）；自动重复不另计按键，未观察到释放时结束为空 |
| `application_activation_policy_observations` / `regular_app_intervals` | 应用实例激活策略（`regular`、`accessory`、`prohibited`）的初值和变化，读不到为空／应用处于 `regular` 的区间，即有 Dock 图标的普通应用，到策略变化、消失或应用通道中断为止 |
| `audio_process_instances` / `audio_process_presence_events` | CoreAudio 进程对象身份（客户端 PID、bundle ID，可关联负责应用的 `process_instances`）／出现和消失 |
| `audio_input_observations` / `audio_output_observations` | 所有音频进程是否在用麦克风／有应用归属的音频进程是否在出声，各有初值和变化 |
| `camera_devices` / `camera_device_presence_events` / `camera_running_observations` | 摄像头身份（UID、名称）／连接和断开／是否在运行；系统不提供是哪个进程在用 |

`capture_run_configuration` 按运行保存 AFK 阈值与各可选通道开关。每轮提交更新 `confirmed_until_utc_ms`，取 Swift 的观测轮次时间。读取失败另记。助手异常退出、传输积压超限或写入失败时结束当前运行；C# 意外退出时，助手随控制管道关闭而退出，运行结束保留未确认。`timeline` 组合活动、屏幕状态、权限和通道记录。

窗口按 AX 通知能力选择监听或每秒回退查询；支持通知时每 60 秒校准。输入可用时，键盘、鼠标移动、按钮和滚轮更新 AFK 活动时间，到期计时器判断离席；移动和滚轮不另存事件。输入不可用时每秒读系统 idle。权限核对和输入批量写入分别调度。

激活策略先订阅 KVO 再读初值；实测 KVO 会漏掉变化，所以每秒再读一次现值核对。音频和摄像头先挂属性监听再读初值，通知只触发读取，每秒也核对一次，所以属于读当前值：时间是读取时间，一秒内的往返会丢。音频「在用」指流在运行，静音的流也算。确认客户端 PID 仍反查到同一个 CoreAudio 对象后，用系统的 responsible PID 找已记录的应用实例。查找不可用或失败时用客户端 PID，并核对已知的 bundle ID。归属可稍后补上，音频输出从确认归属时开始记录。这三个通道不需要授权。

锁屏和解锁取分布式通知，启动和恢复时通过 `CGSessionCopyCurrentDictionary()` 读取未公开键 `CGSSessionScreenIsLocked`。字典或键读不到时，初值为 NULL。显示器休眠和唤醒取 `NSWorkspace` 通知，初值检查在线显示器是否都在休眠。这两组状态独立记录，其他通道继续观测。[Apple 的显示器与会话查询](https://developer.apple.com/documentation/coregraphics/quartz-display-services) · [屏幕通知](https://developer.apple.com/documentation/AppKit/NSWorkspace/screensDidSleepNotification)

系统休眠和用户会话停用中断应用、窗口、输入、AFK、时区、时钟和媒体观测。恢复后重建各自初值，也重新读取锁屏和显示器状态。权限丢失只影响依赖该权限的通道；输入 tap 中断只影响输入和 AFK。启动时间未知的进程身份在中断后断开，后来读到启动时间也不追溯认证。
