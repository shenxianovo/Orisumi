---
title: 覆盖与恢复
description: 查询观测依据，区分日志补读、当前值与缺口。
---

分析一段时间的数据前，先查各来源的观测依据，再关联事实：

```sh
orisumi capture coverage --from 2026-11-13T00:00:00+08:00 --to 2026-11-14T00:00:00+08:00
```

命令读每个来源所有库的 `capture_coverage` 视图，返回与半开区间 `[from,to)` 相交的记录，保留原区间，不裁剪；没有库返回 `no_database`。

| 字段 | 含义 |
| --- | --- |
| `scope` | 事实或通道范围 |
| `mode` | `replay` 日志或历史补读，`notification` 通知，`snapshot` 读当前值 |
| `started_at_utc_ms` / `stopped_at_utc_ms` | 这条依据的时间范围；同值是一个时点，空结束表示未确认 |
| `evidence` / `detail` | 运行状态、读取结果、可用性或缺口，及上下文 |
| 来源附加列 | 运行 ID、`confirmed_until_utc_ms`、浏览器配置等 |

记录分几类：

- **运行**：进程或浏览器连接的起止。结束未确认时 `evidence` 为 `unconfirmed`，`confirmed_until_utc_ms` 说明至少确认到了哪。
- **读取失败**：`read_failed`，一个时点。这一轮的事实已回滚，下一轮重读。
- **文件变化**：日志被移动、替换、截断、改写或缺失时的时点，Claude、Codex 有。
- **缺口**：浏览器快照和库对不上（`reconciliation_changed`）、连接还在但约两分钟没收到快照（`snapshot_timeout`）、投递被拒（`delivery_rejected`）；macOS 通道不可用及原因。
- **补读范围**：浏览器历史已读到的时间段（`range_read`）。

这些记录合不成一个“全程完整”的布尔值。没有新事实只在链没断时说明状态没变；读现值只证明读的那一刻。补读完成的时间和日志覆盖的来源时间是两回事。

## 恢复边界

| 来源 | 能恢复 | 补不回来 |
| --- | --- | --- |
| Claude 日志 | 从已提交的完整行接着读；来源保留的日志可重新回填，重放按行去重 | 来源已删的日志（默认保留 30 天）；追加时中段被改写的部分 |
| Codex rollout | 同上，含归档和 `.zst` 换版 | 来源已删的 rollout；下次完整核对前被改写又删掉的部分 |
| Codex 会话现值 | 重读名称、归档、置顶 | 两次读取之间的变化 |
| 浏览器 | 重发未确认的投递；从已提交位置补读历史；标签、书签、下载重新记初值 | 入队前丢的事件、Chrome 已清掉的历史、断开期间的中间状态 |
| macOS | 通道恢复后重新订阅、记初值 | 中断期间的切换和输入；两次读取之间的激活策略、音频、摄像头往返 |

日志按追加读，用文件身份、长度和修改时间发现变化。追加时只校验首尾检查点；Codex 每 60 秒核对时校验整段已读内容，中段被改写会在这时发现并重读。末尾没换行的半行等下次再读；`.zst` 归档整份解码。

重建输出库前停掉对应采集器，重建后重启，浏览器另需重载扩展。能回放的历史重新补读，其余重新记初值。
