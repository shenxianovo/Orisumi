生产只运行装进它自己目录的发布版本；开发用检出里的构建和自己的存储，所以开发不影响生产。

## 实例

实例是带 `instance.json`（如 `{"name":"prod"}`）的存储目录，数据、运行状态和装好的程序都在里面，结构见[存储](../overview/storage.mdx#目录)。

| 实例 | 目录 | 名字 | 命令 |
| --- | --- | --- | --- |
| 生产 | `~/Library/Application Support/Orisumi` | `prod` | `orisumi` |
| 预览 | `~/Library/Application Support/Orisumi-preview` | `preview` | `orisumi-preview` |
| 开发 | `<检出>/.local/store` | `dev_<检出目录名>` | `orisumi-dev` |

- 名字只含 `[a-z0-9_]`。每个用户级的全局名字都由它派生，生产也一样：LaunchAgent `dev.orisumi.<名字>.<来源>`，Chrome 接收端 `com.orisumi.<名字>.browser`，命令链接 `~/.local/bin/orisumi`（生产）或 `~/.local/bin/orisumi-<名字>`。开发实例没有命令链接。
- 程序没给 `--store` 时，从自己所在目录往上找 `instance.json`；找不到而处在检出里，就用这个检出的开发实例，首次使用时创建；都不是就报错。不回落到生产目录，也不读环境变量：LaunchAgent 和 Chrome 拉起的进程不继承环境变量。
- 每个检出各有一个开发实例，多个 worktree 可以同时开发。开发实例只做短时运行和测试，常驻采集留给预览。

## 发布

`orisumi-dev release [组件…]` 只在工作树干净时运行。宿主（`host`）和每个采集器各自发布成 Native AOT 程序，放进 `~/Library/Application Support/Orisumi-releases/<组件>/<版本>/`。版本是程序版本加提交号（如 `0.1.0+5bcfe4ea…`），也就是运行记录里的 `collector_version`。

- 组件就是宿主和 `src/Collectors/` 下的每个项目，不用登记。
- 发布要求零警告，并用 `describe` 核对版本。已有的版本目录直接复用，发布后不再改动。浏览器的发布另含 `extension/`，macOS 的含 Swift 助手。
- 发布目录不含实例信息，同一份能装进预览，也能装进生产。以后对外分发，可以把它包成 NuGet 包或压缩包；安装只认目录。

## 安装与启停

`orisumi install <发布目录>…` 把发布复制进实例的 `app/host/` 或 `app/collectors/<来源>/`：先放进临时目录，再原子换入。实例相关的内容只在这一步写入：宿主的命令链接，浏览器扩展的 `config.json`（接收端名字）和扩展名后缀 `(<名字>)`。

`capture start` 按[启动方式](../capture/index.mdx#新增采集器)启动本实例的采集器，并注册本实例的 Chrome 接收端；已在运行的先停掉。`capture stop` 停掉它们并注销接收端，每次运行以 `completed` 结束。

- `resident`（Claude、Codex）：LaunchAgent 保活，启动时先全量核对，之后按来源通知和定期核对增量导入。
- `terminal`（macOS）：从调用的终端分离启动，继承它的窗口和输入权限，终端关闭后照常运行。PID 和进程启动时间记在 `state/<来源>.pid`，停止前据此确认还是同一个进程；日志在 `logs/<来源>.{out,err}.log`。重启电脑后要再跑一次 `capture start`。
- `chrome`（浏览器）：由 Chrome 拉起，`capture start` 只注册接收端。

Chrome 给未打包扩展的 ID，是加载路径 SHA-256 的前 32 位十六进制，`0-f` 依次映射为 `a-p`。接收端因此按扩展所在路径算出 ID 来注册，不用手填。在 Chrome 中加载扩展仍需手动，`capture start` 会打印路径和预期 ID。预览和生产的扩展可以装在同一个 Chrome 配置里并排运行。

## 预览与切换

```sh
orisumi-dev release
orisumi-dev preview start [组件…]
orisumi-dev preview status
orisumi-dev promote [组件…] [--migrate 迁移.cs]
```

- `preview start` 把当前提交的发布装进预览实例并启动。预览读同一批真实来源，写自己的库，和生产并排运行。`preview status` 列出两边装的版本、各来源最近一次运行和最近一小时的读取失败。
- `promote` 停掉生产，运行可选的迁移脚本（`dotnet run --file 迁移.cs -- <生产目录>`），把预览里装着的同一版本装进生产，启动生产，最后停掉预览。预览没装的组件用当前提交的发布。迁移规则见[数据库结构](../capture/index.mdx#数据库结构)。
- 回退：旧版本目录都还在。停掉生产，用 `orisumi install` 装回旧版本，再 `capture start`。改过库结构的版本退不回去。

`--releases`、`--prod`、`--preview` 可以改这三个目录，供测试使用。
