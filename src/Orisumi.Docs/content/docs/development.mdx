## 安装与源码入口

只支持 macOS。需要 .NET 11 SDK 和 Xcode Command Line Tools。在仓库根目录安装全局入口：

```sh
dotnet pack src/Orisumi.Cli -c Release -o .orisumi/packages
dotnet tool install --global Orisumi.Cli --source .orisumi/packages --version 0.1.1
```

将全局工具目录 `~/.dotnet/tools` 加入 `PATH`。`orisumi` 从当前目录向上定位 `Orisumi.slnx` 与 CLI 项目，遇到其他 Git 仓库即停止；仓库外不能使用源码入口。

每次调用先增量构建当前检出的 Debug 源码，包括未提交修改；失败即退出。构建信息写 stderr，命令保留 stdin/stdout、参数、退出码和工作目录，相对路径以调用位置为准。

普通源码修改无需重装；修改入口机制或项目路径后重新打包安装。直接运行构建产物不会自动构建；后台采集和 Chrome 接收端使用这种方式。

## 命令与运行

CLI 使用 `System.CommandLine`、`Spectre.Console`，开发命令在 `Orisumi.Cli/Dev`，各采集器独立成项目。完整选项见各命令 `--help`。

| 命令 | 用途 |
| --- | --- |
| `orisumi dev build [-c Release]` | 构建项目 |
| `orisumi capture start --store .orisumi` | 启动或重启系统采集器，保留数据 |
| `orisumi capture coverage --from … --to …` | 查询各来源的[观测依据与缺口](./recovery.mdx) |
| `orisumi codex capture --all` | 导入所有 Codex 会话；单会话可传 ID，省略时读 `CODEX_THREAD_ID` |
| `orisumi claude capture` | 导入 Claude 会话 |
| `orisumi foreground --windows --input --microphone --audio-output --camera` | 持续采集 macOS，选项各开一个通道；可指定秒数，Ctrl+C 正常停止 |
| `orisumi timeline --from … --to …` | 查询活动时间线，时间参数包含 UTC 偏移或 `Z` |
| `orisumi dev docs` | 文档预览；安装、检查和构建见[文档维护](./contributing.mdx) |

`--store` 默认是当前目录的 `.orisumi`，数据库在 `raw/`，日志在 `logs/`。

`capture start` 停止同一存储目录上次启动的前台进程，再从调用环境启动全部通道，以继承窗口和输入权限；PID 和进程启动时间写入 `foreground.pid`，停止前据此确认仍是同一进程；日志直接追加至 `logs/foreground.{out,err}.log`。启动命令退出或终端关闭后继续采集。

Codex、Claude 以 `capture --watch` 常驻监听，由用户 LaunchAgent 保活。配置指向当前构建产物，重新运行启动命令会替换配置并重启。Chrome 扩展需单独重载；首次注册也可使用 `capture start --extension-id EXTENSION_ID`。

重建输出库前停止相关监听和导入；重建后重启采集并重载扩展，建立新初值。来源数据保持只读，清空输出库不会删除来源内容。

## 浏览器扩展

```sh
orisumi dev browser install
orisumi dev browser build
orisumi browser register-chrome EXTENSION_ID --store .orisumi
```

在 Chrome 扩展页启用开发者模式，加载 `src/Collectors/Orisumi.Collectors.Browser/ChromeExtension`，使用页面显示的 ID 注册。修改扩展后重新构建并重载；注册指向当前构建的接收端，其 stdout 专用于 Native Messaging 二进制协议。

## 行数统计

`orisumi dev loc [--json]` 统计当前工作区，包括未提交修改和未忽略的新文件；跳过已删除文件、符号链接、空行和纯注释。`Impl`/`Tests` 按同一刻度显示，文档、配置和生成文件（含锁文件）归 `Outside code`，不计入代码总数。

项目从 `.csproj`、`package.json` 识别，嵌套文件归最近项目；名称分别取项目文件名和包名。项目内测试归该项目；独立 C# 测试只引用一个非测试项目时归该项目，其余归 `Cross-module`。独立脚本归 `Scripts`，CLI 的 `Dev/` 归 CLI 实现。无法归属的已识别语言文件列入 `Unclassified files`，不计入总数。

JSON stdout 包含 `code`、`roles`、`modules`、`languages`、`unclassifiedPaths`。文本重定向保持表格且不含终端控制码；`NO_COLOR` 关闭配色。

## 验证

在仓库根目录运行；测试使用临时数据和进程，结束后清理。

```sh
dotnet build Orisumi.slnx
dotnet run --file tests/CaptureStartupChecks.cs
dotnet run --file tests/SchemaChecks.cs
dotnet run --file tests/CaptureIntegrationChecks.cs
dotnet run --file tests/CaptureCoverageChecks.cs
dotnet run --file tests/ClaudeIncrementalChecks.cs
dotnet run --file tests/CodexIncrementalChecks.cs
dotnet run --file tests/MacOSObservationChecks.cs
npm --prefix src/Collectors/Orisumi.Collectors.Browser/Extension test
dotnet run --file tests/SourceLauncherChecks.cs -- "$(command -v orisumi)"
dotnet run --file tests/LocChecks.cs -- src/Orisumi.Cli/bin/Debug/net11.0/Orisumi.dll
```

启动检查覆盖独立存活、日志、信号和旧 PID；Schema 检查来源清单、结构打包、视图、coverage 列、重复打开；采集检查覆盖独立变化、修订、重试、身份与中断。源码入口检查使用临时仓库，覆盖更新、构建失败、参数、退出码、二进制输入输出和信号。LOC 检查使用临时 Git 仓库。

新增采集器的来源、恢复和数据库要求见[采集开发](./capture.mdx)。
