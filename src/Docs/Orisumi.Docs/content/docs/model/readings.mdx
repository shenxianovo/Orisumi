title: "读出"
description: "从原件算出来的东西，随时可以删掉重算"
---

从原件算出来的东西都叫读出。读法可以是一个程序，也可以是一次模型调用，两者只是读法不同，所以只用这一个概念。读出随时可以删掉，从原件重算。

依据：

- [留下观测重算理解](../requirements/belief.mdx#留下观测重算理解)：长期留下的是原件，读出随读法的进步重做。
- [身份事后读出](../requirements/belief.mdx#身份事后读出)：不同名字之间的对应关系也是一种读出。

## 读出记录

`orisumi run read` 读每个来源最新的一次采集，写出三种读出。每种读出在 `readings/<读出>/<读出 id>/` 下有两个文件：

- `items.jsonl`：产物，一行一条，每条带原件里的[位置](./raw.mdx#位置)。
- `reading.json`：读出 id、名字、读法（`orisumi read <读出> <版本>`）、读的时间，以及输入的采集（`<来源>/<采集 id>`）。

依据：[理解能追溯来源](../requirements/belief.mdx#理解能追溯来源)：从一条读出能找到读法、输入的采集和原件里的那一行。模型读出加进来时，读法记下模型、提示词和那次调用的 trace。

## 人说的话

`said`：人亲手输入给编程助手的话，按时间排。每条有时间、来源、会话 id、会话标题、工作目录、正文和位置。

勘探发现两家助手都标出了哪段是人亲手输入的，哪段是注入的上下文，标法不同：

- Claude Code：取 `type` 为 `user`、`origin.kind` 为 `human` 的记录里的文本块。rewind 会把记录复制进新的会话文件，uuid 不变，所以同一个 uuid 只读一次。标题取日志里的 `custom-title`。
- Codex：读 `threads.thread_source` 为 `user` 的线程，取 user 消息里 `content_item_kinds` 标为 `user.text` 的段。子 Agent 和续接文件开头复制来的历史标着 `inherited_user_message`，读的时候跳过；同一个线程里时间和正文都相同的只读一次。标题取 `session_index.jsonl` 里这个线程的最后一行，没有时取 `threads.title`。

依据：

- [同一份数据多种视图](../requirements/belief.mdx#同一份数据多种视图)：人自己讲述的东西是一种视图，知道是这个人写的就能放在一起看。
- [一件事散在多处](../requirements/belief.mdx#一件事散在多处)：同一条记录会出现在好几个文件里。

## 时间线

`timeline`：各台设备上的时段按时间排开。每条有起止、设备、种类、说明和位置。

| 种类 | 从哪来 | 说明 |
| --- | --- | --- |
| 前台 | 旧 Heartbeat 的时段 | 应用名、应用身份的原名、窗口标题 |
| 浏览器 | 旧 Heartbeat 的时段，来源是 `browser` | 页面标题和网址 |
| VRChat | 旧 Heartbeat 的时段，来源是 `vrchat.account` | 世界名 |
| 键鼠 | 旧 Heartbeat 的键鼠事件 | 每台设备每 10 分钟的按键、点击、滚轮次数 |
| Claude Code 会话 | 主会话日志 | 标题和工作目录 |
| Codex 会话 | `thread_source` 为 `user` 的线程 | 标题和工作目录 |
| 提交 | Git | 短 sha、标题行、改动的文件数和增删行数 |

- 设备：旧 Heartbeat 的时段用它所在的流对应的设备，会话用采集它的机器，提交用仓库的路径。
- 会话按记录的时间戳切段，相邻两条记录隔了 30 分钟以上就分成两段。Claude Code 同一个 uuid 只算一次，Codex 跳过复制来的历史。
- 提交按 sha 去重，时间取作者时间。

依据：

- [一件事散在多处](../requirements/belief.mdx#一件事散在多处)：前台、会话、提交各记一部分，摆在同一条时间线上才看得出一件事。
- 勘探发现前台不等于人在做什么：一台电脑没关、人在另一台前时，两台都有前台时段。每 10 分钟的键鼠计数用来分出哪台有人在操作。
- [一个东西有多个名字](../requirements/belief.mdx#一个东西有多个名字)：同一个应用在不同平台上的标识不同，产品名也会换。时间线同时显示应用名和应用身份的原名，对应关系留给身份读出。

## 覆盖

`coverage`：每台设备、每种数据哪些时段有数据，以及旧 Heartbeat 记下的丢失。

- 有数据：时间线里同一台设备、同一种类的时段，间隔在 30 分钟以内的连成一段。提交是瞬间的，不算覆盖。
- 丢失：旧 Heartbeat 的丢失记录按设备、数据种类和原因连成段，带估计丢失的条数。

依据：[采集会丢数据](../requirements/belief.mdx#采集会丢数据)：Agent 回答时要知道哪段是空的、为什么空。

## 时间

原件里的时间保持原样，两家会话和旧 Heartbeat 用的都是 UTC。读出存带时区的时间点，命令输出时换成本机时区，每段输出开头写明时区。

勘探发现时区出错发生在读取方把 UTC 换成本地时间、或按本地日期切分的那一步，所以换算只在显示时做一次。
