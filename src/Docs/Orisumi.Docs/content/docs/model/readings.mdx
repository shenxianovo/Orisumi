从原件算出来的内容叫读出。当前先交付采集与恢复；进入读取阶段时，从人亲手输入的文本和一个真实问题开始，按来源已验证的字段取出内容，并指回具体一次取得的原件。

例如，要查一句在 Codex 里说过的话，可以从保存的日志和数据库快照取出相关记录，把原话、来源和采集名字一起返回。来源字段直接支持的事实由程序读取，含义与动机交给使用材料的 Agent 解释。确定性读取反复答不好的题，再成为系统内模型处理的验证样本。

依据：[留下观测重算理解](../requirements/belief.mdx#留下观测重算理解)、[理解能追溯来源](../requirements/belief.mdx#理解能追溯来源)。

## 输入与引用

后续读取从仍保留的采集记录取得输入。每条结果保留精确的采集记录和材料路径；文本需要行内核查时可继续使用[位置](./raw.mdx#位置)。压缩文件、数据库快照和二进制附件先指向整份材料。

相同内容在两次采集或两处路径出现时，各自的出处都存在。只有读法用来源身份或其他证据证明等价后，才生成可展开全部出处的代表关系。代表位置属于读出，原来的精确引用保持原意；目标采集被逻辑删除时，引用报告失效。

首次需要数据库行、解码文本或媒体时间内的定位时，选一个真实样本验证带类型和版本的定位器。转换成文本的产物同时记录父原件与转换方法。

## 第一条读取路径

进入这一阶段后，先核对两家助手怎样区分人亲手输入的文本、注入上下文和复制历史，完成一条查询到原件的路径。导洞中的 `said`、`timeline`、`sources` 是需求线索，正式能力按真实问题逐个形成。

验证同时保留容易误判的例子：相同文本来自不同事件、前台应用不等于人在投入注意力、记录时间与取得时间不同、材料缺失而答案未知。原件时间值保持原样，统一时间表示和时区显示在读出中处理。

先用结构字段和全文检索支持明确词句。语义或关系索引由可核实的漏题触发，用同一题集比较收益、读取量和成本。

## 存在哪

第一类读出确实需要索引时，先验证单个本地 SQLite 投影。用已有基准材料和增长后的历史检查时间查询、全文检索、分页，以及删除投影后的全量重建。查询结果和索引都应能从长期保存事实重新得到。

远端并发查询成为真实需要时，再比较其他数据库或集中查询。当前先承担一种投影的实现和验证成本，取舍见 [0005 投影先验证单 SQLite](./adr/0005-projection-databases.mdx)。

## 模型处理何时加入

确定性读出遇到反复需要语义解释的任务时，用固定输入比较程序读取后交给 Agent 理解，与系统内模型处理的质量及费用，再决定是否加入模型处理。

正式模型处理若开始，每次保存实际发送的内容、工具往返、模型返回结果和能直接取得的运行信息。两次结果各自保留；有多个正式理解版本或人工纠正时，显式记录采用哪版，并验证选择可以重建。模型未返回的内部过程保持未知。

采用原则与验证条件见 [0004 模型处理启用时保留调用事实](./adr/0004-model-readings-as-records.mdx)。

## 怎么验收

先对照一个真实问题的来源事实，再逐步使用导洞基准和新来源的问题。确定性行为用最小输入输出核对；问答结果区分事实、推断与未知，引用能回到原件。新旧理解需要比较时，固定输入选代表题盲评，最终质量由用户判断。
