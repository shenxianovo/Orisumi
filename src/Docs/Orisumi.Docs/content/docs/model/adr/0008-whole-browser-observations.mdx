---
title: "0008 大浏览器观测完整保存后回执"
description: "用字节分片跨过 Native 上限，实时与回填分别发送"
---

真实 bookmarks API 的受控样本返回超过70 MiB，单条 Native 消息最多64 MiB；getTree 和 getVisits 的接口也无法统一靠分页缩小。采用扩展先持久化完整观测、必要时按字节分片、接收器重组成一份原件并发布后回执；分片不成为独立业务原件，中断从头重放。这样保留来源完整返回与既有原件恢复语义，代价是重传整件及整件 JSON 校验的内存成本。

标签和窗口观测、持久记录回填各使用一条固定 Native 连接，分别等待自己的完整回执。多一个接收进程换取发送故障隔离，避免单条大回填挡住实时队列；共用的 Worker 和本地存储仍可能产生延迟。单连接交错发送需要同时管理多个进行中原件及中断状态，本轮用两条连接保持接收器每连接单原件的规则。协议与失败留证见[浏览器观测](../browser.mdx#进入原件)。
