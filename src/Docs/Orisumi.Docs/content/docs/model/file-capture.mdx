以 Codex 为例，一轮采集读取日志和附件的原始字节，再取得 SQLite 数据库的完整快照，保存到同一份[原件](./raw.mdx)采集记录中。某份材料读不到时，其余材料照常保存，缺口写进这轮记录；随后可以恢复这轮已保存的内容，或等待下轮重采。

Claude Code、Codex 和任意目录共用一个采集器。来源提供名字、出处、一组目录及单独指定的文件；目录声明保存路径前缀、选择规则和是否可缺省，单独的文件声明保存路径及取得方式。扫描、读取、部分失败和定期运行都由共用采集器完成。

依据：

- [收集不靠自觉](../requirements/belief.mdx#收集不靠自觉)、[能补的也定期采](../requirements/belief.mdx#能补的也定期采)：启动后自动采，之后定期继续。
- [各处原样都存](../requirements/belief.mdx#各处原样都存)、[留最原始的一层](../requirements/belief.mdx#留最原始的一层)：保存选中的文件字节、数据库完整快照和链接目标，理解留给读出。
- [采集幂等](../requirements/belief.mdx#采集幂等)：重采时相同的块直接复用。

## 自动运行

```sh
orisumi run capture files <目录> --interval 300 --retries 1
orisumi run capture claude-code --once
orisumi run capture codex --home <Codex目录> --once
```

启动立即采一轮，每轮完成后等待 `--interval` 秒，再采下一轮；默认 300 秒。同一来源串行采集。`--once` 让三种采集命令都只运行一轮。停止命令就停止循环。

`--retries` 控制本轮读取的额外尝试次数，默认 1 次。普通文件读不到或检查发现变化时重试；SQLite 在忙或被锁定时重试。重试用完仍失败，记下路径和原因。

`--store <目录>` 选择原件存储，采集和 `raw` 命令共用这个选项。省略时沿用[概览里的默认目录](./index.mdx#代码)。

每轮重新枚举并读取选中的材料，已有块由原件存储复用。采集器排除自身的存储目录，符号链接按[链接规则](#符号链接)记录。源文件消失时，已经采下的原件继续保留；只有新的文件清单变化。

这是采集程序启动后的自动循环。当前 macOS 的登录启动与固定运行位置见[本机持续采集](./continuous-capture.mdx)；文件系统事件监听按来源的实际变化窗口另行选择。

## 文件字节

文件可以长期被别的程序打开。采集器尝试以允许共享读、写和删除的方式打开，记录长度、修改时间和创建时间，读取开头长度范围内的字节，读完再检查文件句柄与路径的信息。

读到的字节先放进会在关闭时删除的临时文件。检查通过后，再从临时文件切块入库。读取期间被截断、路径被替换，或检查发现变化，就丢弃这次临时结果并重试；重试用完仍失败，把路径和原因记入本轮失败说明。权限和共享限制导致打不开时，同样处理。

文件内容保持原样，包括末尾尚未写完整的记录、二进制附件和压缩文件。压缩文件也按读取到的字节保存；其中的损坏同样留下，解压和内容解释属于读出。清单的 `method` 是 `file-bytes`。

## SQLite 快照

需要数据库一致性的文件由来源明确指定。采集器只读打开源数据库，通过 SQLite online backup 生成临时数据库，再将完整快照切块保存，清单的 `method` 是 `sqlite-online-backup`。

快照包含整个数据库的结构和数据，包括采集程序尚不认识的表、索引、二进制值和空值。SQLite 将主文件及 WAL 中参与这份一致状态的已提交数据合在一起，所得快照可以作为单个数据库文件独立打开。保存的字节是快照文件的字节，源数据库主文件和 WAL 的物理布局由 SQLite 处理。

数据库忙或被锁定时按本轮重试次数再试；格式损坏、缺失或读取失败时记录缺口。临时快照及其旁文件在读取结束或失败后删除。数据库的失败和普通文件的失败一样，保留本轮已经保存的其他材料。

## 符号链接

对选中范围内的符号链接，采集器读取链接目标的原字符串，清单的 `method` 是 `readlink`，目标写进 `linkTarget`。链接本身的文件内容是空的。链接到文件或目录都按这个规则保存，目录链接的目标留给恢复后的使用者按需访问。

来源根目录若本身是符号链接，本轮将它记为未遍历的缺口。明确要求 SQLite 快照的文件若是符号链接，本轮保存链接目标，同时记下未取得数据库快照。链接的恢复方式见[恢复与导出](./raw.mdx#恢复与导出)。

## 采集时间窗口

采集根的 `capturedAt` 记录本轮开始，`completedAt` 记录本轮结束。材料在这个窗口中逐项取得：单份 SQLite 快照内部一致，日志、附件和数据库之间可能对应不同时间。

普通文件的大小、修改时间和创建时间检查能发现常见变化；元数据保持相同的原地改写仍可能漏过。周期扫描保留每轮实际观察到的内容，两轮之间出现又消失的文件和中间版本可能未被采到。

## 结果和失败

沿用采集根的 `manifest` 和 `failure` 两个字段：

| 结果 | `manifest` | `failure` |
| --- | --- | --- |
| 完整完成 | 有，来源为空时是空清单 | `null` |
| 部分完成 | 有，只列成功保存的材料 | 有，按路径排序汇总未采到的路径和原因 |
| 全部失败 | `null` | 有 |

单个文件或目录的读取失败不会挡住其他目录和文件。块、清单或根的存储失败则终止本轮，向调用方报告；程序继续等待下一轮。如果存储仍可用，就留下失败采集记录；连记录也无法保存时，错误留在运行输出里。

可缺省目录不存在时按没有这类材料处理；目录存在但读不到、实际是普通文件，或根目录是符号链接时仍记缺口。各来源声明哪些目录可缺省，见[来源说明](./sources.mdx)。

失败原因保存在采集记录并写入运行输出，调用方可以查看本次结果。当前持续探活暂缓；实际需要发现采集停止或长期没有新结果时，再接一个简单的外部检查。

依据：[采集失败要通知](../requirements/belief.mdx#采集失败要通知)。

## 代码接口

`Orisumi.Capturing` 的 `CaptureSource` 描述来源；`FileRoot` 描述目录、保存路径前缀、选择规则和是否可缺省；`FileInput` 描述单独指定的文件、保存路径和读取方式。多个输入汇入同一份清单。每份材料的 `origin` 记来源的绝对路径，采集根的 `origin` 由来源提供。CLI 的 `files` 来源使用目录的绝对路径作为出处，采目录里的普通文件和符号链接。

`Collector.Scan` 完成一轮，`Collector.Watch` 定期产出每轮结果。普通文件字节由 `StableFileReader` 取得，数据库快照由 `SqliteSnapshotReader` 取得。`ClaudeCodeSource` 和 `CodexSource` 声明各自的来源规则；块、清单和根的编码仍放在 `Orisumi.Raw`。
