---
title: "原件"
description: "从来源拿到的最原始的一层，原样存下"
---

原件是从一个来源能拿到的最原始的那一层，原样存下，解析、去重和合并都留给读出。一次采集运行一个来源的采集程序，得到一组原件和一份采集记录。

依据：

- [留最原始的一层](../requirements/belief.mdx#留最原始的一层)：原件默认一直保留，以后的每种读法都从它出发。
- [各处原样都存](../requirements/belief.mdx#各处原样都存)：一件事散在几处的，几处都存，复制出来的几份也照存。

## 采集记录

每次采集在 `raw/<来源>/<采集 id>/capture.json` 写一份采集记录：

| 字段 | 内容 |
| --- | --- |
| `id` | 采集 id，开始采集的 UTC 时间 |
| `source` | 来源：`claude-code`、`codex`、`heartbeat`、`git` |
| `collector` | 采集程序和它的版本，例如 `orisumi capture codex 1.0.0+<提交>` |
| `host` | 在哪台机器上采的 |
| `capturedAt` | 什么时候采的 |
| `origin` | 从哪个位置采的：目录，或者数据库所在的主机 |
| `from`、`to` | 采的时间范围 |
| `sourceVersion` | 来源软件的版本，采集程序能问到时记下，例如 Git 的版本、旧 Heartbeat 库的迁移号 |
| `files` | 每个文件的路径、原位置、字节数和 SHA-256 |

依据：

- [记下采集器版本](../requirements/belief.mdx#记下采集器版本)：以后才知道该怎么读。
- [格式随版本变化](../requirements/belief.mdx#格式随版本变化)：勘探中 Codex 三个月里有 28 个版本；旧 Heartbeat 的应用标识和键码都中途换过格式。

## 位置

原件里的一行用位置指称：`<来源>/<采集 id>/<文件>:<行号>`，例如 `codex/20261103T143521Z/session_index.jsonl:12`。读出的每一条、命令输出的每一行都带着位置，任何结论都能回到原件里的那一行。

依据：[理解能追溯来源](../requirements/belief.mdx#理解能追溯来源)。

## 旧 Heartbeat 交来的行

旧 Heartbeat 是上一版的采集端，它已经把前台、浏览器、键鼠和 VRChat 采成了数据库里的行。这些行是现在能拿到的最原始的一层，所以当作从系统读到的数据存成原件，来源版本记旧 Heartbeat 库的迁移号。

新采集端上线时旧 Heartbeat 下线，两者前后接替，时间上不重叠。旧 Heartbeat 交来的是它在客户端切好的时段，新采集端交来的形状可以不同，读出按采集程序和版本分别读。

依据：

- [有的数据错过就没了](../requirements/belief.mdx#有的数据错过就没了)：前台和键鼠当时没采到就没有了，旧 Heartbeat 留下的就是全部。
- [格式随版本变化](../requirements/belief.mdx#格式随版本变化)：换了采集端，形状跟着变。
