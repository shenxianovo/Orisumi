原件是从一个来源能拿到的最原始的那一层，原样存下，解析、去重和合并都留给读出。一次采集运行一个来源的采集程序，得到一组原件文件和一份采集记录。原件文件、采集记录和删除记录都存成块，块是唯一的事实。

依据：

- [留最原始的一层](../requirements/belief.mdx#留最原始的一层)：原件默认一直保留，以后的每种读法都从它出发。
- [各处原样都存](../requirements/belief.mdx#各处原样都存)：一件事散在几处的，几处都存，复制出来的几份也照存。
- [原件存成块](../requirements/belief.mdx#原件存成块)：块按内容寻址、不可变，其余都是投影。

## 完整内容的边界

**完整内容**是采集端一次交给存储的一段有结束边界的原始字节。一份完整内容可以包含多个来源单元，存储时可以拆成多个块。

采集端按来源决定完整内容在哪里结束：普通文件交来一次读取的字节；SQLite 交来 online backup 取得的一份完整数据库快照；连续事件来源按自己的规则组成一批事件再交付。事件批次的大小和时间由各来源设计确定。取得方式随内容记在清单里。

存储层负责将完整内容切成物理块，并按原顺序读回。来源单元、完整内容和物理块分别有自己的边界，出处与采集运行另行表达。

依据：

- [留最原始的一层](../requirements/belief.mdx#留最原始的一层)：文件、数据库行和系统事件各有来源给出的原始形态。
- [原件存成块](../requirements/belief.mdx#原件存成块)：大文件按内容切成块，小记录先成批再切。
- [来源怎么采](./sources.mdx)：文件读取、数据库快照和数据库行导出按各自来源取得原件。

## 两层

完整材料与物理块分开表达：

- **完整材料**：一次文件读取、一个数据库快照或来源交来的一批事件。清单保留材料的完整哈希、出处和保存路径。
- **块**：完整内容按字节切成的物理单位，用来存储、复用和恢复。一份材料可以跨多个块，材料内部的一条记录也可以跨块。

材料内部如何定位单独决定：当前明文文本可按行读取，压缩文件、数据库快照和附件先通过采集记录与保存路径引用整件。需要解析才能确定的位置，随读法增加。物理切块与这些[位置](#位置)分开。

依据：

- [留下观测重算理解](../requirements/belief.mdx#留下观测重算理解)：解析是理解的一部分，解析器改进了，重新读一遍就行。
- [不绑定某种存储](../requirements/belief.mdx#不绑定某种存储)：物理切法可以换，上层的单元和位置不跟着变。

决定见 [0001 完整材料、定位器与物理块分开](./adr/0001-two-layer-chunking.mdx)。

## 块

块名是块内容的 SHA-256，带算法前缀，例如 `sha256-00a81be0…`，按压缩前的原文算。已经有的块不再写，相同字节切出的相同块共用存储。追加日志通常复用前部的块，新块数量由内容和切点决定。

- **存放**：所有来源的块混放，按名字的前两个十六进制字符分到 256 个子目录。一个块属于哪个来源、哪个文件，只写在采集记录里；按来源看是投影。
- **压缩**：压缩后变小的块存成标准 zstd 帧，其余保留原字节；内容开头恰好像 zstd 帧的一律压缩。读取先检查 `28 B5 2F FD` 魔数：有魔数则解压一层，否则直接取文件字节，再计算 SHA-256 核对块名。这个规则只依赖 zstd 和 SHA-256，独立读者也能恢复。
- **校验**：每个块读出时都核对哈希，对不上就报错。

切块器决定在哪里切，块名决定块是谁，两者各管一件事：切块器用 Gear 哈希快速找切点，块名用 SHA-256 确定内容。

切块器是存储格式的一部分，带版本：

- 第 1 版叫 `orisumi-cdc-1`：FastCDC 的切法，最小 256 KiB、平均 1 MiB、最大 4 MiB，归一化级别 2；GEAR 表的第 i 项取 SHA-256(i) 的前 8 字节，判断切点用哈希的高位。
- `config.json` 记当前用哪一版，每份采集记录记它自己用的那一版。换了切块器，新的采集按新版本切，旧块照样能读；新旧两版之间的去重断开。读原件从来用不到切块器。

采集程序自己导出的批量记录，例如旧 Heartbeat 的行，按时间和主键排序，让相同结果重采时逐字节一样。排序和查询由来源规则确定，用的查询原样记在采集记录的 `origin` 里。Codex 保存整个 SQLite 数据库的一致快照，取得方式见[文件采集](./file-capture.mdx#sqlite-快照)。块复用按每次实际交来的字节判断。

依据：

- [采集幂等](../requirements/belief.mdx#采集幂等)：同一份原件采多少次，存下来的都是同一份。
- [数据比代码长寿](../requirements/belief.mdx#数据比代码长寿)：读块只要 zstd 和 SHA-256。

## 采集记录

每次采集写一份采集记录，内容没变也写，失败了也写。采集记录分两部分，都是块。

所有记录都编成紧凑的 UTF-8 JSON：字段按下表的顺序，空值照写 `null`，时间一律是 UTC、精确到毫秒，例如 `2026-11-04T04:44:30.737Z`，中文原样写。

**根**放在 `records/` 下，内容与文件清单分开，不读别的块就能列出全部采集：

| 字段 | 内容 |
| --- | --- |
| `kind` | 记录的种类，根是 `capture`；`records/` 下还放着删除记录，以后还有模型读出的记录 |
| `source` | 来源，例如 `files`、`claude-code`、`codex`、`heartbeat`、`git` |
| `collector` | 采集程序和它的版本，例如 `orisumi capture codex 1.0.0+<提交>` |
| `chunker` | 这次采集用的切块器 |
| `host` | 在哪台机器上采的 |
| `capturedAt` | 本轮采集开始的时间 |
| `origin` | 从哪个位置采的：目录，或者数据库所在的主机和那条查询 |
| `from`、`to` | 采的时间范围，没有范围的来源写 `null` |
| `sourceVersion` | 来源软件的版本，采集程序能问到时记下，例如 Git 的版本、旧 Heartbeat 库的迁移号 |
| `manifest` | 文件清单：`hash` 是整份清单的名字，`blocks` 是按顺序组成它的块 |
| `failure` | 失败的原因，写成 `{"reason": "…"}`；成功时是 `null` |
| `completedAt` | 本轮结束的时间，写根时记录 |

`capturedAt` 和 `completedAt` 围出本轮取得材料的时间窗口；其中的文件和数据库分别读取。SQLite 快照内部是一致状态，各文件之间仍可能反映这个窗口内的不同时间。`from`、`to` 表达来源筛选的数据时间范围，与本轮运行的起止时间分开。

全部失败的采集同样写一个根，`manifest` 是 `null`，`failure` 写明原因，例如目录不存在、没有读权限。部分完成时，两者同时存在：`manifest` 只列成功保存的文件，`failure.reason` 汇总未采到的路径与原因。来源不在和来源为空分开记：空目录是一次成功的采集，清单里没有文件。具体的读取和重试规则见[文件采集](./file-capture.mdx)。

**文件清单**是 JSON Lines，每个文件或符号链接一行，按路径的 UTF-8 字节序排序：

```json
{"path":"projects/x.jsonl","origin":"/Users/me/.claude/projects/x.jsonl","bytes":123,"hash":"sha256-…","blocks":["sha256-…"],"method":"file-bytes","linkTarget":null}
```

`path` 是本轮内的保存路径，`origin` 是来源位置，`bytes`、`hash` 和 `blocks` 分别是已保存内容的字节数、完整 SHA-256 和按顺序组成它的块。`method` 记取得方式：

| `method` | 保存内容 |
| --- | --- |
| `file-bytes` | 普通文件读取到的原始字节 |
| `sqlite-online-backup` | SQLite online backup 产生的完整数据库快照 |
| `readlink` | 符号链接的目标原字符串，写在 `linkTarget` |

普通文件和数据库快照的 `linkTarget` 是 `null`。符号链接的 `bytes` 是 0、`hash` 是空内容的 SHA-256、`blocks` 是空数组，链接目标只在 `linkTarget` 中保存。读取链接目标时保留原字符串，包括相对路径或指向来源目录之外的路径。

清单像原件一样切成块，存在 `blocks/` 下：内容没变时就是同一个名字，一次内容不变的采集只多一个根。一个文件变化通常只影响清单的一部分块，实际复用范围由清单字节与切点决定。

依据：

- [记下采集器版本](../requirements/belief.mdx#记下采集器版本)：以后才知道该怎么读。
- [格式随版本变化](../requirements/belief.mdx#格式随版本变化)：勘探中 Codex 三个月里有 28 个版本；旧 Heartbeat 的应用标识和键码都中途换过格式。
- [采集失败要通知](../requirements/belief.mdx#采集失败要通知)：每次采集都留下记录，事后分得清哪段采过、哪段没采到。
- [采集幂等](../requirements/belief.mdx#采集幂等)：导洞里一份 Claude Code 的采集记录压缩前 346 KB，每小时重列一遍会白白攒下；拆出清单以后，没变的部分只存一份。

## 恢复与导出

```sh
orisumi run raw restore <采集> <新目录>
orisumi run raw export <采集> <保存路径> <新文件>
```

`raw restore` 将一份采集恢复到新的目标目录：

```text
<新目录>/
  capture.json     原样保存的采集记录根
  manifest.jsonl   原样保存的文件清单
  files/          按保存路径恢复的文件和符号链接
```

例如，Codex 的数据库恢复到 `files/state_5.sqlite`，可以直接用 SQLite 打开；日志、图片和其他附件也各有文件。恢复读取原件存储中的块，来源目录可以已经消失。部分完成的采集恢复清单中已经保存的材料，缺口仍写在 `capture.json` 的 `failure` 中。

恢复时核对每个块的哈希、整份清单的哈希，以及每个文件的长度和完整哈希。全部材料恢复成功后才发布目标目录；失败或取消时清理临时结果。目标目录须是一个新路径。

符号链接按 `linkTarget` 的原字符串重建。指向恢复目录外的链接仍依赖那个外部位置，搬动恢复目录后也按原来的目标寻找文件。普通文件的内容独立保存在恢复目录里。

`raw export` 只导出清单中的一个普通文件或数据库快照，核对长度和哈希后写到新的目标文件。符号链接随整份采集恢复。`CaptureRecovery` 实现这两个操作，查看清单和读原件仍由 `RawStore` 提供。

单轮恢复以一份仍保留的采集为输入。完整存储的副本还要保留采集记录、删除记录及它们所需的块，副本取得与恢复的下一步验证见[副本与节点](./nodes.mdx)。

依据：[数据比代码长寿](../requirements/belief.mdx#数据比代码长寿)、[理解能追溯来源](../requirements/belief.mdx#理解能追溯来源)：保存下来的材料可以独立读取，并带着出处和取得方式。

## 删除记录

删除写成一条删除记录，也是块，放在 `records/` 下，写着目标采集、时间、原因和执行的机器：

```json
{"kind":"deletion","target":"sha256-<根>","deletedAt":"2026-11-04T07:35:02.118Z","reason":"…","host":"…"}
```

当前 `raw delete` 保存这条记录，使目标采集从正常列举与查找中消失。采集记录和内容块仍在存储里，磁盘空间继续占用。物理删除和共享块回收在用户提出具体需求后，先预览影响范围，再按获准范围实现。

完整存储副本保留删除事实，恢复可见采集时一并应用；外部备份的保留规则还可能留着已逻辑删除的字节。

依据：[原件存成块](../requirements/belief.mdx#原件存成块)、[多处都有一份](../requirements/belief.mdx#多处都有一份)。

## 位置

精确出处由采集记录和材料路径确定。当前明文文本里的行可以用位置指称：`<来源>/<采集记录>/<文件>:<行号>`。

- 读出里存采集记录根的完整名字；命令输出只显示名字的前 12 个十六进制字符，例如 `codex/3f9a1c2e7b4d/session_index.jsonl:12`；输入时接受至少 8 个字符、并且唯一的前缀，和 git 的短 sha 一样。
- 相同内容在几次采集里出现时，各次采集的引用保持独立。目标采集逻辑删除后，原引用报告失效。按证据归并的代表位置留给后续读出。
- `raw line` 按指定采集和路径接回文件字节，再按文本行读取，适用于明文 JSONL 等文本材料。
- 压缩日志、数据库快照和二进制附件先通过采集记录与保存路径引用整件，交给 `raw export` 或 `raw restore` 取得内容。细粒度定位由需要它的读法逐项验证。

后续读出保留精确出处，结论先能回到对应材料，再按已验证的定位方式进入其中。来源自己的身份保留在原件里，跨来源对应另由读出解释。

依据：[理解能追溯来源](../requirements/belief.mdx#理解能追溯来源)。决定见 [0002 位置精确指向一次取得](./adr/0002-position-by-record-name.mdx)。

## 旧 Heartbeat 交来的行

旧 Heartbeat 是上一版的采集端，它已经把前台、浏览器、键鼠和 VRChat 采成了数据库里的行。这些行是现在能拿到的最原始的一层，所以当作从系统读到的数据存成原件，来源版本记旧 Heartbeat 库的迁移号。旧 Heartbeat 交来的是它在客户端切好的时段，新采集端交来的形状可以不同，读出按采集程序和版本分别读。

依据：

- [有的数据错过就没了](../requirements/belief.mdx#有的数据错过就没了)：前台和键鼠当时没采到就没有了，旧 Heartbeat 留下的就是全部。
- [格式随版本变化](../requirements/belief.mdx#格式随版本变化)：换了采集端，形状跟着变。
