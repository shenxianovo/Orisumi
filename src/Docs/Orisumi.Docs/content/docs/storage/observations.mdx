---
title: "Observations"
description: "Observation、事物、类型和 InputSet 的权威表：Observation 怎样保存，内容怎样表示，删除时留下什么"
---

`observations` 保存每份未删除的 Observation，`deleted_observations` 记住每份已删除的 Observation 的身份，`things` 保存事物，这三张是 Core 数据的权威位置。类型和输入集各有自己的表：`schema_revisions`、`thing_types` 和 `input_sets` 是权威表，`schemas` 是投影，支持按资源名查找类型。

## observations [#observations]

每份未删除的 Observation 一行。保存后不再修改，删除时移除。

| 列 | 类型 | 含义 |
| --- | --- | --- |
| `observation_id` | `uuid` | 身份，主键 `pk_observations` |
| `schema_id` | `uuid` | 业务类型的 SchemaId |
| `schema_revision_id` | `uuid` | 所用的 SchemaRevision |
| `observer_id` | `uuid` | 负责的 Observer |
| `speaker_id` | `uuid`，可空 | 说话人 |
| `observer_description_id` | `uuid`，可空 | 形成这份陈述时 Observer 的描述 |
| `formation` | `text` | 形成方式 |
| `input_set_id` | `uuid`，可空 | 这次处理用到的 InputSet |
| `replaces` | `uuid[]` | 被它替换的 Observation，可以为空数组 |
| `start_at`、`end_at` | `timestamptz`，可空 | 事实时间的边界 |
| `time_zone` | `text`，可空 | 事实所属的 IANA 时区 |
| `recorded_at` | `timestamptz` | 保存时间 |
| `content` | `jsonb` | 业务字段，与 API 中的 `content` 相同 |
| `fact_range` | `tstzrange`，可空 | 用于时间查询的事实时间范围，见[换算与查询](./queries.mdx#fact-range) |
| `claim_key` | `text`，可空 | 命题键的摘要，类型没有声明 `claimFields` 时为 `NULL` |
| `state_key` | `text`，可空 | 状态键的摘要，类型没有声明 `stateFields` 时为 `NULL` |
| `search_text` | `text`，可空 | `searchable` 字段的值，用换行连接 |

| 约束或索引 | 内容 | 用途 |
| --- | --- | --- |
| `ix_observations_schema_id_fact_range` | GiST `(schema_id, fact_range)` | 按类型和事实时间查询 |
| `ix_observations_fact_range` | GiST `(fact_range)` | 不限类型的事实时间查询 |
| `ix_observations_schema_revision_id` | `schema_revision_id` | 找出使用某条修订的 Observation |
| `ix_observations_schema_id_observation_id` | `(schema_id, observation_id)` | 按业务类型列出；删除类型前检查 [HISTORY-9](../core/rules/history.mdx#history-9) |
| `ix_observations_observer_id` | `observer_id` | 按负责的 Observer 查询 |
| `ix_observations_speaker_id` | `speaker_id` | 按说话人查询 |
| `ix_observations_formation` | `formation` | 按形成方式查询 |
| `ix_observations_claim_key` | `claim_key`，只含非空值 | 找出同一命题的 Observation |
| `ix_observations_state_key` | `state_key`，只含非空值 | 同一状态取一条 |

多列 GiST 索引需要 `btree_gist` 扩展，由 Initial migration 创建。

- `observer_id`、`speaker_id`、`observer_description_id` 和 `input_set_id` 都没有外键：目标删除后引用保留，见 [HISTORY-8](../core/rules/history.mdx#history-8)。所以按 Observer 查询在 Observer 删除后照常返回。
- `claim_key`、`state_key` 和 `search_text` 在保存时按 SchemaRevision 算出，保存后不变。`claim_key` 和 `state_key` 是类型加字段值的 SHA-256，用摘要作键，所以比较时不用读内容。

### 内容的表示 [#content]

- `content` 以 `jsonb` 保存，空白和键的顺序不保留。字符串中不能有 `\u0000` 或无效的代理对，否则 API 返回 `400`。
- 数值以 `jsonb` 的 `numeric` 保存，`integer` 没有 64 位的上限。数值必须在 `numeric` 的范围内（小数点前最多 131,072 位，小数点后最多 16,383 位），超出时 API 返回 `400`。
- 事实时间保存在列中，见 [PostgreSQL · 时间](./postgresql.mdx#time)。

## things [#things]

每个事物一行，保存它的身份和类型。

| 列 | 类型 | 含义 |
| --- | --- | --- |
| `thing_id` | `uuid` | 事物的身份，主键 `pk_things` |
| `schema_id` | `uuid` | 事物的类型 |
| `deleted` | `boolean` | 事物是否已删除 |

| 约束或索引 | 内容 | 用途 |
| --- | --- | --- |
| `ix_things_schema_id_thing_id` | `(schema_id, thing_id)` | 按类型列出事物；删除事物类型前检查 [HISTORY-9](../core/rules/history.mdx#history-9) |

事物没有内容，所以删除时保留这一行作为删除的身份，把 `deleted` 置为真，后端据此返回 `410`。

## deleted_observations [#deleted-observations]

每份已删除的 Observation 一行，永久保留，只保存身份。

| 列 | 类型 | 含义 |
| --- | --- | --- |
| `observation_id` | `uuid` | 已删除的 Observation 的身份，主键 `pk_deleted_observations` |

- 读取时，身份在这张表中就返回 `410`，在 `observations` 和这张表中都不存在就返回 `404`。
- 一个 `observationId` 不能同时出现在两张表中，后端生成时避开两张表，见 [OBSERVATION-12](../core/model/observation.mdx#observation-12)。
- 程序实例在第一次写入之前被删除时，它的 `thingId` 由实例登记的移除标记占用，见 [Management · 第一次写入的检查](./management.mdx#first-version)。

## schema_revisions [#schema-revisions]

每条 SchemaRevision 一行，保存后不再修改。

| 列 | 类型 | 含义 |
| --- | --- | --- |
| `schema_revision_id` | `uuid` | 修订的身份，主键 `pk_schema_revisions` |
| `schema_id` | `uuid` | 业务类型的 SchemaId，索引 `ix_schema_revisions_schema_id` |
| `recorded_at` | `timestamptz` | 保存时间 |
| `content` | `jsonb` | 字段、约束和含义 |

`observations.schema_revision_id` 的外键 `fk_observations_schema_revisions_schema_revision_id` 指向这张表，所以修订在使用它的数据删除之前不能移除。

## thing_types [#thing-types]

每个事物类型一行。

| 列 | 类型 | 含义 |
| --- | --- | --- |
| `schema_id` | `uuid` | 事物类型的 SchemaId，主键 `pk_thing_types` |
| `resource_name` | `text` | 资源名，唯一索引 `ux_thing_types_resource_name` |
| `display_name` | `text` | 类型名称 |
| `description` | `text` | 业务说明 |

资源名在事物类型和 Schema 之间也不重复，见 [SCHEMA-5](../core/model/schema.mdx#schema-5)。两张表分开，这项检查由后端在串行的事务中完成。

## schemas [#schemas]

每个未删除的 Schema 一行，是投影，支持按资源名查找业务类型。

| 列 | 类型 | 含义 |
| --- | --- | --- |
| `schema_id` | `uuid` | SchemaId，主键 `pk_schemas` |
| `resource_name` | `text` | 资源名，唯一索引 `ux_schemas_resource_name` |

字段定义、名称和说明在 `schema_revisions.content` 中。删除 Schema 时移除这一行，资源名随之释放。

## input_sets [#input-sets]

每个 InputSet 一行。InputSet 是一个值，保存后不变，也不删除。

| 列 | 类型 | 含义 |
| --- | --- | --- |
| `input_set_id` | `uuid` | InputSet 的身份，主键 `pk_input_sets` |
| `members` | `uuid[]` | 成员的 `observationId` |

`members` 上的 GIN 索引 `ix_input_sets_members` 支持按成员反查。成员被删除后留在数组中，读取时不可读取，这里只有 id，不含内容。

## 删除 [#deletion]

第二天用户删掉浏览器的时段。删除一份 Observation 时，在一个事务中执行下面的步骤：

1. 沿 `replaces` 找出全部被它替换的 Observation，这是一个集合。
2. 经 `input_sets.members` 和 `observations.input_set_id` 找出依据这个集合的 Observation，作为响应的 `dependents`，集合内的不算。
3. 把集合中的 `observation_id` 写入 `deleted_observations`。
4. 把它们的识别依据写成[墓碑](./queries.mdx#key-tombstones)，删除 `recognition_keys` 中的行。
5. 删除它们在各张投影中的行，再删除已没有使用方的内容，见 [Contents · 删除](./contents.mdx#deletion)。
6. 删除它们在 `observations` 中的行。

删除一个事物时，先经 `observation_references` 找出以 `about` 和 `part` 引用它的 Observation，把每一份按上面的步骤删除。然后把 `things` 的 `deleted` 置为真，把它的识别依据写成墓碑。它是受管理的程序实例时，再把实例登记标记为已移除，见 [Management · 删除实例](./management.mdx#removal)。

其他 Observation 对被删除目标的引用留在它们的内容和 `observation_references` 中，见 [HISTORY-8](../core/rules/history.mdx#history-8)。删除不保存删除的时刻。
