后端在 PostgreSQL 中保存二十一张业务表。九张是 Core 数据的权威，七张是推导出来、供查询使用的投影，`runs` 和 `run_reads` 记下一次工作读过什么，`write_streams` 记下写入流的进度，另外两张是 Observer 的管理登记。这样设计的理由见 [ADR · 数据存储](../adr/data-storage.mdx)。

此外还有迁移工具自己的元数据表。

## 例子 [#example]

[Walkthrough](../start/walkthrough.mdx) 那一天 16:00，VS Code 的前台时段结束，这份 Observation 已保存：

| 表 | 这一段对应的行 |
| --- | --- |
| `observations` | 这一段一行，记着内容、Observer、形成方式和事实时间 |
| `things` | VS Code 这个本机应用一行，第一次提到时写入 |
| `observation_references` | 这一段对 VS Code 一行，对前台状态 Observer 一行 |
| `contents` | VS Code 的图标一行，之后的时段读到同一个图标时共用 |
| `recognition_keys` | VS Code 这个本机应用一行，第一次读到它时写入 |
| `observation_contents` | 这一段对图标一行 |
| `observer_instances` | 前台状态 Observer 一行，记着它的启用状态、设置和最近的状态报告 |

第二天用户删掉浏览器的时段，它从 `observations` 中移除，身份写入 `deleted_observations`，它在各张投影中的行也随之移除；图标还有其他时段使用，所以保留。

- 七张投影可以随时从权威表重建，见[重建](#rebuild)。
- 权威表不设置指向投影的外键。投影可以有指向权威表或其他投影的外键。
- `recognition_keys` 不能从 Observation 推导：调用方给出的值由业务规则组成，后端不解释它们。`write_streams` 不是 Core 的数据，丢失时已经处理的请求可能再处理一次，程序下次启动时重新声明业务类型。
- 两张管理表不是 Core 的投影，配置、凭证和移除标记都不能从 Observation 推导。

按类型的查询都从以类型开头的索引进入，只读取目标类型的行，所以数据量大的类型不影响其他类型的查询。各表的约束和索引写在表所在的页中，名字的写法见[命名](#naming)。

## 事务 [#transactions]

- 每个操作在一个事务中完成，事务开始时取得一个固定键的事务级 advisory lock（`pg_advisory_xact_lock`）。所以所有读写，包括管理登记的写入，都串行执行。
- 一个写入请求在一个事务中完成，每次写入一个保存点。一次写入被拒绝时回到它的保存点，其他写入照常保存，见 [OBSERVATION-17](../core/model/observation.mdx#observation-17)。序号和请求中的写入在同一个事务中保存，所以重发不会重复。
- 保存一份 Observation 时，`observations` 的新行、它提到的新事物、它在投影中的变化和这次写入登记的识别依据在同一个事务中写入。
- 删除时，删除身份、Observation、投影的变化、墓碑、不再使用的内容和管理登记的移除标记在同一个事务中写入，见 [Observations · 删除](./observations.mdx#deletion)。

## 重建 [#rebuild]

七张投影按以下方式从权威表算出，结果与逐次保存和删除后的投影相同：

1. `schemas`：每个在 `schema_revisions` 中有行的 SchemaId 一行。
2. `observation_references`：按每份 Observation 的 Core 成员和 SchemaRevision 枚举它的引用。
3. `observation_contents`：按每份 Observation 的 SchemaRevision 枚举它的 `binary` 值，每份对每个摘要一行。
4. `replacements`：每份 Observation 的 `replaces` 中每个元素一行。
5. `reviews`、`same_as_links`、`adoptions`：读对应类型的 Observation，见 [Queries · 默认视图](./queries.mdx#view)。

重建只读权威表，不写入它们。

## 命名 [#naming]

同一个名字在三处使用三种写法：

| 位置 | 格式 | 示例 |
| --- | --- | --- |
| API 字段 | `camelCase` | `observerDescriptionId` |
| C# 属性 | `PascalCase` | `ObserverDescriptionId` |
| 表名、列名、约束名、索引名 | `snake_case` | `observer_description_id` |

约束和索引按下表命名：

| 约束或索引 | 规则 | 示例 |
| --- | --- | --- |
| 主键 | `pk_<表名>` | `pk_observations` |
| 外键 | `fk_<表名>_<目标表>_<列名>` | `fk_observations_schema_revisions_schema_revision_id` |
| 检查 | `ck_<表名>_<内容>` | `ck_observer_hosts_kind` |
| 唯一索引 | `ux_<表名>_<列名>` | `ux_schemas_resource_name` |
| 普通索引 | `ix_<表名>_<列名>` | `ix_things_schema_id_thing_id` |
