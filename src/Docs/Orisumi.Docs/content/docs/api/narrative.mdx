---
title: "Narrative"
description: "请求叙事 Observer 写一天的几件事，边写边收到结果"
---

Web 控制台打开一天时，如果这一天还没有写下的几件事，它请求叙事 Observer 写这一天：`POST /narratives` 带上这一天的范围和时区，响应是一条事件流，每写完一件事收到一个 `episode`，最后收到 `saved`。叙事 Observer 怎样读记录、怎样调用模型，见 [Narrative](../observers/narrative/index.mdx)。

## 请求 [#request]

```http
POST /api/narratives
Content-Type: application/json

{ "from": "2026-10-31T00:00:00+08:00", "to": "2026-11-01T00:00:00+08:00", "timeZone": "Asia/Shanghai" }
```

`from` 包含在内，`to` 不包含，范围不超过 25 小时。每次请求都写新的一批：这段时间原来有当前理解中的几件事时，新的一批替换它们，见 [Narrative · 写入](../observers/narrative/index.mdx#submission)。

## 事件流 [#stream]

响应的 `Content-Type` 是 `text/event-stream`，按 [Server-Sent Events](https://html.spec.whatwg.org/multipage/server-sent-events.html) 的格式发送：

```text
event: episode
data: {"startAt":"2026-10-31T20:16:00+08:00","endAt":"2026-10-31T20:51:00+08:00","title":"把代码迁移到事物与 Observation 模型","summary":"…","sessionIds":["01a191f7-dcfc-7894-863c-5ec8720eb9b2"],"localApplicationIds":[]}

event: saved
data: {"observationIds":["01a19210-…"]}
```

| SSE 事件 | 时机 | 数据 |
| --- | --- | --- |
| `episode` | 每写完一件事 | 这件事，见契约中的 `NarrativeEpisode` |
| `saved` | 全部写完并保存后，流结束 | 保存下来的几件事的 `observationId`，按推送的顺序 |
| `failed` | 写作失败，流结束 | 原因，见契约中的 `NarrativeFailed` |

收到 `failed` 时，已经收到的几件事没有保存。这段时间没有记录时，流里只有一个 `saved`，`observationIds` 为空。请求方中途断开时，叙事 Observer 照样写完并保存，之后用 `GET /observations` 带 `resourceName=episodes` 能读到它们，见 [Reading · 查询观测](./reading.mdx#observations)。

## 错误 [#errors]

| 状态码 | `code` | 含义 |
| --- | --- | --- |
| `409` | `narrative_in_progress` | 另一次写作正在写重叠的范围，等它结束后读取结果 |
| `503` | `narrative_unavailable` | 叙事 Observer 没有配置 API Key |
