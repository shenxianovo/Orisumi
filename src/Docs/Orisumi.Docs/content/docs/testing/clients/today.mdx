## 为什么验证 [#why]

今天页面讲这一天做了哪几件事。几件事由叙事 Observer 边写边推回，失败时不留下半批；应用排行只算前台应用时段，设备和会话不进排行。约定见 [Web · 今天](../../clients/web.mdx#day)。

## 前置条件 [#setup]

后端由路由拦截在内存中模拟，放进同一天的前台应用时段、助手交互和叙事 Observer 的描述。`POST /narratives` 的响应由用例给出。

## 操作与预期结果 [#steps]

| 操作 | 预期结果 |
| --- | --- |
| 一天有前台应用时段和助手交互 | 排行只列本机应用；设备和会话不在排行里 |
| 这一天已经写下几件事 | 不请求写作；写出模型、用到的应用和时长、说过话的会话，以及“另有 N 个没有发言的会话” |
| 这一天还没有写 | 请求写一次，收到 `saved` 后读取保存下来的几件事 |
| 流里收到 `failed` | 撤下已经显示的几件事，写出原因和“重写”，不再自动请求 |
| `503`，`code` 为 `narrative_unavailable` | 写“叙事 Observer 没有配置 API Key”，页面其余部分照常 |
| `409`，`code` 为 `narrative_in_progress` | 显示“正在写”，隔几秒重读，读到后显示 |
| 几件事写下之后又有新的记录 | 写“之后有新的记录”；“重写”请求写一批新的 |
| 点排行里的应用 | 打开它的档案，列出来源、时段的束和所在的一件事 |
