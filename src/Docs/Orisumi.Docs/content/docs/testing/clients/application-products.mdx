## 为什么验证 [#why]

Web 控制台按[归属](../../observers/application-identity/index.mdx#membership)把各设备上的本机应用合并为应用产品。本机应用的线索来自它的描述，产品来自当前理解中的线索归属，判错时用户否定线索归属。约定见 [Web · 应用的合并](../../clients/web.mdx#applications)。

## 前置条件 [#setup]

纯函数用构造的事物和 Observation 运行。页面测试用路由拦截在内存中模拟后端的读取和写入。

## 操作与预期结果 [#steps]

| 操作 | 预期结果 |
| --- | --- |
| 两个本机应用的线索属于同一个产品 | 名称和时长按一个产品显示，时长是两者之和 |
| 本机应用的线索没有线索归属 | 按本机应用单独显示为未归属 |
| 产品没有线索归属 | 事物页不列出它 |
| 线索归属指向的产品已删除 | 线索未归属 |
| 打开本机应用的档案 | “和它有关的”连到产品，线是推断 |
| 在理解页否定一条线索归属 | 写下用户本人的 `deny` 复核；这一行写“已否定”，本机应用回到未归属 |
| 撤回这份否定 | 删除这份 Review，这一行回到“确认”和“否定” |

## 测试实现 [#implementation]

- 按产品合并、时长相加、彼此之间不算切换：`src/lib/day.test.ts` 的 `groupThings`。
- 线索匹配和产品的线索：`src/lib/applications.test.ts` 的“归属”。
- 事物页的应用、档案里的产品、否定和撤回：`tests/e2e/applications.spec.ts`，后端由路由拦截在内存中模拟。

这些是 Vitest 和 Playwright 的测试，结果不进入 TUnit 报告。
