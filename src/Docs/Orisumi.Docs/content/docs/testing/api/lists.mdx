## 为什么验证 [#why]

查询按事实时间排序，游标绑定查询条件。约定见 [观测查询](../../api/reading.mdx#observations)。

## 前置条件 [#setup]

HTTP 用例经真实 API 和独立的 PostgreSQL 数据库运行。Runtime 使用临时数据目录；Observer 的读数、日志和模型回答由测试控制。实际运行的补充证据单独说明，见 [测试分工](../index.mdx#kinds)。

## 操作与预期结果 [#steps]

| 操作 | 预期结果 |
| --- | --- |
| 用 observerId、resourceName 和 formation 筛选 | 只返回对应的 Observation |
| 用 speakerId 筛选 | 只返回这个事物说的；`speakerId` 为 `null` 的按 `observerId` 比较 |
| 用 excludeSpeakerType=models 筛选 | 模型说的话不返回，用户的话和 `speakerId` 为 `null` 的返回 |
| 用 thingId 和 role 筛选 | 只返回以这个角色引用它的 Observation |
| 不带时间范围，分别按 asc、desc 查询 | 按已知边界排序，相同时间按 observationId 升序；两个边界都未知的始终最后 |
| 给出 from 和 to | 只返回与范围重叠的观测；两者必须成对 |
| 用 limit=1 沿 next 翻页 | 各页与完整结果一致，不重不漏 |
| 把游标用于另一组条件或另一种查询 | 400 |
| GET /things 和 POST /things/read | 名字取默认视图中的 Name，用户写的优先；批量结果保留顺序、重复和未找到状态 |

## 测试实现 [#implementation]

方法位于 `tests/Orisumi.Integration.Tests/`：

- 筛选、两种排序、未知时间和游标绑定：`WriteApiTests.ObservationPaginationBindsFiltersAndKeepsUnknownTimesLast`。
- 目标删除后投影和查询：`ProjectionTests.RebuildPreservesThingsReviewsHistoryAndDeletedTargets`。
- formation：`UnderstandingApiTests.FormationDescriptionsAuthorsAndImmutableContentFollowTheContract`。
- 事物列表、批量读取和名字：`UnderstandingApiTests.ThingNamesPreferPeopleThenLatestAndDeletionRetainsReferences`。
- 分页：`SdkTests.FixtureWritesAndReadsThroughHttpAndScriptReimportIsUnchanged`。

未覆盖：`speakerId`、`excludeSpeakerType`、`thingId` 和 `role` 的筛选，由实现任务补上测试；翻页期间新增、修改或删除数据；本次没有重新覆盖所有半开区间边界组合。
