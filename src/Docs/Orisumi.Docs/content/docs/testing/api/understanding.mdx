## 为什么验证 [#why]

默认视图是所有读取方看到的结果，规则的顺序和组合都会影响它。原有 Observation 和输入证据保留。依据见 [UNDERSTANDING-4](../../core/rules/understanding.mdx#understanding-4) 和 [Review](../../core/model/review.mdx)。

## 前置条件 [#setup]

通过真实 API 和独立 PostgreSQL 数据库运行；模型回答由测试替身提供。实际运行的补充证据单独说明。

## 操作与预期结果 [#steps]

| 操作 | 预期结果 |
| --- | --- |
| 模型写判断，用户写事实时间未知的 deny | current 不含旧判断，all 仍含 |
| 用户只否定一段 | current 仍含旧判断，带 `deniedRanges` |
| Review 的时段完全覆盖判断 | current 不含它 |
| 类型声明了 `claimFields`，否定一条判断，新一代写出同一命题 | 新的一份也隐藏，跨代生效 |
| 类型没有声明 `claimFields`，否定一条判断，新一代写出相同内容 | 新的一份可见 |
| 否定一个命题后，用户用 `stated` 再说同一命题 | 新的一份可见，不用先撤回 |
| 模型用 `replaces` 替换一条 `stated` 的陈述 | 用户的陈述留在默认视图中 |
| 范围否定：事物加时段，时段内已有 Observation | 引用这个事物、事实时间被完全覆盖的隐藏；部分重叠的带 `deniedRanges` |
| 范围否定之后，迟到一条落在这个时段内的 Observation | 同样隐藏 |
| 范围否定带 `schemaIds` | 只作用于这些类型 |
| 范围否定的事物有成立的 Same-As | 另一个事物的 Observation 同样在范围内 |
| Review 的 `targetId` 和 `scope` 都有值，或都为空 | 按 REVIEW-2 拒绝 |
| 否定一份 Review | 这份 Review 不再生效，它否定的陈述恢复 |
| 否定对撤回的撤回 | 原来的否定再次生效 |
| 用户确认过旧判断，模型用 `replaces` 替换它 | current 同时包含两条 |
| 替换者被否定 | 被替换的不恢复 |
| 来源、模型和用户为同一事物命名 | 优先用户 Name；否定它后取保存时间最晚的 Name |
| 声明 `stateFields` 的类型有两条同一状态的陈述 | current 取一条：`stated` 优先，其次保存时间最晚；all 返回两条 |
| 没有声明 `stateFields` 的类型 | current 全部返回 |
| 按时间范围查询状态 | 在这段时间的陈述中取一条 |
| 陈述的输入被否定 | 这条陈述带 `basisDenied`，仍然显示；引用方查询能找到 deny；沿 InputSet 能读到被否定的 Observation |
| 用户纠正现读的回答，写一条 `stated` 的 Observation | 下一次模型读取时读到 |

## 测试实现 [#implementation]

方法位于 `tests/Orisumi.Integration.Tests/UnderstandingApiTests.cs`：

- `ReviewsDetermineCurrentUnderstanding`：整条否定、部分否定、确认后替换。
- `ThingNamesPreferPeopleThenLatestAndDeletionRetainsReferences`：三个作者的名字、用户优先和否定后的选择。
- `DeniedInputRemainsTraceableThroughInputSetAndReferrers`：输入、InputSet 和 Review 的追溯。

未覆盖：`claimFields` 跨代、范围否定、撤回、`stateFields`、`deniedRanges` 和 `basisDenied`，由实现任务补上测试。
