export const caseId = 'api-schema-fields';

## 为什么验证 [#why]

字段说明随 SchemaRevision 保存，写入方和读取方才能解释字段。每个字段、对象成员和数组元素都要有说明，见 [SCHEMA-10](../../core/model/schema.mdx#schema-10)。请求结构错误和规则错误影响的范围不同，见 [API · 校验阶段](../../api/writing.mdx#validation)。

## 前置条件 [#setup]

通过 `WebApplicationFactory` 启动 API，连接独立的测试数据库，见 [Database](../database.mdx)。每个场景在 schemas 中声明两个 Schema：第一个有合法声明，第二个按表中条件构造。合法声明含普通字段、可空字段、对象成员和对象数组，数组元素也写非空 `description`。

## 操作与预期结果 [#steps]

| 操作 | 预期结果 |
| --- | --- |
| 写入合法声明，再读取 SchemaRevision | `200`；各层的 description 原样读回，包括引用角色、取值解释和单位 |
| 第二个 Schema 的字段、对象成员或数组元素缺少 description，分别检查这三个位置 | `400`，rule 为 SCHEMA-10；schemas 整体失败，两个声明都不保存 |
| 第二个 Schema 的说明是空字符串或全为空白，分别检查各层位置 | 同上；字段的 nullable 为 true 也不允许省略说明 |
| 第二个 Schema 的字段说明是 null、数字、布尔值、对象或数组 | 请求结构错误，`400`，不带 index；两条修订都未保存 |
| 只修改字段说明的措辞，形成同一 Schema 的新修订 | 新旧修订分别读回自己的说明；旧的 Observation 仍引用原来的修订，见 [SCHEMA-15](../../core/model/schema.mdx#schema-15)、[SCHEMA-2](../../core/model/schema.mdx#schema-2) |
| 声明 `thingTypes` 带 `fields` | 请求结构错误，`400` |
| 再次声明事物类型，说明不同 | 保存最后一次的内容，见 [SCHEMA-17](../../core/model/schema.mdx#schema-17) |
| 目标是事物的 reference 缺少 role，或 role 不是 `about`、`part`、`mention` | 按 SCHEMA-19 拒绝 |
| `stateFields` 或 `claimFields` 列出没有声明的字段 | 按 SCHEMA-20、SCHEMA-21 拒绝 |
| `searchable` 声明在非字符串字段上 | 按 SCHEMA-22 拒绝 |
| 一个 Observer 的资源名和已有的事物类型相同 | 按 SCHEMA-5 拒绝 |
| reference 缺少 target；顶层字段命名为 id | 分别按 SCHEMA-9、SCHEMA-7 拒绝 |
| 不声明内置类型；一个 Observer 声明内置类型的其他修订 | 内置的修订可直接写；这个 Observer 的声明优先，其他 Observer 仍使用内置的修订 |

## 测试实现 [#implementation]

以下方法位于 `tests/Orisumi.Integration.Tests/SchemaDescriptionTests.cs`：

- `DescriptionsRoundTripAndChangesPreserveHistory`：合法声明各层的 description 原样读回；只改措辞形成新修订后，旧修订读回原来的说明，新的修订读到新说明。
- `DescriptionErrorsPreserveStructuralAndPerVersionBoundaries`：六组参数，每组改一个位置。字段缺少说明、对象成员的说明为空字符串、数组元素的说明全为空白时，返回 `SCHEMA-10`，整次请求回滚；这个对象成员的 nullable 为 true。字段说明为数字、对象成员说明为 `null`、数组元素说明为对象时，是请求结构错误，不带 `index`，第一条修订未保存。

- `KindAndReferenceDeclarationsRespectSchemaRules`：target 缺失和顶层 id。
- `BuiltInTypesNeedNoDeclarationAndAnObserversOwnDeclarationTakesPrecedence`：内置类型默认可用及声明优先级。

字段后缀由写入方负责，都用 Id/Ids；Observer 声明与读回字段由相应 Observer Case 检查。

未覆盖：

- `thingTypes`、`role`、`stateFields`、`claimFields`、`searchable` 的声明，由实现任务补上测试。
- 上面六组以外的位置与错误组合，例如对象成员缺少说明、说明为布尔值或数组。
- 不同 Observer 同时使用新旧 Schema 的 .NET 自动化组合；Python 实际验证见 [SDK Languages](../hosting/sdk-languages.mdx)。

空 inputs 不形成 InputSet；重复成员的拒绝和保存点回滚见 [Writes](./writes.mdx)。
