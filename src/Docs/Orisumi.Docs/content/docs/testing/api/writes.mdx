## 为什么验证 [#why]

后端根据完整内容认出对象并保存新的说法，每次写入独立保存。契约见 [Writing](../../api/writing.mdx)。

## 前置条件 [#setup]

HTTP 用例经真实 API 和独立的 PostgreSQL 数据库运行。Runtime 使用临时数据目录；Observer 的读数、日志和模型回答由测试控制。实际运行的补充证据单独说明，见 [测试分工](../index.mdx#kinds)。

## 操作与预期结果 [#steps]

| 操作 | 预期结果 |
| --- | --- |
| 不带 `key`，两次写入相同的温度 | 形成两份 Observation |
| 同一 `key` 连续写相同内容、不同内容，再回到最初的内容 | 相同内容什么都不发生；两次变化各保存一份，一共三份 |
| 带 `time` 写入；再重复；再改时间 | 重复时什么都不发生；时间变化时保存新的一份 |
| 省略 `time` | Observation 仍保存，事实时间边界未知 |
| 缺少 formation 或使用未知值 | 缺少时请求返回 400；未知值按 OBSERVATION-11 拒绝这次写入 |
| 写 description 后写 Observation | 描述是 `observer-descriptions` 类型的 Observation，`observerDescriptionId` 为 `null`，之后的 Observation 引用它 |
| 描述变化后再写 Observation | 新的描述替换旧的，已有的 Observation 继续引用旧的，新写的引用新的 |
| 另一个 Observer 写同一依据，内容相同 | 什么都不发生 |
| 另一个 Observer 写同一依据，内容不同 | 保存新的一份，`replaces` 指向这个依据最新的一条 |
| 同一依据写入不同内容 | 结果的 `replaced` 列出被替换的 `observationId`；内容相同时为空数组 |
| 写入带 `speakerId` | 读回是这个事物；用识别依据提到时事物被创建 |
| 省略 `speakerId` | 读回 `speakerId` 为 `null` |
| 一次写入违反规则，后面的写入有效 | 只回滚失败的写入，其内容、识别依据和 InputSet 都不留下 |
| 写入字段形状不符合 Schema 的内容 | 这次写入按 SCHEMA-2 被拒绝，同一请求的其他写入保存 |
| 识别依据超过 2048 字节 | 这次写入被拒绝，同一请求的其他写入保存 |
| 使用本 Observer 未声明的类型 | 这次写入被拒绝 |
| 重发已处理的序号或更小的序号 | 返回 duplicate，不重新保存 |
| 请求超过 10 MiB | 返回 413 |

## 测试实现 [#implementation]

方法位于 `tests/Orisumi.Integration.Tests/`：

- formation 和描述：`UnderstandingApiTests.FormationDescriptionsAuthorsAndImmutableContentFollowTheContract`。
- 引用变化：`WriteApiTests.ReferencesResolveInOrderAndCompareSavedIds`。
- 识别、替换、时间和序号：`WriteApiTests.RecognitionVersionsObservationsAndSequenceFollowTheWriteContract`。
- 形状错误和过长的识别依据：`WriteApiTests.WrongShapeOnAnExistingEntityAndLongKeysRejectOnlyThatWrite`。
- 逐次回滚：`WriteApiTests.RejectionRollsBackOnlyItsWriteIncludingKeysInputsAndContent`。
- 输入集合复用与结构错误边界：`WriteApiTests.InputsShareOneSetAndContentAndSchemaFailuresHaveDifferentBoundaries`。
- 并发识别和 HTTP 大小边界：`WriteApiTests.ConcurrentRecognitionPreservesOneChainAndHttpBoundariesRemainExplicit`。
