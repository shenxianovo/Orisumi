这一页是开发工具的语言。产品的术语在建模阶段另行整理。

## 三层

改动按时机经过三层，每层是一个 `orisumi` 命令。

**整理**：
改完文件后顺手做的第一层：格式化改过的代码，lint 改过的文件。命令是 `orisumi tidy`。
_避免_：format 阶段、预检

**验证**：
决定改动能否交付的第二层，全部由门禁组成，包括整理是否已经做完。命令是 `orisumi verify`。
_避免_：完整检查、CI 检查

**评审**：
改完之后给评审者看的第三层，全部由报告组成，内容是相对基点的变化。命令是 `orisumi review`。
_避免_：质量检查、模型检查

**基点**：
评审用来比较的那次提交。
_避免_：基线、对照版本

## 检查

**检查**：
`orisumi` 对改动或整个仓库做的一项验证或扫描。每项检查是门禁或报告之一。
_避免_：校验、步骤

**门禁**：
发现问题就失败的检查。门禁失败的改动不能交付。
_避免_：阻断项、硬失败

**报告**：
给出发现供评审参考的检查，只在没有完成时失败。
_避免_：警告、软失败

**例外**：
lint 门禁中声明为不需要修改的一条发现，由所属项目写明理由。评审复核这个理由是否仍然成立。
_避免_：噪音、忽略项、suppression

**噪音**：
评审中看起来是新增、其实只是改名或移动的发现，由模型在每次评审时判断。
_避免_：误报、例外

## 题

**题**：
交给决策模型的一个问题，带题型和通过条件。写作规则、例外的理由和噪音判断也是题。
_避免_：提示词、prompt

**判断题**：
问一个陈述是否成立的题。模型给出成立的概率，这个概率表示模型的把握。
_避免_：是非题、predicate

**选择题**：
从一组固定选项里选一个的题。模型给出每个选项的概率。
_避免_：分类题、choice

**通过条件**：
题自己声明的阈值，决定模型的回答算通过还是失败。
_避免_：门槛、cutoff
