一份观测依据已保存的数据形成时，用 [InputSet](../model/input-set.mdx) 记下实际用到的输入，之后才能沿着它追溯。一份观测的问题分别在这些位置回答：

| 问题 | 回答的位置 |
| --- | --- |
| 谁负责 | Observation 的 `observerId` 和 `observerDescriptionId` |
| 陈述了什么 | Observation 的 `content` |
| 确认或否定了什么 | [Review](../model/review.mdx) 的 `targetId` 或 `scope` |
| 用了哪些已保存的 Observation | `inputSetId` 指向的 InputSet |

## 输入 [#inputs]

### EVIDENCE-1 列出输入 [#evidence-1]

执行方：写入方

依据已保存的数据形成观测时，必须用输入集列出实际用到的 Observation。聚合、推断，以及用户读完日志后的陈述，都需要输入集；直接采集和亲身陈述没有输入，`inputSetId` 为 `null`。Observer 如实声明是否依据了已保存的数据。

### EVIDENCE-2 读了就列 [#evidence-2]

执行方：写入方

值进入了处理的 Observation，都列为成员。例如 A 引用 B：处理只读了 A，成员只有 A；处理也读了 B，A 和 B 都是成员。

### EVIDENCE-3 不事后推算 [#evidence-3]

执行方：写入方、后端

输入由 Observer 在处理时确定，不得事后由查询结果、事实时间重叠或 `recordedAt` 推算。理由见 [ADR · Observer 与输入集](../../adr/observers-and-evidence.mdx#rationale)。

### EVIDENCE-4 输入只是输入 [#evidence-4]

执行方：读取方

输入集只表示这些 Observation 提供给了这次处理。观测确认或否定了什么，写在 Review 中，见 [OBSERVER-7](../model/observer.mdx#observer-7)。

### EVIDENCE-5 只列直接输入 [#evidence-5]

执行方：写入方

输入集只列这次处理的直接输入。处理用到了上一层的观测 J，又没有重新读取 J 的输入时，只列出 J；J 的输入由 J 自己的输入集列出。

### EVIDENCE-6 实际的组合 [#evidence-6]

执行方：写入方

输入集记下实际用到的 Observation 组合。处理过程中读到了同一件事的新旧两份说法时，两份都列出。需要复现处理时，模型和程序版本由 Observer 的描述表达，提示词、参数或发送的文本由 Observation 的业务字段表达。

## 追溯 [#tracing]

### EVIDENCE-7 逐层追溯 [#evidence-7]

执行方：读取方

读取方沿输入集逐层追溯：成员本身也有输入集时，继续向下。引用都指向已保存的 Observation，所以追溯不会成环。成员被删除时，见 [HISTORY-8](./history.mdx#history-8)。

### EVIDENCE-8 依据不变 [#evidence-8]

定义

Observation 不可变，所以已有的依据不变。是否重新处理，由 Observer 或业务规则决定，见 [UNDERSTANDING-8](./understanding.mdx#understanding-8)。

## 一次工作 [#runs]

Agent 自己决定读什么，它用了哪些数据不能靠它事后列出。[一次工作](../../api/reading.mdx#runs)由系统记下读取：Agent 开始一次工作，读取时带上它，写入时不用再列输入。

### EVIDENCE-9 一次工作的输入 [#evidence-9]

执行方：后端

写入带 `runId` 时，后端用这次工作的读取记录形成 InputSet，写入方不用再列。读取记录是到这次写入为止，带这个 `runId` 的读取返回过的全部 Observation。还没有读过任何 Observation 时，`inputSetId` 为 `null`。程序化的 Observer 继续自己列输入。
