---
title: "Identity"
description: "什么是同一个事物，何时再说一句，何时新写一份 Observation"
---

写入前要回答两个问题：这里提到的对象是哪个事物？这份陈述和已有的哪一条是同一句话的新说法？下表是常见情况的答案。

| 情况 | 事物 | Observation |
| --- | --- | --- |
| 提到一个新的来源对象 | 新建 | 不涉及 |
| 提到已有的来源对象 | 沿用 | 不涉及 |
| 重新读到来源，内容没有变化 | 沿用 | 什么都不发生 |
| 来源中的对象变了 | 沿用 | 新的一份，替换旧的 |
| 修解析器后重读，或者模型重判 | 沿用 | 新的一份，替换旧的 |
| 新的独立观测 | 沿用或新建 | 新的一份 |
| 另一个 Observer 确认、否定或陈述 | 沿用 | 新的一份 |
| 用另一种方法独立解释同一份证据 | 沿用 | 新的一份 |

例如采集器把一条工具结果误记成用户发言，修复解析器后重读日志，这是纠正：新的交互替换旧的，旧的一份仍可追溯。用另一个模型重新评价当天的活动，这是独立解释：新的一份和旧的并存。

## 共同规则 [#common]

### IDENTITY-1 业务规则定身份 [#identity-1]

执行方：写入方、后端

业务规则决定什么算同一个事物，什么算同一句话的新说法。写入方认出已有的事物时沿用它，否则新建。业务规则可以用已持有的引用、来源的标识或业务上的匹配认出事物。后端按写入方指出的事物保存。

### IDENTITY-2 身份与 Observer 无关 [#identity-2]

执行方：写入方

事物的身份由业务规则决定，与提到它的 Observer、运行它的托管方和编写它的语言无关。例如同一台 Mac 上的两个程序实例提到 QQ 这个本机应用，得到同一个事物，各自形成观测。

## Observation [#observation]

### IDENTITY-3 独立观测，新写一份 [#identity-3]

执行方：写入方

新的独立观测是一份新的 Observation，没有识别依据，或者用它自己的依据。另一个 Observer 的确认、否定或陈述，以及用另一种方法对同一份证据作出的独立解释，都是新的一份，见 [UNDERSTANDING-2](./understanding.mdx#understanding-2)。

### IDENTITY-5 Observation 的粒度 [#identity-5]

执行方：写入方

Observation 的粒度由业务规则决定：来源中的内容变化时，是替换原来的一份，还是新写一份。来源的性质决定这一点：

| 来源 | Observation | 变化 |
| --- | --- | --- |
| 保留历史，例如日志 | 一条来源数据一份，用这一条的标识作识别依据 | 新的来源数据是新的一份；同一条来源数据重读内容不同时，替换原来的一份 |
| 只给当前状态，例如日历事件 | 一个对象一个识别依据，每次写入完整内容 | 新的一份替换旧的，事实时间写在新的一份上 |

例如 Codex 的索引文件追加每次改名，所以每次改名是一份 Name，会话本身是事物。日历事件改时间时，来源只给出新的时间，所以新的一份替换原来的一份。

对象本身是事物。一个对象的内容只能读到一部分，或者会变的部分来自不同的来源时，各写成单独的 Observation，它们引用同一个事物。补全不得把几次独立的读数合并为同一份 Observation。

## 识别 [#recognition]

### IDENTITY-6 不补造身份 [#identity-6]

执行方：写入方

来源缺少稳定标识时，写入方按已有证据识别事物，不得补造来源身份；证据不足以确定的字段保持未知。作用范围不同的同名标识属于不同的事物，例如两台设备上同名的应用。作用范围由业务规则决定，例如设备、账号、浏览器 profile 或一个来源会话；托管方和程序实例不是来源对象的作用范围。

Observer 为自己形成的理解新建事物时，用自己范围内的依据，见 [THING-4](../model/thing.mdx#thing-4)。

### IDENTITY-7 识别依据 [#identity-7]

执行方：后端

识别依据是认出事物或 Observation 所用的一组值：业务类型、作用范围、标识方案和标识的值。一份事物的识别依据最多对应一个事物，一个事物可以有多份，也可以没有。一份 Observation 的识别依据对应一条替换链，新的一份接在最新的一条之后，见 [OBSERVATION-19](../model/observation.mdx#observation-19)。身份始终是 `thingId` 和 `observationId`。识别依据删除时留下墓碑，见 [HISTORY-11](./history.mdx#history-11)。

### IDENTITY-8 各说各的 [#identity-8]

执行方：写入方

多个 Observer 要对同一个事物各写一份内容时，把 Observer 的 `thingId` 放进识别依据的 `scope`。例如两个 Observer 都写同一类判断，重判时各自替换自己的一份，互不影响。识别依据是全局的，所以没有放进 `scope` 时，写入同一份依据的 Observer 共用一条替换链，见 [OBSERVATION-19](../model/observation.mdx#observation-19)。
