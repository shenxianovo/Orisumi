来源只能告诉 Orisumi 发生了什么。“QQ 号 123 是本人”“这两个设备是同一台机器”这类理解，采集时拿不到，靠人录入也不现实。所以这些理解由模型读已保存的数据形成，用户只在发现错误时否定。

这一页写理解怎样形成，以及默认视图怎样算出系统目前采用的陈述。否定、替换和同一的结构见 [Review](../model/review.mdx)、[Observation · 替换](../model/observation.mdx#replacement) 和 [Same-As](../model/same-as.mdx)，公共类型见 [Common Types](../model/common-types.mdx)。理由见 [ADR · 模型形成的理解](../../adr/understanding.mdx)。

| 层 | 例子 | 谁产生 | 保存方式 |
| --- | --- | --- | --- |
| 证据 | QQ 号 123 发了这句话 | Observer | 永久保存，尽量保留原样 |
| 世界知识 | QQ 是腾讯的软件 | 模型自带 | 读取时现取，不保存 |
| 私有理解 | 123 是本人，下午在写 Web 控制台 | 模型推断，用户纠正 | 保存为 Observation，可以出错和重做 |

## 形成 [#forming]

### UNDERSTANDING-1 采集时不判断关系 [#understanding-1]

执行方：写入方

采集时只记下来源给出的内容，提到来源中的对象。来源没有直接给出的关系留给理解。例如 QQ 的采集只记发送者是 QQ 号 123，“123 是本人”由模型另外陈述。

### UNDERSTANDING-2 判断互不覆盖 [#understanding-2]

执行方：写入方

每次判断形成新的 Observation，新旧判断都保留，所以能看到认识怎样变化。模型变强后可以重读过去的数据，再形成一批判断，用 `replaces` 替换上一轮，或者用 [Adoption](../model/adoption.mdx) 切换到新的一代。

### UNDERSTANDING-3 世界知识不保存 [#understanding-3]

执行方：写入方

世界知识在读取时由模型现取，不保存。私有理解保存为 Observation，模型写下的叙事也是，例如“下午在写 Web 控制台”这件事，见 [Episode](../../observers/narrative/episode.mdx)。软件要用来计算的结果同样保存为 Observation。

## 默认视图 [#view]

后端用一份规则算出默认视图，Web、Mac、Observer 和 Agent 共用它。规则理解否定、替换和同一，其他业务类型的含义留给读取方。隐含的矛盾留给模型读取时处理，算图不参与：例如两条陈述分别说 14:00 在北京和 14:30 在上海，后端都返回。

### UNDERSTANDING-4 当前理解 [#understanding-4]

执行方：后端

当前理解是默认视图中的陈述。读取 Observation 默认 `view=current`，`view=all` 返回全部，见 [API · 视图](../../api/reading.mdx#view)。规则按顺序：

1. 被否定的隐藏。否定来自指向它的 Review、同一命题的 Review（[REVIEW-4](../model/review.mdx#review-4)），或者时段完全覆盖它的范围否定（[REVIEW-5](../model/review.mdx#review-5)）。部分否定时保留这一条，返回 `deniedRanges`，由读取方裁剪。被否定的 Review 不再生效（[REVIEW-6](../model/review.mdx#review-6)）。
2. 被替换的隐藏，替换者被否定也不恢复。形成方式为 `stated` 的陈述和[用户确认过的判断](../model/review.mdx#review-7)不受模型的替换影响，模型的替换指替换者的形成方式是 `inferred` 或 `extracted`。
3. 模型判断按采用的那一代过滤，见 [ADOPTION-1](../model/adoption.mdx#adoption-1)。
4. 同一状态取一条：用户写的优先，也就是形成方式为 `stated` 的，其次保存时间最晚的，见 [SCHEMA-20](../model/schema.mdx#schema-20)。这一步在查询条件筛选之后执行，所以按时间范围查询时，得到的是这段时间里的状态。

认识的变化是这些陈述和它们的复核按保存时间排列的结果，用 `view=all` 读取。

### UNDERSTANDING-7 记得否定 [#understanding-7]

执行方：写入方

形成判断前，Observer 读取相关的否定并列入输入。类型固定的判断，Observer 在写入前跳过用户否定过的结论。类型声明了命题键时，模型又写出被否定的结论，后端照常保存，它在默认视图中隐藏，见 [REVIEW-4](../model/review.mdx#review-4)；其他类型由用户再否定一次。

### UNDERSTANDING-8 依据被否定 [#understanding-8]

执行方：后端

一条陈述的 InputSet 中有被否定的陈述时，后端在结果中标记 `basisDenied`，这条陈述仍然显示，读取方能找到被否定的那一条。是否重新处理由下一轮的 Observer 决定，见 [EVIDENCE-8](./evidence.mdx#evidence-8)。

## 现读 [#reading]

### UNDERSTANDING-10 现读的回答 [#understanding-10]

执行方：写入方

模型回答问题时现读原文，这次回答不保存。用户纠正时写一条 `stated` 的 Observation，下一次模型读取时能读到。
