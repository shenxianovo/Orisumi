---
title: "References"
description: "引用的目标、位置和保存方式，以及关系都是引用"
---

引用是一份 Observation 指向别的数据的方式。例如前台时段的 `localApplicationId` 引用 VS Code 这个事物，推断的 InputSet 引用下午的前台时段。引用的目标只有两种：事物和 Observation。

## 目标 [#targets]

### REFERENCE-1 引用的目标 [#reference-1]

定义

引用的值是目标的 id：事物是 `thingId`，Observation 是 `observationId`。业务字段的 `reference` 用 `target` 声明目标种类，见 [SCHEMA-9](../model/schema.mdx#schema-9)。

例如交互引用设备这个事物，设备改名不影响这份交互。推断的输入引用下午的一份前台时段，这段时段后来被替换，追溯时读到的仍是当时那一份。

### REFERENCE-2 引用的位置 [#reference-2]

定义

一份 Observation 的引用，是 Core 或它的 SchemaRevision 声明为引用的全部位置：

- Observation 的 `schemaRevisionId`；
- Core 声明的引用成员：`observerId`、`speakerId`、`observerDescriptionId`、`inputSetId` 和 `replaces`；
- 业务字段中 `type` 为 `reference` 的值，包括对象成员和数组元素。

枚举引用时，保留每个引用所在的位置：SchemaRevision、Observer、替换和输入是不同的关系。

### REFERENCE-3 只引用存在的目标 [#reference-3]

执行方：后端

新的 Observation 引用的目标 Observation 都必须已保存且未被删除。写入按顺序逐个保存，所以 Observation 不能引用自己，两份新的 Observation 也不能互相引用。引用的事物不存在时，后端按 [THING-2](../model/thing.mdx#thing-2) 创建它；用识别依据以 `mention` 提到已删除的事物时，按 [HISTORY-11](./history.mdx#history-11) 保存；其余情况下，已删除的 `thingId` 不能再被引用。

目标保存后又被删除时，已有的引用保留，见 [HISTORY-8](./history.mdx#history-8)。

### REFERENCE-4 引用存在引用方 [#reference-4]

定义

引用只保存在引用方的 Observation 中。要找出引用某个事物或 Observation 的数据，就查询引用方。

## 关系 [#relations]

### REFERENCE-5 关系都是引用 [#reference-5]

定义

事物之间的关系都表达为 Observation 中的引用，关系的时间、责任和形成方式就是这份 Observation 的时间、Observer 和形成方式。例如交互的 `deviceId` 说明它发生在哪台设备上，[Relation](../model/common-types.mdx#relation) 说明 QQ 号 123 是本人，两者是同一种引用。
