事物是被提到和被观测的对象，例如这台 Mac、一个 Codex 会话、QQ 号 123、用户本人。事物只有身份，关于它的一切都是 [Observation](./observation.mdx)：设备叫什么、会话的标题、QQ 号是谁的，都是引用它的陈述。

用户操作的就是事物：打开一个人、一台电脑或一个应用，读到的是它现在的样子、它的关系和发生过的事，见 [API · 对象视图](../../api/reading.mdx#thing-view)。

<ModelRelations node="Thing" />

- **身份**：`thingId`，来源对象靠[识别依据](../rules/identity.mdx#identity-7)认出
- **类型**：[事物类型](./schema.mdx#thing-types)
- **决策**：[ADR · 事物与观测](../../adr/things-and-observations.mdx)

## 成员 [#members]

| 成员 | 类型 | 含义 |
| --- | --- | --- |
| `thingId` | UUIDv7 | 事物的身份 |
| `schemaId` | SchemaId | 事物的类型 |
| `keys` | 识别依据的数组 | 认出这个事物所用的依据，可以为空 |

## 示例 [#example]

一条 QQ 消息提到发送者：

```json
{
  "thingId": "019e1bbb-ec00-7000-8000-0000000000d1",
  "schemaId": "019e1bbb-ec00-7000-8000-000000000011",
  "keys": [
    { "scope": null, "scheme": "qq.uin", "value": "123" }
  ]
}
```

## 规则 [#rules]

### THING-1 只有身份 [#thing-1]

定义

事物没有内容，也没有事实时间。它的类型和识别依据是它保存的全部信息。

### THING-2 提到时创建 [#thing-2]

执行方：后端

写入用识别依据提到一个事物，而它还不存在时，后端创建它。提到事物不需要先写入，也不需要负责的 Observer，所以多个 Observer 可以提到同一个事物。

### THING-3 内容写成 Observation [#thing-3]

执行方：写入方

关于事物的内容都写成引用它的 Observation。名字用公共的 [Name](./common-types.mdx#name)，其他内容由业务类型定义，例如设备的平台、本机应用的标识线索。

### THING-4 Observer 自己的事物 [#thing-4]

执行方：写入方

来源没有给出标识时，Observer 可以用自己范围内的依据新建事物：`scope` 是这个 Observer 的 `thingId`，`value` 由它决定。例如模型认出一个人，用 `zhangsan-classmate` 作依据，同一批写入能引用它，重跑不会重复。这样的依据只在这个 Observer 内有意义，见 [IDENTITY-6](../rules/identity.mdx#identity-6)。

产品、人这类由判断形成的对象用这种依据认出，跨代保持同一个 `thingId`。新一代模型写入前先读已有的对象并沿用依据。归属是判断，可以变，对象留着。“一件事”按内容就能找到，写成 [Episode](../../observers/narrative/episode.mdx)，它不是事物。

### THING-5 事物不合并 [#thing-5]

执行方：写入方

两个事物其实是同一个时，写一条 [Same-As](./same-as.mdx)，两个 `thingId` 和已有的引用都不变。例如两个设备事物是重装系统前后的同一台机器，或者两个人其实是同一个人。这个判断错了，否定这条 Same-As 即可。

### THING-6 thingId 不变 [#thing-6]

执行方：后端

`thingId` 是 UUIDv7，生成后不再改变，事物删除后仍然占用。新事物的 `thingId` 由后端生成，直接运行的程序实例也一样。受托管的程序实例由托管方预先分配，见 [HISTORY-7](../rules/history.mdx#history-7)。什么算同一个事物由业务规则决定，见 [Identity](../rules/identity.mdx)。

### THING-7 类型不变 [#thing-7]

执行方：后端

事物的 `schemaId` 在创建后不再改变。
