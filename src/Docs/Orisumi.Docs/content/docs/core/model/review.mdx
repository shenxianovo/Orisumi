---
title: "Review"
description: "对一条陈述或一个范围的确认和否定"
---

Review 是一份 Observation，表示确认或否定，中文叫复核。[Walkthrough](../../start/walkthrough.mdx) 那一天，用户发现 15:00 到 16:00 其实在开视频会议，就写一份 Review，指向模型的推断，事实时间是 15:00 到 16:00，说明写“在开会”。被否定的推断保持原样，默认视图按这份 Review 算出结果。

Review 也能指向一个范围。例如“这两小时不是我在用这台电脑”否定的是这台电脑在这两小时内的全部数据，包括之后才迟到的数据。

- **类型**：内建类型，后端理解它的语义，见 [Overview · 内建语义](../index.mdx#semantics)
- **决策**：[ADR · 不可变的 Observation](../../adr/immutable-observations.mdx)、[ADR · 模型形成的理解](../../adr/understanding.mdx)

## 类型 [#type]

| 项目 | 值 |
| --- | --- |
| SchemaId | `019e1bbb-ec00-7000-8000-00000000000e` |
| 显示名称 | 复核 |
| 说明 | 表示对一条陈述或一个范围的确认或否定。事实时间是它针对的时段，未知时针对整条。 |
| 资源名 | `reviews` |

| 字段 | 类型 | 必填 | 可空 | description |
| --- | --- | --- | --- | --- |
| `verdict` | `string` | 是 | 否 | `confirm` 确认或 `deny` 否定 |
| `targetId` | `reference`，目标为 Observation | 是 | 是 | 被复核的 Observation |
| `scope` | `object` | 是 | 是 | 被复核的范围 |
| `scope.thingIds` | 事物引用的数组，`role` 为 `mention` | 是 | 否 | 范围涉及的事物，空数组表示不限 |
| `scope.schemaIds` | `string` 的数组，值是 SchemaId | 是 | 否 | 范围涉及的业务类型，空数组表示不限 |
| `text` | `string`，`searchable` | 是 | 是 | 说明，例如“在开视频会议” |

## 示例 [#example]

否定一条推断的后半段：

```json
{
  "verdict": "deny",
  "targetId": "019e1bbb-ec00-7000-8000-000000000301",
  "scope": null,
  "text": "在开视频会议"
}
```

否定这台电脑在两小时内的数据，事实时间是这两小时：

```json
{
  "verdict": "deny",
  "targetId": null,
  "scope": {
    "thingIds": ["0196f3a1-5d0c-7a11-8e2f-1b2c3d4e5f61"],
    "schemaIds": []
  },
  "text": "这两小时是朋友在用"
}
```

## 规则 [#rules]

### REVIEW-1 复核不改原文 [#review-1]

执行方：写入方

确认和否定都写成一份 Review，被复核的陈述保持原样。撤销一条判断是否定它，只有用户要抹掉数据时才删除，见 [History · 删除](../rules/history.mdx#deletion)。

### REVIEW-2 目标或范围 [#review-2]

执行方：后端

`targetId` 和 `scope` 恰好一个有值。`scope` 的 `thingIds` 和 `schemaIds` 至少一个不为空。

### REVIEW-3 针对的时段 [#review-3]

定义

Review 的事实时间是它针对的时段，两个边界都为 `null` 表示整条。时段完全覆盖被否定的 Observation 时，这份 Observation 隐藏；只覆盖一部分时，它保留，后端返回被否定的时段，由读取方裁剪，见 [UNDERSTANDING-4](../rules/understanding.mdx#understanding-4)。

比较时段时，只知道一个边界的 Observation 当作时间点。两个边界都未知的 Observation 只被整条的否定覆盖。

### REVIEW-4 否定落在命题上 [#review-4]

执行方：后端

否定目标 Observation 时，这个类型声明了 [`claimFields`](./schema.mdx#schema-21) 的话，后端按命题键判断，命题键相同的 Observation 都被否定，跨代也一样。所以新一代模型写出同一个结论时，它同样隐藏。保存时间晚于这份 Review、形成方式为 `stated` 的 Observation 不受影响：用户改变说法时直接再说一句，不用先撤回。

类型没有声明 `claimFields` 时，否定只作用于这一条，新模型靠读到这次否定来避免重犯，见 [UNDERSTANDING-7](../rules/understanding.mdx#understanding-7)。

### REVIEW-5 范围否定 [#review-5]

执行方：后端

范围否定在读取时计算，所以对迟到和将来的 Observation 同样生效。一份 Observation 在范围内的条件是：业务类型在 `schemaIds` 中，并且业务字段引用了 `thingIds` 中的事物，角色不限；空数组不限制这一项。比较事物时按成立的 [Same-As](./same-as.mdx) 展开。

### REVIEW-6 撤回 [#review-6]

执行方：后端

否定 Review 本身就是撤回：被否定的 Review 不再生效，它否定的陈述恢复。撤回不用删除。这条规则同样适用于对撤回的撤回。

### REVIEW-7 用户确认的判断 [#review-7]

执行方：后端

用户确认过的判断是有一份生效的 `confirm` Review、这份 Review 的形成方式是 `stated` 的 Observation。模型的替换和 [Adoption](./adoption.mdx) 不影响它，它留在默认视图中。
