## 背景 [#context]

Orisumi 的主要读取方之一是模型，大规模的语义判断成本已经很低，模型读得完用户的全部文字。所以要回答的问题是：模型读什么、写什么、用户怎样纠正，哪些结构值得让后端理解。

这次决定用真实数据做了三项检验：沿 18 个维度遍历候选模型，按规则剪到 384 个组合；用约 27 万条真实数据跑一个原型，再写 30 个反例；用 10 月的 401 个“会话 × 天”片段（约 277 万字）试跑摘要和回答。

检验暴露了几个问题。否定只按 id 隐藏时，新一代模型写出同一个结论，这个结论就复活了。代的指针把用户自己的陈述也隐藏了。否定或删除替换者时，旧内容复活。Web、Mac 和 Observer 各自实现“当前理解”，规则会分叉。

## 决定 [#decision]

- Observation 保存后不可变，只有一个身份。说法变化时再说一句，新的一份用 `replaces` 指向被替换的。
- 同一识别依据内容相同时什么都不发生，内容不同时后端自动填写 `replaces`。修解析器、来源对象变化、模型重判都走这一条路。
- InputSet 是一个值，成员是 `observationId`。
- 否定、替换和同一是 Core 的三种内建语义，后端理解它们，其他类型后端只检查结构。
- 否定落在命题上：类型声明了 `claimFields` 时，后端按类型加这些字段的值判断，同一命题跨代也被隐藏。没有声明的类型，否定只作用于这一条，新模型靠读到这次否定来避免重犯。
- 否定可以指向事物和类型组成的范围，在读取时计算，对迟到和将来的 Observation 同样生效。
- 否定 Review 本身就是撤回。
- 同一是内建类型 Same-As，读取时展开，事实时间是成立的时段，否定它就是拆开。
- 默认视图由后端负责，所有读取方共用一份规则，规则按顺序是否定、替换、代和状态。
- Adoption 说明一种类型的判断采用哪一代，可以只适用于一段时间，旧判断保留。
- 引用事物的字段声明 `role`，类型可以声明 `stateFields`、`claimFields` 和 `searchable`。对象视图、默认视图、删除和搜索都靠这些声明工作，不用认识具体的业务类型。
- 由判断形成的对象也是事物，用 Observer 范围的依据认出，跨代保持同一个 id。
- 负责方和说话人分开：`observerId` 是记录它的一方，`speakerId` 是说这句话的事物。
- 第一版不做预建摘要，模型回答问题时现读原文。周、月、主题摘要都不做，读不动时再加。
- 搜索第一版是子串扫描。
- Agent 用了哪些数据由系统记下：一次工作的读取记录就是 InputSet。

## 理由 [#rationale]

**删除版本。** 一份陈述的“版本”和“再说一句”是同一种东西的两个名字。同一来源改同一属性的情况，在现有数据中占 23 / 271,319，`replaces` 足以表达它，而且能跨 Observer、能一句替换几句。去掉版本这层外壳之后，引用只有两种目标，一个身份就够了，InputSet 也不用再有历史和删除语义。全部 Observation 不可变，类型也不用再声明内容变不变。

**否定指向命题。** 反例检验中，否定只按 id 隐藏时，新一代模型写出同一个结论就会复活。结构化的判断有明确的键，后端能认出“这是同一句话”。自由文字没有这样的键，靠下一次模型读到否定。

**内建语义。** 判定标准先写定，再检验：盲推的两路都得到“稳定 id 的对象加带出处的断言”；原型跑通了 12 项单独的操作，但 `denial` 和 `same-as` 是写在规则里的类型，只靠声明表做不到。承认这三种语义是内建的，比把它们伪装成普通类型更诚实。`same-as` 留在 Relation 的 `predicate` 里时，后端要识别一个字符串的特殊含义，它也没有时段；提成内建类型后，“账号回收后不再是同一个人”也能表达。

**默认视图归后端。** 规则要看每条陈述的复核、替换链、命题键和 Adoption，读取方自己做要逐条反查。规则写在一处，Web、Mac、Observer 和 Agent 读到的就是同一个结果。隐含的矛盾留给模型，算图不参与，因为判断矛盾需要理解内容。

**替换者失效时不恢复。** 新的说法被否定，说明新的错了，不说明旧的对了。恢复旧内容就是一次没有人作出的判断。

**用户的话高于模型。** `stated` 的陈述和用户确认过的判断不受代的影响。否则一次换代会把用户说过的话也隐藏。

**模型的话要能认出来。** 助手的回答被助手会话 Observer 采回后，负责的是这个 Observer，说话的却是模型。分开这两个位置，读取方才能排除模型的话，模型不会把自己说过的话当成证据。

**不做预建摘要。** 10 月试跑中，19 个里程碑在各层的关键词覆盖是片段 19、天 16、周 8、月 7，损失主要发生在天到周。三道题中有两道，用户认为只用原文的回答更接近真实情况；两种读法的 token 接近，只用原文的耗时约两倍。月摘要还写错了一件已解决的事，分层读法在一题上靠下钻纠正，在另一题上没有。“摘要层是必需的”在一个月的规模上不成立。

**子串扫描。** 全部约 27 万条的子串扫描 0.39 秒，10 月的 277 万字约 0.03 秒，第一版不需要分词和向量。

放弃的方案：

- **保留版本，只改写法。** 替换已经覆盖版本能做的一切，两套机制并存，读取方要分别理解。
- **修解析器时原地重算字段，id 不变。** 模型当时读到的文字和修复后的文字不同，追溯对不上。
- **用一个当前代指针管全部判断。** 不能只重做 10 月，也会隐藏用户的陈述。
- **合并事物。** 合并错了拆不开，已有的引用也要改写。
- **同一个来源的不同内容拒绝写入并报告。** 修解析器和来源对象变化都要另走一条路。
- **Agent 的结论自己列依据。** Agent 决定读什么，它列的和实际读的可能不同。
- **先建好周、月、主题摘要，模型读摘要。** 试跑中损失大，还多一层要维护、要否定的产物。

## 代价 [#costs]

- 每次变化都多一份完整的 Observation，存储随变化增长。
- 后端要理解命题键、替换链、范围否定和 Adoption，默认视图的查询比按列筛选复杂。
- 范围否定按读取时计算，每次查询都要算。
- `stateFields`、`claimFields` 和 `role` 由类型的作者声明，声明错了，默认视图和删除都会错。
- 自由文字的否定要靠下一次模型读到，模型可能重犯。
- 现读原文比读摘要慢，上下文也更长。半年以上的规模没有测过，到时读不动再加。
- 字面搜索要靠模型换词。“纠结”在 10 月出现 0 次，这个主题要靠模型想到别的说法。
- 派生文字里的残留要重做，删除只能移除结构上连着的内容。
- 这次检验的规则由助手写，子 Agent 读到过项目规则；默认视图和否定、全量重放还没有在真实规模上测过，“换一个模型只给来源内容”的最小重做也没有做。
