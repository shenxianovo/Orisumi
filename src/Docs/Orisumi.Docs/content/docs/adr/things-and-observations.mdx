## 背景 [#context]

Orisumi 保存的数据来源各异：前台应用、输入事件、浏览历史、健康数据，还有模型的推断和用户的确认、否定。字段各不相同，读取方却要用同一种方式定位数据、遍历关系、按时间查找事实。

用户操作的是对象：一个人、一台电脑、一个应用、一个账号。同一个对象同一时刻可以有多种说法，来源记下的名字、模型判断的名字和用户写的名字可以并存。推断要指向它当时读到的内容，事后不能变样。

实际数据支持把模型收得很小：没有一个内容被第二个 Observer 观测过，9 个引用字段中 8 个指向设备、会话这类对象。粒度规则也一直在把模型推向同一个方向：会话只留身份，产品只留名称，会变的部分都拆成单独的类型。

## 决定 [#decision]

- 用户的数据只有两种：事物和 Observation。
- 事物只有身份，没有内容，第一次被提到时创建，身份是 `thingId`。
- Observation 是一份陈述。谁负责、说了什么、怎么来的、依据什么、事实何时成立，都在这一份中，身份是 `observationId`。
- Observation 保存后不可变，见 [ADR · 不可变的 Observation](./immutable-observations.mdx)。
- 引用的目标只有事物和 Observation，值是对应的 id。
- 事物之间的关系都写成 Observation 中的引用。
- 新的 Observation 只能引用已保存且未被删除的 Observation。
- Schema 定义一种 Observation 类型，每次修改是一条 SchemaRevision，Observation 固定引用它所用的修订。两台设备可以各用各的修订，没有当前修订。
- 事物类型和 Observation 类型分开声明，事物类型只有名称和说明。
- 引用的位置由 Core 或 SchemaRevision 声明，可以出现在顶层字段、对象成员和数组元素中。
- 只有 Observation 保存事实时间。

## 理由 [#rationale]

事物回答“在说谁”，Observation 回答“说了什么”。把它们分开之后，模型的很多规则都不需要了。

事物没有内容，所以没有并发和覆盖的问题，任何 Observer 都能提到同一台设备。这也让采集不需要先写入被引用的对象，读不到后端也能写。

Observation 指向 Observation 时，内容固定，依据不会在事后漂移。设备这样的事物没有内容，也就没有漂移，设备改名只是多一条陈述，引用它的数据都不受影响。

关系都是 Observation 中的引用，所以每条关系都有时间、责任和形成方式，前端可以把所有引用字段画成同一种边。“设备上的应用”和模型判断的“123 是本人”是同一种东西。

合并之后，读取也变简单了：查询一次就拿到内容和时间，删除一件事也只是删除一份 Observation。

只引用已保存的 Observation，引用就不会成环。

业务类型的身份和 SchemaRevision 分开后，增减字段不用新建类型，旧数据按原来的修订解释，不需要迁移。业务含义改变时新建类型，旧数据才不会被重新解释。事物类型没有字段，所以用不到修订。

引用的位置由 Core 或 SchemaRevision 声明，读取方不必理解业务字段，就能枚举一份 Observation 的全部引用。

放弃的方案：

- **内容和 Observation 分成两层。** 多一层间接，读取要多一步。共用内容的能力没有用到。
- **事物保存内容。** 多个 Observer 要共用它时，内容会互相覆盖，只能规定共用的对象只放不变的内容。
- **表示关系的对象和字段引用并存。** 读取方和前端要处理两套，选择哪一种也要靠判断。
- **只保留最新值，需要历史时由各业务类型另存。** 推断依据的内容会在事后改变，每种类型还要各自设计历史。
- **允许引用目标晚到。** Observation 之间会出现循环依赖，后端还要在目标后到时反查引用方补做检查。
- **只允许顶层字段作为引用。** 好处只是存储方便，却让物理布局限制了领域结构。
- **结构变化就新建类型和资源名。** 同一业务概念的数据散落在多个类型中。

## 代价 [#costs]

- 事物本身读不到内容，显示设备名要再查 Name。读取接口要能把事物和它的陈述一起返回。
- 事物的描述要定义成单独的业务类型，类型会变多。
- 每份 Observation 都保存完整内容，存储随写入增长。
- 写入方必须按依赖顺序写入 Observation，两份首次出现的 Observation 不能互相引用。
- 业务数据保存前，所用的 SchemaRevision 必须已保存。
- 引用可以出现在嵌套结构中，存储和反查不能只按顶层单列设计。
- 设备当时叫什么，要按事实时间查，时间未知时查不到。
