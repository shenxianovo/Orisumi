Web 控制台是 Orisumi 的完整读取界面，目前只在本机使用。它按人组织记录，不按来源：首页“今天”先讲这一天做了哪几件事，每件事下面是用到的应用和会话；点任何一个名字，打开这个事物的档案；模型新形成的判断集中在“理解”里，错的就否定。采集和原始记录放在单独的一区，怀疑时才去看。

控制台是读取方：它读取所有 Observer 的数据。用户在这里否定或确认判断，写下一份 [Review](../core/rules/understanding.mdx#review-type)，也可以给事物写名字、删除实体，见 [ADR · 删除](../adr/deletion.mdx)。它还请求叙事 Observer 写一天的几件事，见 [API · Narrative](../api/narrative.mdx)。其余数据由 Observer 写入。设备端客户端只展示最近的数据，更早的日期和追溯都在这里查看。

| 页面 | 地址 | 内容 |
| --- | --- | --- |
| [今天](#day) | `/` | 这一天做了哪几件事，用了哪些应用、多久 |
| [事物](#things) | `/things` | 记录提到的应用、设备、会话和人 |
| [档案](#archive) | `/things/{id}` | 以一个事物为中心的织图：它叫什么、和谁有关、经历了什么 |
| [理解](#understanding) | `/understanding` | 模型形成的判断，逐条确认或否定 |
| [Observer](#observers) | `/observers` | 每个 Observer 今天什么时候在记录，现在是否在写入 |
| [托管](#hosts) | `/hosts` | 每台设备和服务器上的程序实例，可以管理 |
| [原始记录](#entities) | `/entities` | 类型图，以及从任意实体织出和它有关的实体 |
| [实体页](#entity-page) | `/entities/{id}` | 一个实体的全部内容、引用、版本和删除 |

## 侧栏 [#sidebar]

页面导航在左边的侧栏，分两组：今天、事物和理解看记录；Observer、托管和原始记录在“采集”下面。理解后面写上次查看之后新形成的判断数。采集出了问题时，“采集”后面有一个红点，判断方法与[今天的页头](#day-header)相同。

“查找”接受 EntityId 和 VersionId。点它或按 ⌘K、`/` 弹出输入框，先按 EntityId 读取，读不到再按 VersionId 读取；读到事物时打开它的档案，读到版本时打开实体页。

侧栏最下面的外观按钮选择主题：跟随系统、浅色或深色。

窄屏时侧栏变成页面顶部的一栏：导航横排，查找和外观收成图标。

彩色只用来区分事物和 Observer 的类别。

## 名字和记号 [#roles]

事物的名字由[读取接口](../api/reading.mdx#things)给出，没有名字时写识别依据的值的第一行，例如本机应用写它的应用包标识。本机应用归到产品后写产品的名字，见[应用的合并](#applications)。来源的名字是它的描述的类型名，例如“前台状态 Observer”；用户本人没有名字时写“用户本人”。事物的颜色按名字稳定地取，所以同名的事物颜色相同。

一个事物在页面上写成一枚记号：带类型图标的色块和名字。本机应用和应用产品有图标时，用应用自己的图标：本机应用用提到它的最近 20 段前台时段中，最新一段带图标的图标，控制台用 `order=desc` 读取它的引用方找到这一段，见 [API · 引用方](../api/reading.mdx#referrers)；应用产品用属于它的本机应用中图标最新的那个。字节按摘要读取并缓存，见 [API · 内容](../api/reading.mdx#contents)。点事物的记号打开它的[档案](#archive)，点来源的记号推出它的面板。

每一句陈述都写出谁说的和形成方式。直接记下的用实线，[推断](../core/model/observation.mdx#formation)用虚线和暖色，所以事实和理解一眼能分开。陈述后面有“凭什么”，点它从右边推出这份 Observation 的面板。

面板写事实时间、内容和它关于的事物、由哪个 Observer 记下和形成方式、依据和复核。推断的陈述在面板里可以确认和否定，否定时可以写一句说明。面板底部的“ID 和原始数据”默认收起，展开后是 EntityId、VersionId、原始内容和进入实体页的入口。在面板里点另一份陈述，下一层接在后面；超过两层时，前面的收成窄条，点窄条回到那一层。Esc 关掉最后一层。打开的面板写在地址的 `stack` 参数里，刷新页面后它们还在。

## 今天 [#day]

今天页面讲这一天做了哪几件事。例如 10 月 31 日：上午“从头审视 Observer 与 Runtime 模型”，下面列出 9 个会话；晚上“把代码迁移到事物与 Observation 模型”，下面是 ChatGPT 9 分钟、QQ 3 分钟和那个 Codex 会话。

← 和 → 翻日期，地址参数是 `date=YYYY-MM-DD`，今天省略这个参数。

### 页头 [#day-header]

页头是日期，下面一句话写几件事、几个助手会话、你说了几句和前台记录的总时长，例如“7 件事 · 24 个助手会话，你说了 20 句 · 前台记录 13 分钟”。

再下面是提示，只在需要时出现：

- 采集出了问题：有机器离线，或有启用的程序实例报告了错误，写出是哪一个，点它进入[托管](#hosts)。判断方法与托管页相同。
- 模型新认定了几件：上次查看理解之后形成的判断数，点它进入[理解](#understanding)。

### 几件事 [#episodes]

几件事是这一天当前理解中的 [Episode](../observers/narrative/episode.mdx)，按开始时间排列。每件事一行：左边是时段，右边是标题和摘要，下面是记号：

- 这件事引用的本机应用，按产品合并，后面写这件事的时段内它在前台的时长，按时长排列。
- 这件事引用的会话里，用户说过话的会话。没有说话的会话合成一枚“另有 N 个没有发言的会话”。

记号下面写“叙事 Observer · 推断”和“凭什么”。悬停一件事时，一天的条上它的时段一起亮起。

打开一天时，这一天没有写下的几件事、而这一天有助手交互或前台应用时段，控制台请求叙事 Observer 写这一天，范围是本地时区的这一天。每收到一件事就显示一件，写着的那一行显示“正在写”；收到 `saved` 后改为读取保存下来的几件事。收到 `failed` 时，已经显示的几件事撤下，写出原因和“重写”。叙事 Observer 不可用时写“叙事 Observer 没有配置 API Key”，页面其余部分照常。

几件事上方写它们由哪个模型、在什么时候写下。今天的记录在这之后又有新的保存时，写“之后有新的记录”；“重写”请求写一批新的，取代原来的几件事。

### 一天的条 [#day-strip]

几件事上面是一天的条，0 点到 24 点，分三道：几件事的时段、助手会话中每次用户说话的时刻、前台应用时段。前台应用时段按应用的颜色画。今天有一道现在的竖线。

### 应用 [#day-applications]

最下面是这一天的应用：每个产品或未归属的本机应用一行，左边是名次、记号和名字，右边是长度按时长比例的条和时长。默认列出前 12 个，其余收在“还有 N 个”里。标题后面写总时长和切换次数，例如“13 分钟 · 在 5 个应用之间切换了 11 次”。同一个 Observer 相邻两段指向不同的应用，算一次切换。

只有前台应用时段算进这里。设备、会话这些事物不进排行，它们在几件事和档案里出现。

今天的数据每 5 秒刷新一次，几件事每分钟刷新一次。

## 事物 [#things]

事物页面列出记录提到的事物，按类型分组：应用产品和未归属的本机应用、设备、助手会话、人。助手会话只列这一天有交互的，日期与[今天](#day)相同，用 `date` 参数选择。每组按名字排列，组名后面写数量。顶部的输入框按名字筛选。点一个事物打开它的档案。

## 档案 [#archive]

档案是以一个事物为中心的织图。例如 ChatGPT 这个本机应用的档案：中间是它的图标和名字，下面写“本机应用 · 在 J929TVWWK3 上”和“前台状态 Observer 这样称呼它”；左边是它的名字和看到过它的 Observer；右边是它所在的设备、它的线索、它属于的产品，以及今天的 5 段前台时段。

中间是这个事物：记号、名字、类型和所在之处，以及名字由谁写下、怎样形成，取自 `nameVersionId` 指向的 Name。下面是“写一个名字”：用户写下的名字成为一份用户本人的 Name，按 [UNDERSTANDING-9](../core/rules/understanding.mdx#understanding-9) 优先使用。

两边是和它有关的陈述，按类别分组，每组一个小标题：

| 边 | 组 | 内容 |
| --- | --- | --- |
| 左 | 怎样称呼它 | 引用它的每份 Name，写名字、Observer 和形成方式；没有名字时是一个虚线的“还没有名字” |
| 左 | 谁看到过它 | 写下过引用它的陈述的 Observer |
| 右 | 和它有关的 | 经由陈述连到的其他事物，例如本机应用描述连到设备和线索、线索归属连到产品、Relation 连到另一个会话。线上写字段或 `predicate` |
| 右 | 经历 | 引用它的、有事实时间的陈述，按类型收成一束，写数量和总时长，点开逐条列出；它所在的一件事单独一行 |

每条线从中间连到两边的节点。直接记下的线是实线，推断的是暖色虚线。点事物节点走到那个事物的档案；节点上的“凭什么”和陈述节点推出那份 Observation 的面板。同一组超过 6 个节点时，先列出最近的 3 个，其余收成“还有 N 个”。

陈述来自事物的引用方，每种业务类型怎样分到这几组由 EntitySchema 的字段决定：`thingId` 是名字，有事实时间的是经历，陈述引用的其他事物是关系，一件事引用的除外。所以接入新的 Observer 和类型后，档案照样能用。设备这类被大量引用的事物，经历和关系读最近 1000 份引用方，数量后面写“+”。

窄屏时三栏上下排列，不画连线。

### 会话的对话 [#sessions]

助手会话的档案在织图下面显示这一天的对话。例如上午在 Claude Code 里讨论建模的会话，下面按时间列出你说的话、助手的回复和工具调用。

页头是会话的产品，以及交互中记下的客户端、工作目录和模型。子 Agent 的会话按[子 Agent 关系](../observers/assistant-sessions/assistant-subagent.mdx)写出它的父会话。交互按时间排列，每次交互左边写时刻：

| 交互 | 显示 |
| --- | --- |
| 你说的话 | 浅色底的一段，写“你” |
| 助手的回复 | 正文，写产品名；Codex 的过程说明颜色较浅，最终回答写“回答” |
| 另一个 Agent 或产品发出的消息 | 虚线框，写“Agent”或“应用” |
| 工具调用和它的结果 | 合成一行：工具名、参数的摘要和结果的状态，例如退出码不为 0 时写出退出码。点开显示缩进后的参数和结果；结果全是文字块时连成正文 |
| 推理 | 收起的一行，写出第一句；没有可读的文字时写“只有加密的内容” |
| 上下文 | 收起的一行，写出上下文的种类和来源记下的角色，例如 `instructions`、`response_item · developer` |

“对话”“过程”“全部”切换显示的范围：对话只有消息，过程加上工具调用和推理，全部再加上上下文。地址参数 `view` 记下选择。

工具的输出、上下文和图片只在原始记录中，控制台在点开或显示时按片段的位置读取原始记录，见 [Assistant Interaction · 内容](../observers/assistant-sessions/assistant-interaction.mdx#content)。超过 2 万个字符的输出先显示开头，可以展开全部。

### 应用的合并 [#applications]

各设备上的本机应用按[应用产品](../observers/application-identity/application-product.mdx)合并显示。例如两台 Mac 和一部 Android 手机上的 QQ，在控制台中是一个 QQ。控制台读出全部应用产品、当前理解中的线索归属和本机应用描述，按 [Application Identity · 归属](../observers/application-identity/index.mdx#membership) 匹配：

- 显示前台应用名称和时长的地方按产品合并，名称取产品的名字。产品的时长是它的各本机应用时长之和。本机应用的记号也用产品的名字。
- 未归属的本机应用按本机应用单独显示。

应用产品的档案在“和它有关的”里列出属于它的本机应用和线索，每条线索连着它的线索归属。

## 理解 [#understanding]

理解页面列出模型形成的判断，也就是形成方式为推断的 Observation，[几件事](#episodes)除外。例如“ChatGPT 属于应用产品 ChatGPT”“这个 Codex 会话继续了 Claude Code 的‘Observer 与 Runtime 建模’”“00:46 的 Codex 会话叫‘讨论采集建模与实现分工’”。

页头写一句说明：判断直接生效，错的才需要否定，确认过的模型以后不会取代。下面分“待看”和“全部”：待看是上次查看之后形成的判断，全部是当前理解中的全部判断。判断按业务类型分组，组内按保存时间倒序。

每条判断一行：先是一句话，判断中的事物写成记号，例如名字写“这个会话叫‘……’”，Relation 写“主语 `predicate` 宾语”，线索归属写“线索属于产品”；其他类型写类型名和内容的第一个文字字段。下面写 Observer、形成方式、保存时间和依据了几个输入。右边是“确认”和“否定”，否定时可以写一句说明；已复核的写“已确认”或“已否定”，可以撤回，撤回是删除这份 Review。

“上次查看”记在浏览器中，打开理解页面时更新。

## Observer [#observers]

Observer 页面每个 Observer 一行，显示它今天什么时候在记录、现在是否在写入。例如前台状态 Observer 从 10:13 记到 17:36，之后它那一行是空的，右边写着“29 分钟前”；18:04 它保存了 VS Code 的一段，这一行末尾开始跳动。

开头是一句话，例如“3 个 Observer，1 个正在写入”，后面是今天的 Observation 数，以及最后一次写入的时刻和 Observer。

Observer 是全部程序实例和用户本人，今天没有写入的也列出。Observation 的 Observer 读不到时，这些 Observation 单独成一行“不可读取”。名称与[来源的名字](#roles)相同，同名的加 EntityId 末 4 位。

每一行的时间轴分两段，所有行对齐：

| 段 | 范围 | 内容 |
| --- | --- | --- |
| 今天 | 当天 0:00 到 24:00，占 4/5 | 今天的 Observation |
| 现在 | 最近 10 分钟，占 1/5 | 同样的内容放大 |

一行按哪种时间画，看这个 Observer 写的陈述：

- 今天写了有事实时间的 Observation 的，例如前台状态 Observer，按事实时间画：时段是一段横条，只知道一个边界的是一道刻度。
- 其余的，例如应用识别 Observer 和用户本人，按保存时间画，每份 Observation 一道刻度。这些 Observation 从 Observer 的引用方读出。

最近 60 秒内保存过 Observation 的 Observer 算正在写入。它的一行高亮，末尾的点跳动；每一行右边写最近一次写入距现在多久，以及今天的 Observation 数。正在写入的排在前面，其余按最近一次写入排列。

点一行，右边推出这个 Observer 的面板，地址参数同样是 `stack`。

今天的 Observation 每 5 秒刷新一次，引用方每分钟刷新一次。事实时间远离今天的补发不在按事实时间画的行中出现。系统开启“减少动态效果”时，末尾的点不跳动。

## 托管 [#hosts]

托管页按机器列出程序实例，规则见 [Management](./management.mdx)。顶部是一句话，例如“2 台机器，1 台离线”，下面写有几个 Observer 在运行、几个等待设备同步；右边是“接入”，签发配对码。

每台机器一张卡片：名字、设备或服务器、连接状态，例如“离线 · 18 分钟前联系过”；右边是“安装”和更多操作（改名、移除，已移除的是重新接入）。机器离线时“安装”不可用。卡片里每个程序实例一行：

- 名字和版本，下面是运行状态的点和文字，以及错误。机器离线时运行状态是“状态未知”。
- 后端接受的配置还没被设备执行时，写着“等待同步”。
- 右边是启用开关，离线时也能改，设备连接后执行。
- 已删除的实例收在卡片底部，写出它是否已经停止。

点一个实例，右边推出它的面板，样式与陈述的面板相同：

| 部分 | 内容 |
| --- | --- |
| 状态 | 配置（带启用开关）、同步、运行、连接、版本和写入，错误、被拒绝的原因和采集提示写在下面。写入写出等待转发的请求数和被拒绝的写入数，都为 0 时不显示 |
| 设置 | 设置的 JSON。写成对象时才能保存，整个对象一起保存，可以还原 |
| 维护 | 重试；有被拒绝的写入时可以重发；更新、卸载和新建实例作用于它的安装包，更新和卸载的确认写出受影响的实例。机器离线时不可用；操作进行中和结束后，下面一行写出进度和结果，没有收到结果时写“没有收到结果，上面是设备现在的状态” |
| 删除实例 | 在面板中确认后永久删除 |

面板底部链到这个程序实例的档案。Esc 关闭面板。

“接入”的对话框显示 8 个字符的配对码、剩余的有效时间和拷贝。“安装”的对话框先读取那台机器可以安装的包，每个包一行，原来的实例已删除的写明会新建实例。

托管方和实例每 5 秒刷新一次，进行中的在线操作每秒读取一次状态。

## 原始记录 [#entities]

原始记录页面从任意实体出发，织出和它有关的实体，事物和陈述都可以作为起点。它和[档案](#archive)用同一套织图，区别是可以一层层展开，也能显示 InputSet 和 EntitySchema。例如从 VS Code 开始：点它，左边长出它的前台应用时段，每段写着“14:00–16:00 · 前台状态 Observer”；点其中一段，左边长出前台状态 Observer。停在 Observer 上，整条路亮起：前台状态 Observer —来源— 14:00–16:00 —`localApplication`— VS Code。

地址参数 `root` 是起点的 EntityId。没有起点时，页面是[类型图](#type-map)，在那里选起点。

### 织图 [#weave]

事物是线，Observation 是把线系在一起的结：谁依据什么说了什么。业务字段中的每个引用都是一条边，所以应用所在的设备和模型判断的“123 是本人”画法相同。织图按这个意思画节点：

- 有事实时间的陈述写它的名字，下面写事实时间和记下它的 Observer。
- 其余的 Observation 画成结，写着 Observer、形成方式、事实时间和依据了几个输入，它的 InputSet 并进结。例如应用识别 Observer 认定 `com.tencent.qq` 属于 QQ：这条线索归属是一个结，左边连着它读过的输入，右边连着线索和应用产品 QQ。
  [Relation](../core/rules/understanding.mdx#relation) 是两个事物之间的一条边，线上写 `predicate`，点这条边打开这份 Observation。
  有上一版时，结上另写一行这次改了什么：数组字段写加入和移出的元素，引用字段写目标的名字，其他字段写新的值，去掉的字段写“去掉”，几处变化用分号隔开。首版写“新建”；内容相同、只有时间变化时写“内容相同”。
  被否定的结画删除线，被取代的结颜色变浅，[复核](../core/rules/understanding.mdx#understanding-5)连在它旁边。依据已被否定的结写“依据已被否定”，见 [UNDERSTANDING-8](../core/rules/understanding.mdx#understanding-8)。
  结上的 Observer 名字可以单独点：点一次，Observer 长在结的左边，线上写“来源”；再点一次收起。展开结时只长出依据和其他邻居，谁说的已经写在结上。
- 事物各是一个节点。EntitySchema 只出现在类型图和面板里。

位置按来龙去脉从左往右排。点一个节点，它的邻居长在它左边或右边的一栏，连线上写着关系：

| 邻居 | 在哪边 | 线上写 |
| --- | --- | --- |
| 记下它的 Observer。结的 Observer 由点结上的名字长出 | 左 | 来源 |
| 它依据的输入，即 InputSet 的成员 | 左 | 依据 |
| 引用它的 Observation | 左 | 引用所在的字段，例如 `localApplication` |
| 它的业务字段引用的实体 | 右 | 字段名 |
| 以它为输入的陈述 | 右 | 依据 |
| 它作为 Observer 写下的 Observation | 右 | 来源 |

邻居来自 Core 的结构：Observation 和 InputSet 的固定字段、EntitySchema 声明为 `reference` 的字段，以及后端给出的引用方。所以接入新的 Observer 和类型后，织图照样能用。

已经在图上的邻居只连一条虚线。再点一次节点，收起从它长出来的整枝。

同一边、同一个标签、同一类型的邻居超过 6 个时，先长出最近的 3 个，其余收成一束，写着“还有 N 个”；点一次线束再放出 8 个。例如 VS Code 一天有几十段前台应用时段，它们收在一束里。

依据按类型分组：一种类型只有一个输入时直接长出，同一类型有两个以上时全部收成一叠，写着“6 个”和类型名，点一次同样放出 8 个。

一个节点和从它长出来的整枝占一段高度，同一个节点长出来的各枝上下排开，互不交错。

停在一个节点上，它从起点长出来的那条路亮起，其余的变淡。选中的节点下面有“详情”和“从这里开始”：前者推出它的面板，后者把它设为新的起点。

每次生长后，画面对准新长出来的节点，最小缩到 60%。拖动背景平移，捏合或按住 ⌘ 滚动滚轮缩放；右下角是缩小、放大和“适应画面”。

### 类型图 [#type-map]

类型图分四列：来源、陈述（连同 InputSet）、有事实时间的陈述、事物。一条线表示一种类型的实体经由某个字段引用另一种类型，线上写字段名，末尾的 `Id` 或 `VersionId` 省略。例如前台应用时段指向本机应用的线上写着 `localApplication`。

引用关系来自样本：每种 Observation 的类型取最近的一份，读出它引用的类型。事物的类型中，程序实例是来源。

点一个类型，下面列出它的实体：

- 事物、来源、陈述和依据按名字排列，同名的写出不同的那一段。
- 有事实时间的陈述列出最近 24 小时的，按时间倒序。

点一个实体，从它开始织。地址参数 `type` 是业务类型的 `resourceName`，或者 `input_set`。

## 实体页 [#entity-page]

实体页显示一个实体的一个版本，从面板底部的“ID 和原始数据”进入。例如一段前台应用时段的实体页，标题是“VS Code”，上方写“前台应用时段”。标题下面是 EntityId、所选的版本和它的保存时间。事物的实体页在内容的位置写识别依据，没有版本。

页面从上到下是引用图、内容、版本、复核和删除。Observation 的复核一节列出引用它的 Review，并提供“确认”和“否定”。地址参数 `version` 选择版本，不写时显示当前版本。内容中的 `binary` 字段写出媒体类型和大小，媒体类型是图片时显示图片。

引用图的中间是这个实体，左边是它引用的事物和版本，右边是引用它的版本。每个节点写名字、类型和引用所在的字段，字段名省略末尾的 `Id` 或 `VersionId`。有事实时间的节点在右侧写出事实时间，例如“14:00–16:00”。点击节点进入它的实体页，引用的是版本时选中那一版。

鼠标在节点上停留片刻，或者用键盘聚焦节点，旁边浮出它的预览：名字和类型；事实时间和时长；内容的前几个字段、来源和形成方式；引用所在的字段和保存时间。预览只用来看，点击仍然进入节点所属的实体。
