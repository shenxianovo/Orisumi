# 导洞设计

导洞的模型已整理进文档站的模型分区 `src/Docs/Orisumi.Docs/content/docs/model/`：原件、读出、给 Agent 的命令、存储和四个来源怎么采。这里留着按题倒推的需要、进度、下一步和待定的问题。

## 题目要什么

先从测量基准倒推，每道题要读到哪些东西：

| 题 | 要读到的 |
| --- | --- |
| A1 一天做了什么 | 各设备的前台、浏览器、VRChat 时段；会话在什么时候、标题；提交 |
| A2 课题类型 | 人在会话里说的话 |
| A3 Heartbeat 故障 | 人说的话；旧 Heartbeat 哪台设备哪段没数据、记下的丢失 |
| A4 设计决定 | 人说的话，以及它前后助手的回复（决定常是助手提、人确认） |
| A5 晚上在哪台 | 两台的前台时段、键鼠疏密、VRChat 世界 |
| A6 对 GPT 的不满 | 人说的话 |
| A7 盲区 | 有哪些来源、各覆盖到哪；前台有 ChatGPT 对话但没有它的内容 |
| B1、B3、C1 | 人说的话和前后的回复，跨 10-30 到 11-02 四天 |
| B2 重开删了什么 | 提交和改动的文件 |
| B4、B6 | 前台时段、键鼠疏密 |
| B5 晚上 | 提交（me 仓库）、VRChat、键鼠 |

除了「人说的话」要从会话里挑出来，其余都是把原始数据按时间和设备摆开。推论：没有一道题必须先由模型生成理解才能答，四天的人说的话 Agent 读得完。这条要靠第一次答题验证。
