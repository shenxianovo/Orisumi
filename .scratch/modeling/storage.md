# 原件的块存储

2026-11-04 和用户定下，接在导洞之后做。需求见发心页的「采集幂等」「采集失败要通知」「原件存成块」「多处都有一份」。实现之后整理进文档站的模型分区，这份删除。

## 定下的

- **哈希**：SHA-256，块名带算法前缀，例如 `sha256-…`，以后能换算法。哈希按未压缩的原文算，存储时用 zstd 压缩。
- **切块**：FastCDC 按内容切，最小 256 KiB、平均 1 MiB、最大 4 MiB。小记录先成批写成一个文件再切。追加型日志每采一次只多出末尾一两块。
- **版本**：一个版本就是一条采集记录，也是块。某份东西的历史、两版之间的差异都是投影。增量编码是存储层的压缩，块的身份还是全文的哈希；等出现频繁快照的小文件再加。
- **各节点留哪些块**：服务器留全部。设备留自己采的块，服务器确认收到并校验后，按空间清理；要读别的块时从服务器按需拉。
- **加密**：先不加密，服务器是用户自己的机器。用户级密钥加密（restic 的做法）留作以后的选项，代价是密钥丢了数据全没。
- **认证**：先不做。以后每台设备一个密钥对，第一次加入由用户批准，和 Syncthing 的设备 ID 一样。
- **失败**：失败的采集也留一条采集记录，同时发 macOS 通知。
- **部署**：先在本机做。服务器也先在本机跑，作为另一个节点，同步在一台机器上就能试。

## 顺序

1. 勘探参照：读 Perkeep、Syncthing、restic 的设计文档，只读不装，记下能借的和要避开的。
2. 本机的块存储：把导洞的四个来源改成写块，采集记录也是块，块的索引作为投影；导洞的读出和命令改成从块读，答题结果和现在一致。
3. 定期采集和失败通知：每个来源各定频率，失败留记录、发通知。
4. 本机上跑一个服务器节点，按块同步。
