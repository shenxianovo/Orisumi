先让数据存在并留下。沿目标、来源、取得、保存、理解和使用查看依据、候选与影响。✓ 表示用户实际确认；Agent 在授权内采用方案，当前路线、条件性安排和后置项分别展示。

## 阅读方式

✓ 本轮确认来自用户实际表态；既有决定保留历史依据；助手推荐与确认分别显示。每个候选继续到下游问题，或落到具体实施、试验、勘探和条件终点。

授权原话：现在所有候选节点你可以自己看。可以先不用等我确认。

授权选择，不等于逐项确认

[按当前采用路线阅读](current-route.md)。Agent 采用与条件性安排由采用记录表达；试选用于比较，用户确认继续单独保留。

本图含 13 个模块、155 个节点、324 个候选，本轮确认 10 项。

## 模块

- [目标、立场与确认](modules/roots.md)：用户已确认的起点，以及既有立场的适用范围。
- [来源事实与假设](modules/conditions.md)：现实证据支持哪些判断，证据覆盖到哪里。
- [来源范围与接入次序](modules/sources.md)：确认来源实例、选择下一条导洞、界定附件与版本条件；全部路线是候选，用户已确认的根另列。
- [本地记录与既有历史](modules/sources-local.md)：Claude、Codex、旧 Heartbeat、Git、文件、Shell 和 Magpie 的实际材料、替代范围及恢复检验。
- [服务、通信与个人记录](modules/sources-services.md)：IM、笔记、网页 AI、收藏/观看、计划、邮件、听歌、账单；未勘探能力落到具体样本任务。
- [实时观测、媒体与设备](modules/sources-live.md)：前台键鼠、浏览器、屏幕声音、系统剪贴板、VRChat、手机和硬件的观测深度。
- [取得方式与采集调度](modules/capture.md)：文件/数据库一致性、接口全量增量、瞬时事件、媒体分段、离线、权限、启动与当前保障边界。
- [内容、出处、身份与版本](modules/records.md)：一份材料以什么边界保存，怎样区分内容、取得事实与来源里的东西，未来怎样准确回到当时的原样。
- [存储与生命周期](modules/storage.md)：比较整文件、固定块、内容定义块和来源原生增量；分开决定压缩、索引、校验、保留、删除及导出恢复。
- [设备、持久保存与同步](modules/availability.md)：把不丢已取得材料、跨设备查看和设备间交换分别处理，比较外部备份、中心服务与网状同步。
- [整理、身份与理解](modules/understanding.md)：原件之后怎样解析、关联、检索与形成可追溯且可替换的理解。
- [查询、界面与共享](modules/access.md)：Agent与人如何使用同一批材料，怎样控制共享与后续协助的边界。
- [阶段、验证与运行](modules/delivery.md)：每阶段独立有用，以真实材料检验保存与使用；长期读回和运行保障分别安排。

## 采用与重审重点

- [交付路线怎样排序](modules/delivery.md#n-e93627fc1fab2325)：建议先完成收集与历史取回，再按真实问题补查询与理解。判断这样的独立阶段是否符合当前目标。
- [来源接入顺序](modules/sources.md#n-821855273f39bc59)：建议现存易取得材料先留底，同时为一条不可补回的观测做小导洞。决定下一项投入在哪里。
- [Codex状态数据库范围](modules/sources-local.md#n-bb8086babda89015)：建议 state_5 一致整库快照；相比两表导出，保住已知项目、分组与工作树等关系。其他数据库另查。
- [附件与依赖的收集边界](modules/sources.md#n-128cbd6f1a6dfa45)：正文路径与附件实体分别验收；需要确定同一来源包含哪些实际目录与依赖。
- [内容取得与来源身份](modules/records.md#n-15c7ee1513e29577)：建议内容相等、同一次取得、同一来源对象三件事分别表示，避免复用字节时抹掉出处。
- [原件存成块](modules/storage.md#n-1e55971a7ab3ff58)：当前大日志沿用已实现 CDC；本轮样本中静态集整文件更省，中插回放 CDC 更省。选择按真实历史复用还是统一简单形式。
- [多处都有一份](modules/availability.md#n-ae9194edde188509)：建议先用外部有版本备份并验证恢复；内建交换等真实需求出现再选，网状不是长期保存的必然结果。
- [使用能力边界怎样扩展](modules/access.md#n-ee3ad59eb9be5324)：后续查询、理解、查看、共享与主动助理分别有条件。当前数据收集目标不要求先绑定其中一个用途。
- [第一阶段怎样验收](modules/delivery.md#n-ae87acd40d922614)：建议从测试来源消失后仍能恢复原件、已采版本和出处来验收；问答成绩另验。
- [从全景讨论怎样进入实现](modules/delivery.md#n-473477a3b70f395c)：在本次授权内采用具体方案，列出格式、身份、原件样例和验收，完成一段独立交付；选择与实施进展分别记录。

## 覆盖范围与限制

覆盖当前39条需求、6份架构决定、全部来源清单、现有模型与实现，以及本轮展开的实质候选。119个决策均有授权内的 Agent 采用、条件性或后置记录，并给出理由、代价与重审条件。候选继续到共享下游或具体实施、试验、勘探终点；实施与验证范围按独立交付推进。

- 用户确认只对应实际原话及回应范围。delegation 记录自主选择授权，resolution 记录 Agent 的取舍；采用不等于用户逐项确认，也不等于实现完成。
- 新来源、接口、媒体与多设备能力按条件性或后置记录安排；具体试验写在触发条件和分支终点。能力是否已实现、已验证，以实现记录及实际验收为准。
- 影响查询是包含所有候选路线的潜在范围；多前提需要一起判断。它不证明改变某点一定会使全部下游失效。
- 可组合来源范围允许多选，同情境实现方案作单选比较。试选单独保存，保持用户确认和 Agent 采用记录不变；跨节点组合仍需按条件核对。
- 存储对照包含真实静态样本与明确标注的历史回放；只比较去重后压缩内容体积，不能代表真实连续历史、完整元数据、CPU或所有来源。
- 既有答题基准验证过已删除的导洞；不能据此声称重写后的读取能力或全部答案已经通过用户验收。
- 已授权采用的方案按独立交付推进，正式文档和实现随实际完成范围同步替换；尚未实现的路线继续保留条件与证据缺口。
- 外部副本仍是按需手动复制。当前三个来源已由用户级任务持续采集；受限 IP 网络与进程重启有实际证据。真实重新登录、全天运行、系统睡眠、其他平台、全新权限身份及断电各自待验，系统进程状态不能证明来源完整率。
- 浏览器已验证受控新 Profile 的标签/窗口观测、暂存重放与独立恢复；安装实例是扩展生成身份，复制Profile可能复制它。日常Profile安装、长期量、睡眠和未暂存尾部各自保留验收边界。
