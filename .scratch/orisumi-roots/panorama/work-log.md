## 当前交付目标

用户已授权 Agent 审阅候选、自主选择并推进实现，并要求本轮完成后提交、不推送。10 项用户确认保持原话与范围；119 项决策另记 Agent 采用、条件性安排和后置理由。通用方法与工具留在 qstack，项目事实和决定留在 Orisumi；当前路线见[采用记录](site/current-route.md)。

## 当前实现与证据

### 保存与取回

Codex 的日志原字节、state_5 整库一致快照、已选附件目录和直接出处已实现。真实采集包含 1,981 个普通文件、142 个链接、1,602,517,392 字节；本机整轮恢复、单文件导出与独立核对通过。变化版本、来源消失和部分失败由确定性样例覆盖。方法与范围见[Codex 验收](../../../src/Docs/Orisumi.Docs/content/docs/model/validation.mdx#codex-取得与恢复)。

日志、附件与数据库分别取得；采集根记录本轮起止窗口，清单记录取得方式。逐文件独立时间和跨材料共同快照仍未建立。模型与图中的实现说明已按这一实际范围更新。

### 外部副本

真实保存集已经复制到另一台 Linux 机器。2,888 个存储文件、1,159,911,553 字节与本机逐项 SHA-256 一致；独立读者恢复全部 1,981 个文件、142 个链接、1,602,517,392 字节，SQLite quick_check 通过。

外部工具先复制 config/records，再复制 blocks；全部引用校验通过后写完成记录并发布版本目录。当前存储只追加、根最后发布且没有 GC，这个顺序形成完整闭包。并发新增、删除事实、源不可用、缺块和损坏样例均已验证，具体口径见[外部副本验收](../../../src/Docs/Orisumi.Docs/content/docs/model/validation.mdx#外部副本)。

日常库另固定149根，在采集持续运行时复制4931个存储文件、1,338,260,050字节；Linux独立核对全部根引用的44,915,549,035字节材料，并实际恢复三个来源最新根共3273文件、142链接。核验后发布新版本，收口时新增31根留待下一份。当前按需手动备份，未配置计划任务、服务或保留期清理。后续新增材料等下一次备份；旧备份要合并最新可得删除事实才知道后来的删除。加入回收、改写或新依赖记录后重新验证复制顺序。

### 前台观测

macOS 小型原生程序取得 AppKit 通知与公开属性，托管采集器把每条完整观察行立即存成 Raw 记录。当前 macOS 应用级路线已在授权下由 Agent 采用并实现；三个专用应用的 7 次约 1 秒切换与 15 次约 0.2 秒切换全部实际完成，22 条激活与 22 条失活分别与应用自身回调的 PID、次数、各类别顺序和单应用内部顺序一致。

本轮 49 条原件包含 started、initial snapshot、46 条应用通知与 stopped，序号连续，全部恢复。独立核对哈希、长度、LF、来源、取得方式、运行身份与序号通过，共 46,150 字节。同应用 4 次真实切窗和 1 次标题修改期间没有新增应用级通知，说明当前接口的应用级范围。

22 个切换区间的 workspace 通知均先交付新应用激活、再交付旧应用失活；其中 21 次测试应用间切换的自身回调先失活、后激活。产品原件保存 workspace 的实际交付顺序，测试应用自身回调作为独立对照材料；observedAt 表达读取回调的时刻，应用启动日期与保存窗口分别保留。

定时结束与真实 TTY Ctrl+C 已验证。后者返回 130，保存并恢复 started/snapshot/stopped 三条、共 1,436 字节，stopped 原因是 stop-requested，采集根无失败。9 项前台行为测试覆盖逐条可读前缀、原字节、半行与异常、有效行失败回存、存储不可写、超时和原生 SIGINT；开发工具的 2 项新回归覆盖取消后收尾输出和超时强停。公开证据统一见[前台验收](../../../src/Docs/Orisumi.Docs/content/docs/model/validation.mdx#前台观测)。

本轮按 codebase-design 与 improve-codebase-architecture 检查了平台对象读取、进程运行循环、原字节交付及保存职责。Swift → JSONL → 托管原件存储的 seam 能定位并分别验证平台接收与保存问题，生产架构保留现状。

网络限制实验已经区分外部 IP 与本机 IPC：旧 deny network* 也拦截 UNIX socket，开发入口停在 SDK restore 的项目图发现；保留本机 IPC、拒绝全部 IP 后，两轮共 40 份原件、37,586 字节全部恢复，17 次激活与 17 次失活对应，停机空档保持未知。local-first 与本机 local-raw 在授权下采用；整机物理断网、代理联网与断电另测，见[网络与重启验收](../../../src/Docs/Orisumi.Docs/content/docs/model/validation.mdx#网络限制与重启)。

### 持续采集与发布

新增唯一的 `orisumi publish <新目录>` 开发入口，发布本机自包含程序；日常由三个用户级 LaunchAgent 直接运行，明确共用仓库外原件目录。复用文件来源的 300 秒轮末等待与前台逐条保存，系统承担启动和进程重启。没有增加统一采集总管或安装管理状态。既有目标、发布失败和取消的黑盒检查通过，原有路径保持不变，失败产物被清理。

日常两个文件来源各运行两轮，与前台的 48 条观测共固定选入 52 份采集记录；全部恢复并独立核对 6,572 个文件、284 个链接、4,422,039,666 字节，两份 SQLite quick_check 通过。正式前台任务的 22 次激活与 22 次失活和应用自身回调对应。三个任务 bootout 后 CLI/helper 均退出，前台保存正常结束；bootstrap 后新运行与初始查询恢复通过。SIGTERM 后系统 KeepAlive 约 0.6 秒启动新进程。实际重新登录、全天与睡眠仍单独验收。

已移除退出状态的旧 Heartbeat 登录项，并暂停其旧维护任务；旧程序、原件与备份保留。既有 Orisumi 每周架构维护继续使用。固定程序更新后，五项任务已分别产生成功采集记录，新增两项仅采Orisumi/qstack；Chrome host独立更新后取得16份新版本观测，两个run分别连续1–35、1–5，三类材料恢复通过。操作说明见[本机持续采集](../../../src/Docs/Orisumi.Docs/content/docs/model/continuous-capture.mdx)。

三进程共库的实测发现旧 File.Move 发布会重复计算新增对象。最小回归先失败，再改成原子不覆盖发布；40 次共享对象竞争恰好一个新增，60 份恢复通过，其中40次发生在其他写者仍运行时。职责继续留在 StoreFile，未加入全局锁、重试平台或新的存储格式；本机通过的范围见[并发发布](../../../src/Docs/Orisumi.Docs/content/docs/model/validation.mdx#并发发布)。

### 浏览器观测

正式 MV3 扩展保存标签/窗口原回调与独立查询，本地暂存后经 Native Messaging 交本机原件；匹配根回执后移除暂存。受控双 Profile 的119入站帧、118回执根逐字节恢复通过，另有14帧长消息验证。断连暂存、Worker重启、旧回执和两类存储故障分别有行为证据，见[浏览器验收](../../../src/Docs/Orisumi.Docs/content/docs/model/validation.mdx#浏览器观测)。

日常 Chrome 当前 Profile 已加载，16份启动/查询/回调原件核验通过；三类代表材料恢复字节一致，实际 receiver 由 Chrome 维持。用户当次确认的是加载操作，浏览器格式、协议与范围仍标为 Agent 自主采用；长期完整率另测。

### Git 引用与可达对象

导洞A/B在来源隔离后分别恢复26/12个对象与7/2个提交版本，HEAD与其他符号关系另存；旧reflog、index、工作区、LFS实体和子仓库对象分别声明范围。依据这些实测采用bundle及分次命令原输出，正式实现和真实两仓库各两轮独立恢复均通过，分别核对30/23936个对象。默认并行打包导致未改仓库第二轮新增约17.7MB，限定本次命令单线程后bundle完全复用，最终只新增13,661字节出处；取得参数与范围按[Git模型](../../../src/Docs/Orisumi.Docs/content/docs/model/git.mdx)记录。

## 本轮解决的卡点

| 问题 | 当前处理与验证 |
| --- | --- |
| 图的实现字段仍称没有 Codex、没有恢复命令或 ADR3 采用网状 | 按代码、现行模型与验收重写 43 处实现说明，外部副本与前台分别保留准确完成范围 |
| 前台沿周期扫描会留下未提交窗口 | 每条完整观察立即形成独立采集根；已有前缀可恢复，进程停止和未落地尾部的缺口分别说明 |
| 有效观察在存储失败后回存时被误称为无效，计数遗漏 | 最小失败用例先复现，再修正路径与已保存计数；未知/半行仍按对应失败材料保留 |
| TTY Ctrl+C 先杀掉进程树，正常结束行来不及保存 | 原生程序由父进程 stdin 收尾，产品取消窗口与 Dev 有界等待相配合；真实 TTY 及进程行为回归通过 |
| stdin 提前关闭掩盖已取得半行的错误 | 双管道关闭回归保留两种失败事实与已取得末尾字节 |
| 静态查询与管道测试不足以证明真实切换可取得 | 受控应用自身记录真实激活/失活，独立与 22 次切换及 49 条恢复原件对账；清理旧桌面状态阻塞表述 |
| 不同回调通道的跨应用交错次序不同 | 保留 workspace 实际交付顺序，按激活、失活各类别和每个应用内部顺序分别核对，来源时间与取得时间分别说明 |
| 拒绝全部 network* 同时拦截本机通信，开发入口等待 | 分别对照 IP 与 UNIX socket；拒绝 IP、保留本机 IPC 后，真实两轮采集与40份恢复通过 |
| 日常启动依赖工作区与隐式构建 | 显式发布自包含程序，三个系统任务直启；开发入口继续用于开发 |
| 多进程保存相同对象会重复计算新增 | 红灯回归复现后改为原子不覆盖发布；唯一新增、胜者保持和运行中恢复均通过 |
| 开发临时进程与共享编译缓存的清理范围混淆 | 只清本轮专属测试进程；可复用构建服务保留，受影响检查重新运行 |
| 公开证据链接指向被忽略的本机目录 | 统一改引正式 validation 页，公开聚合结果与方法，样本和私密运维值留在本机忽略目录 |
| 先复制内容再复制新增记录可能缺块 | 确定性反例定位缺失清单；先 records 后 blocks 的并发试验和真实异机恢复通过 |
| 只拿早期备份无法知道后来的删除 | 明确旧副本的时间范围，合并最新完整记录后核对正常列举不复活已删除采集 |
| 接收器断连期间短暂标签无法由快照补回 | 扩展先持久暂存，收到原件根回执后清理；受控断连和Worker重启恢复通过 |
| 旧暂存清理失败或新写入失败会互相阻塞 | 两个独立红灯用例复现，修正发送循环；已落盘队列、新观测持久化分别继续可做的工作 |
| Git父进程先退出，子进程仍持输出管道 | 独立复现取消悬住；收尾改成2秒有界排空，保留前缀与缺口，已重父后代的存活单独说明 |
| 相同Git对象集并行打包后字节变化 | 三次单线程测量一致且对象等价；仅本次bundle参数固定线程，正式两轮复验确认内容全部复用 |
| 截断bundle或悬空头部仍可能通过verify | 实测verify只看头与先决对象；完整轮再mirror clone和fsck，截断/悬空各自有失败回归 |
| 浏览器工具拒绝 file 协议 | 保留实际布局未验收的限制；以无浏览器 DOM 测试核对交互逻辑 |

## 图与方法检查

图生成器检查文件引用、节点唯一、关系无环、候选终点、确认字段、采用候选与显式冲突。本轮重建后重新执行图验证、全图 DOM 测试以及本地链接与标题锚点检查。DOM 覆盖导航、搜索、单选/多选、路线载入、试选导出、采用状态/阶段筛选和确认/采用隔离；实际浏览器布局另待验证。

qstack 的方法试跑是有限场景：自主展开已有独立例子，新增“授权后自主采用并实现”的独立 Agent 行为试跑尚未执行。结构检查与真实对话效果分别判断。项目级 tidy/verify 由主 Agent 合并后统一执行，图检查不替代产品验收。

## 尚待补充的证据

- **前台来源覆盖**：当前 Mac 身份、应用级通知、受限 IP 网络及进程重启已有证据；其他平台、更短间隔、全天、系统状态组合与全新权限身份各需对应试验。采集启动窗口和未保存尾部保持边界。
- **长期自动取得**：三个用户级任务已持续运行，实际重新登录和长期资源成本另测；副本仍手动，定时副本按新增材料的备份窗口安排。
- **长期保存**：独立异机恢复证明当前格式可解释、依赖可取得；定期演练、断电和十年介质寿命仍需对应证据。
- **理解与身份**：原件引用与恢复已成立；语义读出、数据库行定位、跨源身份、模型调用包和版本选择继续按真实问题进入。
- **他人使用与共享**：自己的第二保存位置与给其他人看材料分别处理；真实受众、范围和交付产物出现时再验授权。
