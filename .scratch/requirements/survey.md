# 勘探

2026-11-03 定下：先采集、看清每个来源的数据长什么样，再建模。前两版都是挖到半路才撞上真实数据的怪癖，这一版先勘探。勘探程序的规则在 AGENTS.md 的「勘探」一节。

## 勘探记录的写法

每个来源一份记录，写在本文件对应来源下面，或单独成 `.scratch/requirements/survey-<来源>.md`。勘探完的发现整理成需求页里的「假设」。

- 原始数据长什么样：贴一两条真实样本。
- 频率和体量：一天多少条、多大。
- 瞬时还是持久：错过就没了，还是事后能拿到。
- 能追溯到多早。
- 拿不到的部分。
- 怪癖：会被改写、会被重读、同一个东西有不同名字、信息散在几处。
- 拿到它的代价：权限、登录、接口限制、要不要常驻。
- 和哪些来源重合。

## 来源清单

Magpie、Shell 历史、Git、IM 本地库、文件和受保护的系统数据的速记见 `survey-local.md`。

「用户」是用户列的，「候选」是助手补的，待用户判断要不要。顺序是建议的先后：瞬时的先做，持久的随时能补。

### 不用写新程序

| 来源 | 来自 | 怎么勘探 |
| --- | --- | --- |
| 前台应用、键鼠事件 | 用户 | 读旧 Heartbeat 已有的数据，已勘探，见 `survey-heartbeat.md` |
| macOS 前台应用接口 | 用户 | AppKit 初始查询与通知接口，见 `survey-macos-foreground.md`；初始查询、受控切换、原件恢复及受限 IP 网络下重启已验；系统状态组合与全天运行另测 |
| Claude Code、Codex 会话 | 用户 | 本机 JSONL，直接读，已勘探，见 `survey-assistant-sessions.md` |

前两版撞到过的怪癖，勘探时核对：

- 前台窗口几秒切一次，短时段很多；一个应用也会挂几个小时。
- 键鼠事件一天几千条，别的来源一天几条。
- 同一个应用有多个安装（例如 Lark、Chrome），跨平台时身份不同。
- Codex 的标题在索引文件里，不在会话日志里；Claude Code 的标题在日志里，重读时会再出现一次。
- Claude Code 按历史重读时，时区变化会让同一条记录看起来不一样。
- 会话里有用户消息、助手文本、推理、工具调用、子 Agent，各家结构不同。
- 采集端会积压，积压太多会丢数据。

## 用户的决定

- 公司机器上的工作内容照常采集，不做隔离。
- 勘探采到的原始数据都存下来。

存储：用户在想存算分离，参考 [personal-digital-environment](https://github.com/shenxianovo/formal-models/blob/main/models/personal-digital-environment.md)。需求层面已确认「不绑定某种存储」，支持哪几种留到建模阶段。
