# 发心：待定和否决

确认的陈述在文档站 `src/Docs/Orisumi.Docs/content/docs/requirements/belief.mdx`，这里用那里的名字引用。

## 否决

- 数字主权（曾作为发心候选）。用户：形式上有点像，但强调个人数字主权格局太大，不是发心。

## 待定的陈述

- 瞬时与持久（候选定义）。用户的感受，用户自己说可能不对：一件事可能是转瞬即逝的，也可能留下了持久化的东西；可能两个都有，也可能只有一个；两个都有时，留下的信息量也不一样。会依赖「收集一切」。助手的看法：「收集一切」里的四类说的是数据在谁手里、还能不能拿到，这条说的是事情发生时有没有留下痕迹，两者像是正交的。
- 「原始层」的延伸：两层信息量相同时可以删掉原件（用户说这是理想情况）。

## 讲述（2026-11-02 第二轮，助手的推论和候选）

用户确认的只有「有的东西是人讲述出来的」，已进文档站。下面都待用户判断：

- 推论：讲述也是观测，观测的是「这个人在某个时间说了什么」。后来的讲述不覆盖先前的，两次说法不一样时都留着。
- 推论：讲述要花人的力气，所以讲述的成本要尽量低，人用平时的方式说就行。
- 候选场景：
  - 在 QQ 上给自己发一条想法，它就被收进去了。
  - Agent 看到我最近一周的数据，问「那天为什么改了方向」，我回一句，这句就留下了。
  - 我和 Agent 一起写 ME.md 这类自述，写的过程和结果都被收进去。
  - 我纠正 Agent 对我的误解，纠正被留下。
- 问题：Orisumi 会主动向人提问、请人讲述吗？还是只收人主动说的？主动提问像是 Agent 的事，和「只被读」怎么划界？

## 多视图（第二轮，助手的推论和候选）

- 推论：视图主要是给人的。Agent 能读原始数据，但一个人十几年的原始数据，每次回答都全读一遍代价太大，所以 Agent 也需要办法找到相关的部分。
- 问题：帮 Agent 找到相关部分（索引、摘要）是 Orisumi 的事，还是 Agent 自己的事？这和「Orisumi 是否自己调用模型」是同一个问题。
- 候选方向：人看的视图也可以由 Agent 现场读数据生成，Orisumi 不预先做好每种图表。

## 待用户确认的归类与合并

助手做的，用户还没逐条确认：

- 「数据流失」归为假设：它是对现实的判断，20 年里可能变，例如数据可携带的法规让平台都能导出。
- 「模型变强」和「今天的记录会被未来读懂」合并成一条假设。
- 「留下最原始的一层」和「一件事可以有多层」合并成推论「原始层」。
- 「用户是任何人」归为公理。
- 数据的范围和流失的四类并进了「收集一切」：只有它依赖这两条。
- 「怎么删除比怎么添加更重要」不在依赖图里，「数据长寿」只靠「观测为本」就能推出。它写进了 AGENTS.md 的环境一节，作为写代码的原则。

## 待定的问题

- Orisumi 是只存加固定的统计，还是自己也调用模型整理数据？决定「只被读」的边界。
- 「原始层」里「信息量一样」由谁判断？还是先定为原件默认一直保留？
