# 模型处理、追溯和无头：用户的回答

2026-11-03 讨论 poteto 的实践时，助手给了四条候选故事，用户逐条回答。用户确认的部分还没整理进文档站的依赖图，级别、名字和依据待定。

## 用户确认

- 换模型重建。换了更好的模型以后，用同一批证据重新生成理解，并看到新旧两版哪里不一样。
- 追溯来源。觉得某条理解不对时，能知道它来自哪些证据、哪次模型调用。用户的原话要点：知道证据和哪次模型调用就好，不一定原样重现；模型推理带随机性，能看到当时的 trace 就行。
- 无头优先。Orisumi 的每项能力都能不开界面、由 Agent 直接调用；界面只是其中一种查看方式。

## 待定

- 固定证据上的评测。用户：指标很难建立，都需要人判断，而人的注意力有限。等采集搭起来之后，用户自己选一天或几天的记录当评测材料。
- 推论（助手）：「追溯来源」要求每次模型调用的输入、输出和 trace 都留下，并能从理解指回去。它替代了「原样重放」，确定性不再是需求。
- 问题：评测要人判断，那人判断的成本怎么压低？例如只看新旧两版的差异，而不是从头读。
