---
title: 派生与规则
description: 怎么从观测库读出时间段、按设备合并，以及读时生效的规则。
---

观测库只记初值和变化，见[采集开发](../capture/index.mdx#原则)。查询把它们读成时间段，按设备合在一起，再用人或 Agent 写的规则整理。派生结果随时能从观测库和规则原样重建。

## 只读，不改观测库

查询只读打开每个库，包括其他设备的副本。整理规则只在读的时候生效，不写回观测库：

- 观测丢了补不回来，规则写错却随时可能，改库就撤不回。
- 副本是只读的，改了本机的库，其他设备的副本还是原样。
- 今天的噪音可能是明天的信号。比如终端标题里 Claude Code 的 ◐◑ 是“正在跑”，✳ 是“空闲”。

需要缓存时，缓存放进 `derived/`（见[存储](../overview/storage.mdx#目录)），规则一改就整个重建。现在还没有缓存，每次直接读各库。

## 时间段

一个值从它那一行开始成立，到下面最早的一个为止：

1. 同一次运行里同一事物的下一次变化；
2. 运行结束：`stopped_at_utc_ms`，没有就用 `confirmed_until_utc_ms`（崩溃或还在跑的运行只确认到那里）；
3. 依赖通道的事实，到同一次运行里该通道 `available = 0`，恢复后等新的初值。

再截到查询范围。不在任何运行里的时间是未观测，不沿用上一个值。所有派生都只用这一处实现（`Host/Cli/Day/DayTimeline.cs`）。

## 设备

每个库按建库主机归到设备：设备键是 `<platform>:<hardware_uuid>`；没有 `database_identity` 或硬件 UUID 为空时用 `db:<库 ID>`，让它自成一台。设备名取最近一次主机观测的主机名。规则见[多设备](../overview/devices.mdx#读出设备)，`rules/devices.json` 合并尚未实现。

旧库和副本可能缺表或缺列：缺的部分算未观测，列在输出里，不当成空。

## 规则

规则文件放在存储的 `rules/` 下，和观测库一起备份和同步。每次查询都重新读，改完下次就生效；文件格式不对时命令失败，并指出是第几条（从 0 数）。

### 标题

`rules/titles.json`：按文件顺序对每个标题做正则替换（.NET 语法，不区分区域，单次匹配限时 100 ms），先替换再分段，所以替换后相同的相邻段会合并。

```json
{"rules": [
  {"field": "window_title", "bundle_id": "com.apple.Terminal",
   "pattern": "(^|—\\s+)[◐◑◒◓✳\\u2800-\\u28FF]\\s+", "replacement": "$1",
   "why": "Claude Code 的忙闲 spinner"}
]}
```

| 字段 | 含义 |
| --- | --- |
| `field` | `window_title`（macOS 窗口标题）或 `tab_title`（Chrome 标签标题） |
| `bundle_id` | 可选，只对这个应用的窗口标题生效 |
| `pattern` / `replacement` | 正则和替换，`$1` 引用分组 |
| `why` | 为什么要这条，给以后改规则的人或 Agent 看 |

代码里不带默认规则。没有文件就是不整理。
