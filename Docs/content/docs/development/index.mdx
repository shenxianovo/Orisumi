## 安装

只支持 macOS。需要 .NET 11 SDK、Xcode（只装 Command Line Tools 编不了 GUI：SwiftUI 的 `@State` 等是宏，插件只随 Xcode 提供）、Node.js（版本下限见文档站 `package.json` 的 `engines.node`），`PATH` 里要有 `~/.dotnet/tools` 和 `~/.local/bin`。首次在仓库根目录运行：

```sh
dotnet run --project Tools/Dev -- dev setup
```

`dev setup` 先检查上述前置条件，缺了就报错，不代为安装；然后构建解决方案，安装文档站和扩展的依赖，最后安装全局工具 `orisumi-dev`。之后用 `orisumi-dev dev setup` 重跑。再运行 `orisumi-dev deploy` 装上开发实例，并按[签名与权限](./release.mdx#签名与权限)和[Chrome 扩展](./release.mdx#chrome-扩展)授权、加载扩展，各一次。

## 两个入口

- `orisumi`：生产实例里装好的宿主，见[实例、发布与更新](./release.mdx)。
- `orisumi-dev`：开发入口。从当前目录向上找 `Orisumi.slnx`，遇到别的 Git 仓库就停。每次先增量构建这个检出的 `Tools/Dev`（Debug，含未提交的修改），构建失败就退出；再运行构建出的 `orisumi-dev`，所以改了开发命令不用重装，只有改了入口机制或项目路径才要重跑 `dev setup`。开发命令以外的命令转给开发实例里装好的宿主；还没部署过就报错。构建输出写到 stderr；stdin/stdout、参数、退出码和工作目录原样保留。

要跑源码而不部署，用 `dotnet run --project Host/Cli -- --store <存储> …`。宿主通过 `describe` 识别采集器：装好的宿主到实例的 `app/collectors/` 里找；源码构建的宿主取自己相对 `Host/Cli` 的输出目录（如 `bin/Debug/net11.0/`），到 `Collectors/` 下每个目录的同一相对目录找 `orisumi-*.dll`。

## 命令

宿主在 `Host/`（CLI `Host/Cli`、GUI `Host/App.MacOS`），采集器在 `Collectors/<来源>`，共享代码在 `Shared/`（`Platform`：实例、存储、主机和进程；`Capture`：采集器的写入和命令），开发命令在 `Tools/Dev`，测试在 `Tests/`，文档站在 `Docs/`。完整选项见 `--help`。不给 `--store` 时用程序所在的实例，见[实例](./release.mdx#实例)。

宿主命令，`orisumi` 作用于生产，`orisumi-dev` 作用于开发实例：

| 命令 | 用途 |
| --- | --- |
| `capture start` / `capture stop` | 启动或停止本实例的采集器，保留数据，见[安装与启停](./release.mdx#安装与启停) |
| `capture status [--json]` | 各采集器的版本、LaunchAgent 状态（pid 或上次退出码）、最近一次运行和最近一小时的读取失败；只读 |
| `capture coverage --from … --to …` | 查询各来源的[观测依据与缺口](../capture/recovery.mdx) |
| `day [--date …] [--time-zone …]` | 按设备读出一天，见[一天](../query/day.mdx)；只读 |
| `export <目标目录>` | 导出所有观测库的快照，见[导出](../overview/storage.mdx#导出) |
| `install <发布目录>` | 把发布装进本实例，只替换变了的组件，见[安装与启停](./release.mdx#安装与启停) |
| `update [版本] [--from <目录>]` | 只用于生产：更新到正式发布，见[更新](./release.mdx#更新) |
| `<来源> …` | 转给采集器 `orisumi-<来源>`，参数、标准输入输出、退出码和 SIGTERM 原样传递 |

经宿主转发的采集器命令：

| 命令 | 用途 |
| --- | --- |
| `claude capture` / `codex capture` | 常驻监听并增量导入；由 `capture start` 装成 LaunchAgent，没有一次性导入 |
| `macos foreground [秒数] --windows --input --microphone --audio-output --camera` | 采集 macOS，每个选项开一个通道；不给秒数就一直运行，Ctrl+C 正常停止 |
| `macos timeline --from … --to …` | 活动时间线；时间要带 UTC 偏移或 `Z` |
| `browser capture` | 常驻接收扩展的 WebSocket 连接；由 `capture start` 装成 LaunchAgent |
| `<来源> describe` | 版本和常驻采集的参数 |
| `<来源> schema` | 新建观测库的表与列，`release` 用它比较结构 |

开发命令：

| 命令 | 用途 |
| --- | --- |
| `dev setup` / `dev build [-c Release]` | 安装开发入口／构建解决方案 |
| `dev docs …` | 文档站，见[文档维护](./contributing.mdx) |
| `dev loc [--json]` | [行数统计](#行数统计) |
| `deploy [组件…]` | 构建工作树，装进开发实例，见[开发部署](./release.mdx#开发部署) |
| `reset` | 停掉开发采集，删掉开发数据 |
| `release [版本]` | 发布已在开发实例验证的版本，见[发布](./release.mdx#发布) |
| `check` | 运行全部验证 |

## 验证

```sh
orisumi-dev check
```

在检出里运行全部验证，每项打印通过与否和耗时，失败时打印输出，有失败就以 1 退出；清单只在 `Tools/Dev/CheckCommand.cs` 里维护。测试只用临时数据、替身 `launchctl` 和进程，结束后清理，不碰真实的实例和 LaunchAgent。

| 检查 | 覆盖 |
| --- | --- |
| Platform | 主机标识、选库、主机绑定、并发建库 |
| CaptureStartup | LaunchAgent 配置；`launch` 的参数、标准输入输出、进程组、信号转发和退出码 |
| CaptureStatus | 合并已装采集器、LaunchAgent 和来源目录；运行中、未加载、已退出和已停止的运行；不写存储 |
| Schema | 项目与解决方案一致、`describe`、`schema`、结构打包、视图、coverage 列、重复打开、旧库按只增补齐与各种不兼容的拒绝 |
| CaptureIntegration、Claude/CodexIncremental | 独立变化、修订、重试、身份、中断、回放和增量 |
| `swift test`（App.MacOS） | GUI 解码状态和覆盖 JSON、健康与严重程度、时间线上运行和通道的分段、从 app 位置找 CLI 和实例 |
| BrowserIntegration、扩展测试 | 扩展的转发、入队、重连、隐身过滤、版本握手与只重载一次；接收端的 Origin 校验、并发配置、心跳、快照核对、关闭、超时、历史事务 |
| Day | 时间段的运行结束和通道中断、夏令时、今天截到现在、presence 优先级、attention 与标题规则、Chrome 标签、设备分组、缺表、子会话折叠 |
| CaptureCoverage、Export | 覆盖查询的区间；导出时未检查点的 WAL、重复导出、目标位置、库 ID 不符、半成品 |
| MacOSObservation | 用替身来源让每个通道走一遍开始、核对、中断、恢复；Swift 的 JSONL、入库、积压、回滚、两侧进程退出 |
| Instance | 实例解析、bundle ID 与端口、扩展 ID、组件标识、按清单安装与选择性重启、回滚、签名与证书核对、部署、转发、`reset`、`release` 的各项拒绝与结构比较、`update` 与备份 |
| SourceLauncher、Loc | 在临时仓库里测开发入口的构建、参数、退出码、二进制输入输出、信号，以及行数统计 |

新增采集器的要求见[采集开发](../capture/index.mdx)。

## 行数统计

`orisumi-dev dev loc [--json]` 统计当前工作区，包括未提交的修改和未被忽略的新文件；不计空行、纯注释和符号链接。文档、配置和生成文件（含锁文件）单列为 `Outside code`，不算进代码总数。项目按 `.csproj`、`package.json` 识别，文件归最近的项目；只测一个项目的独立测试归那个项目，其余归 `Cross-module`。归不了类的文件列在 `Unclassified files`，也不算进总数。
