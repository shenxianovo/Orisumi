title: 存储
description: 存储目录的位置与结构，以及每个来源写哪个库。
---

每个存储目录是一个实例。生产目录名为 `Orisumi`，开发目录名为 `Orisumi-dev`；macOS 放在 `~/Library/Application Support/` 下，Windows 放在 `%LOCALAPPDATA%` 下。`--store` 可指定其他目录，测试用临时目录。Android 计划使用应用私有目录。各平台的运行状态见[平台](../development/release.mdx#平台)。

正在写的库不放进 iCloud Drive、Dropbox 等同步盘：同步工具复制或覆盖写入中的 SQLite（尤其是 WAL）会损坏它。也不放 `~/Documents`、`~/Desktop`：这些目录受 macOS 隐私保护，后台 LaunchAgent 访问会被拦。

## 目录

| 路径 | 内容 | 丢失后 | 同步 |
| --- | --- | --- | --- |
| `observations/<来源>/<database_id>.sqlite` | 观测库：本机正在写的、以前写的、其他设备的副本 | 补不回来 | 要 |
| `rules/` | 人或 Agent 写的规则，如[标题规则](../query/index.mdx#规则)；设备合并未实现 | 补不回来 | 要 |
| `derived/` | 确定性派生的缓存，能从上两项原样重建（未实现，[查询](../query/index.mdx)现在直接读各库） | 重建 | 不 |
| `instance.json` | 实例名，见[实例](../development/release.mdx#实例) | 程序找不到所属实例 | 不 |
| `app/` | 装好的宿主和采集器，`manifest.json` 记各组件的标识和版本 | 重新安装 | 不 |
| `backups/` | 生产 `update` 前的库快照，保留最近两份，见[更新](../development/release.mdx#更新) | 无影响 | 不 |
| `state/` | 本机运行状态：`current/<来源>.json`、`locks/` | 下次采集从新库开始 | 不 |
| `logs/` | 采集器日志 | 无影响 | 不 |

备份和同步只管 `observations/` 和 `rules/`。重跑结果会变或要付费的派生（如模型读出）不算可重建，出现时另定需要备份的位置。

## 导出

`orisumi export <目标目录>` 把每个来源的所有库拍成快照，按同样的布局写到 `<目标目录>/observations/<来源>/<库 ID>.sqlite`，不含 `state/`、`logs/` 和 `backups/`。

- 快照用 `VACUUM INTO`：采集器照常写入，快照取同一时刻的已提交内容，包括还在 WAL 里的部分。每份是单个文件（DELETE 日志模式），通过完整性检查和库 ID 核对后才替换目标。
- 存储里的库只读打开，内容不变；但打开一个没人在写的 WAL 库时，SQLite 仍可能建出 `-wal`、`-shm`。目标不能落在存储目录里。
- 再次导出时，新快照替换同一库 ID 的旧快照；目标里同名文件的库 ID 对不上就不覆盖。
- 输出 JSON，逐库给出 `exported`、`skipped`（没有 `database_identity`，如建库中途留下的空文件）或 `failed`；有失败时退出码为 1。

导出的库放进另一个存储的 `observations/<来源>/`，就是那里的只读副本，见[多设备](./devices.mdx#合并)。

## 每个来源写哪个库

- 文件名就是库 ID（`database_identity.database_id`），建库时生成，之后不变。
- 一个库只有一个写入方：创建它的主机上的采集器。其他设备只保存只读副本，所以同步只是复制文件。
- `state/current/<来源>.json` 记库 ID、建库平台、硬件 UUID 和 Windows 的 `MachineGuid`。旧指针缺少平台时按 macOS 读取。指针或文件缺失、平台不同、主机标识不匹配时，写入方新建库并更新指针，旧库留作只读副本。
- 同平台时，优先用本机有效的硬件 UUID 匹配建库记录。Windows 的 SMBIOS UUID 缺失、全 0 或全 F 时，改用本机 `MachineGuid` 匹配。若本机没有可用标识，就沿用当前库。
- 新库在锁内建成空文件，同一来源的并发写入方（如多个 Chrome 配置各自的连接）使用同一个库。
- 只读命令不建库。`capture coverage` 和 `export` 读每个来源的所有库，来源按 `observations/` 下的目录认，本机没装对应采集器的（如从其他设备拷来的库）也读；`capture status` 只读本机建的库；`macos timeline` 只读本机当前的 macOS 库。
- 判断库是否属于本机时，用同一规则匹配 `database_identity`。正在创建、尚无身份记录的库也算本机库。

改结构的规则见[数据库结构](../capture/index.mdx#数据库结构)。
