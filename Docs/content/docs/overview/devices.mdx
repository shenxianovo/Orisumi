Orisumi 要在 macOS、Windows、Android 等多台设备上采集，再合到一起读。这页记多设备的约定和尚未实现的部分；已实现的规则写在[采集开发](../capture/index.mdx)和各来源页面，这里只引用。

## 身份

一个库只有一个写入方，所以“哪台主机写的”在建库时就确定，写进库里；“这台主机算哪台设备、叫什么”是读的时候查的规则。重装、迁移、换主板时，算不算同一台会变，所以库里只存原始标识，不存判断。

| 概念 | 怎么来 | 状态 |
| --- | --- | --- |
| 库实例 | `database_identity.database_id`，建库时生成，即库文件名 | 已实现，见[存储](./storage.mdx) |
| 建库主机 | `database_identity` 的 `platform` 和原始硬件标识，建库时随库写入，副本拷到哪里都带着 | macOS 已实现 |
| 主机观测 | `host_observations`，每次运行开始时读主机名、系统版本、系统用户等会变的值 | macOS 已实现 |
| 设备 | 主机键加 `rules/devices.json` 里的合并和命名 | 未实现，做法见下 |
| 来源实例 | 浏览器扩展安装（`profile_id`）、`CODEX_HOME`、`CLAUDE_CONFIG_DIR` 等 | 已由各来源记录；浏览器是哪个 Chrome 配置在派生层判断 |

- 迁移助理把用户目录拷到新 Mac：硬件 UUID 不同，新 Mac 建自己的库，读出两台设备。设备 ID 若存成本地文件，会被一起拷走，新机器冒充旧机器。
- 一台机器上两个存储目录：两个库实例，硬件 UUID 相同，读出同一台设备。
- 重装系统：硬件 UUID 不变，仍是同一台；换主板后加一条人工合并。

各平台标识的稳定程度不同：macOS 的 `IOPlatformUUID` 重装不变；Windows 的 `MachineGuid` 重装会变，SMBIOS UUID 不变，但有些主板出厂写的是多台共用的占位值；Android 应用拿不到硬件标识，`ANDROID_ID` 随签名密钥和恢复出厂设置变化。所以按平台记原始值，不假定有通用的稳定 ID；新平台在 `HostIdentity`、`database_identity.platform` 和 `host_observations.platform` 加值，并补上自己的标识列（Windows 两个都记）。

### 读出设备

主机键已由[查询](../query/index.mdx#设备)读出；`rules/devices.json` 未实现。

- 主机键由建库主机算出，规则只在读的地方维护：macOS `macos:<IOPlatformUUID>`，Windows `windows:<SMBIOS UUID>`（占位值改用 `MachineGuid`），Android `android:<ANDROID_ID>`；读不到硬件标识时用 `db:<database_id>`，让该库自成一台，等人工归类。不按主机名猜。
- `rules/devices.json` 把多个主机键归到一台设备并命名。未归类的主机键各自是一台；设备 ID 用规则里的 ID，否则用主机键；显示名用规则里的名字，否则用最近的主机名。
- 系统用户不算进设备：同一台 Mac 上的两个账号是同一台设备、不同用户。
- 机器转手需要给规则加生效区间，暂不做。

## 合并

未实现。

- 其他设备的库作为只读副本放进同一个 `observations/<来源>/`，见[存储](./storage.mdx)。本地 ID 只在库内有效，跨库用库实例加本地 ID。
- 只读保留的旧库同样参与汇总，按它自己的结构读。
- 观测设备不等于事情发生的设备。浏览器同步会带来其他设备的访问和书签，访问用 `visits.is_local` 区分。同一对象被多台设备观测到时，在派生层按来源自己的身份去重，例如书签 GUID。

## 时间

- 每台设备用自己的时钟记 UTC 毫秒，含义见[时间分两种](../capture/index.mdx#时间分两种)。采集时不做跨设备校正。
- 时区不逐行记。每台设备记时区的初值和变化，其他来源按同一设备、同一时刻对照。
- 启动 ID 随主机观测每次运行记一次，不逐行记。
- 每台设备记时钟事件：墙钟和单调时钟一起读的初值，以及时钟被调整后的变化。macOS 见 [macOS](../capture/sources/macos.mdx#屏幕会话和时间)；Windows 用 `WM_TIMECHANGE`，Android 用 `ACTION_TIME_CHANGED`。
- 时钟偏差作为观测另记，未实现。校正只在派生层做：`corrected_at` 为原始时间加该设备当时的偏差，偏差未知时按 0；原始时间不改。

## 查询与可视化

第一个读出见[一天](../query/day.mdx)：每次直接只读打开各库，在内存里按设备派生，不用 ATTACH（SQLite 默认最多挂 10 个）。还没做的：

- 汇总库：查询变慢或要反复查时，把派生结果放进 `derived/` 里一个可随时重建的库，补上 `corrected_at` 和当时所在时区。
- 查询和图表统一用 `corrected_at`；显示本地时间时，用人当时所在的时区，由设备的时区事件读出。
